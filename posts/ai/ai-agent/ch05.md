# LangGraph 入门：用状态图搭建 Agent

一个最小 Agent 其实就是一个 while 循环：模型输出 `tool_calls` → 执行工具 → 结果塞回消息 → 再调模型，直到模型直接回答为止。手写这个循环不难，难的是接下来想要的东西——多轮记忆、中断后恢复、人在回路审批、分支路由。LangGraph 的思路是：**把 Agent 建模成一张状态图**，循环、分支、持久化都由图引擎接管。

---

## 一、三要素：State、Node、Edge

| 要素 | 是什么 | 类比 |
|------|--------|------|
| **State** | 一个 `TypedDict`，图流转过程中共享的数据 | 全局变量，但受控 |
| **Node** | 普通函数：读 State，返回要更新的字段 | 循环体里的一步 |
| **Edge** | 节点间的跳转规则（固定边 / 条件边） | 循环和分支逻辑 |

每个节点返回一个**部分状态**（只含要更新的键），图引擎按规则合并进 State，然后沿边走到下一个节点。

---

## 二、最小示例：一个节点的聊天图

```python
from typing import Annotated
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages
from langchain_core.messages import HumanMessage

class State(TypedDict):
    messages: Annotated[list, add_messages]  # 追加而非覆盖，见下节

def chatbot(state: State):
    return {"messages": [model.invoke(state["messages"])]}

builder = StateGraph(State)
builder.add_node("chatbot", chatbot)
builder.add_edge(START, "chatbot")   # 入口
builder.add_edge("chatbot", END)     # 出口
graph = builder.compile()

result = graph.invoke({"messages": [HumanMessage("hi")]})
print(result["messages"][-1].content)
```

`StateGraph(State)` 建图 → `add_node` / `add_edge` 连线 → `compile()` 成可执行的 `Runnable`。`START` 和 `END` 是两个虚拟端点，定义图的入口和终止。

---

## 三、`add_messages`：状态更新是合并，不是覆盖

节点返回 `{"messages": [新消息]}` 时，如果不加特殊声明，默认行为是**整个键被覆盖**——消息历史就丢了。`Annotated[list, add_messages]` 给这个键挂了一个 **reducer**：新旧值不是替换，而是按 reducer 规则合并（追加，并按消息 id 去重）。

这是 LangGraph 最容易踩的第一个坑：

```python
class State(TypedDict):
    messages: list  # ❌ 没有 reducer，每轮覆盖，历史丢失

class State(TypedDict):
    messages: Annotated[list, add_messages]  # ✅ 追加合并
```

自定义键也可以写自己的 reducer 函数，语义是 `old, new -> merged`。

---

## 四、条件边：让图自己决定往哪走

Agent 的分支逻辑（"模型要调工具就去工具节点，否则结束"）用 `add_conditional_edges` 表达——一个路由函数读 State 返回分支名：

```python
def classify(state):
    return {"label": "zh" if 含中文(state["text"]) else "en"}

def route(state):
    return "zh" if state["label"] == "zh" else "en"

builder.add_edge(START, "classify")
builder.add_conditional_edges("classify", route, {"zh": "zh_node", "en": "en_node"})
```

条件边就是那个 while 循环里 `if resp.tool_calls:` 的图版本——判断逻辑从循环体里抽出来，变成了图上可见的一条边。

---

## 五、Checkpointer：多轮记忆和中断恢复

裸写循环时，"记住上一轮对话"要自己维护消息列表；LangGraph 把状态持久化抽象成 checkpointer。编译时挂上，每次 `invoke` 按 `thread_id` 续接：

```python
from langgraph.checkpoint.memory import MemorySaver

graph = builder.compile(checkpointer=MemorySaver())
cfg = {"configurable": {"thread_id": "demo-1"}}

graph.invoke({"messages": [HumanMessage("第一条")]}, cfg)
result = graph.invoke({"messages": [HumanMessage("第二条")]}, cfg)
# result["messages"] 有 4 条：第一轮问答 + 第二轮问答
```

同一个 `thread_id` 就是同一段对话。`MemorySaver` 存内存，生产环境换 `SqliteSaver` / `PostgresSaver` 即可，代码不动。有了持久化状态，**中断恢复**（`interrupt()` 暂停图、人工审批后继续）和**时间旅行**（从任意历史检查点重放）才成为可能——这是手写循环最难补的两块。

## 六、和手写 while 循环的对比

| | 手写 ReAct 循环 | LangGraph |
|--|----------------|-----------|
| 工具调用循环 | 自己写 while + if | 边和节点 |
| 分支逻辑 | 埋在循环体里 | 条件边，图上可见 |
| 多轮记忆 | 自己维护消息列表 | checkpointer + thread_id |
| 中断 / 人在回路 | 自己设计持久化 | `interrupt()` + checkpointer |
| 状态 schema | 散落在变量里 | TypedDict 集中声明 |
| 可视化 / 调试 | print | `graph.get_graph().draw_mermaid()` |

什么时候手写循环就够：单轮工具调用、无状态、逻辑直白。什么时候该上图：多节点协作、要审批中断、要会话持久化。

> 本文示例均用 `GenericFakeChatModel` 在本地无 key 环境跑通验证（langgraph 1.2 + langchain-core 1.5），换成 `ChatOpenAI` 即可接真实模型。
