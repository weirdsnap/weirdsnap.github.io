这个文件用到的全是 vscode 扩展 API(import * as vscode from 'vscode')，共涉及三个模块，分别对应三种不同的能力：

1. 配置读取：vscode.workspace.getConfiguration(src/core/config.ts:24)
const cfg = vscode.workspace.getConfiguration('vsAgent');
cfg.get<string>('baseUrl', 'https://api.openai.com/v1');
能力：读取 VS Code 的设置系统（settings.json)。
getConfiguration('vsAgent') 拿到 vsAgent 这个 section 的配置对象，对应 settings.json 里的 vsAgent.baseUrl、vsAgent.model 这些键。
它会自动合并多层级配置：默认设置 < 用户设置 < 工作区设置，最终生效的是优先级最高的那层。
cfg.get(key, defaultValue) 的第二个参数是回退默认值，用户没配就用它。
前提：package.json 的 contributes.configuration 里要声明这些配置项，用户才能在设置界面看到和编辑它们。
2. 加密存储：context.secrets(SecretStorage API)(src/core/config.ts:33, 51)
await context.secrets.get(API_KEY_SECRET);
await context.secrets.store(API_KEY_SECRET, key.trim());
能力：存取敏感信息secrets是vscode.ExtensionContext上的属性，提供get / store / delete / onDidChange` 四个方法。
底层不是普通文件存储，而是调用操作系统的安全凭据服务（macOS 是 Keychain,Windows 是 Credential Manager,Linux 是 libsecret),key 是加密保存的。
这就是为什么文件里注释说"优先存 SecretStorage"——相比明文 settings.json，它不会被同步到 GitHub，也不会被 code --list-extensions 之类的方式带出。
3. 交互输入：vscode.window.showInputBox(src/core/config.ts:45)
await vscode.window.showInputBox({
  password: true,
  ignoreFocusOut: true,
  // ...
});
能力：在窗口顶部弹出输入框，属于 UI 交互 API(window 命名空间下还有 showInformationMessage、showQuickPick、createWebviewPanel 等）。
password: true — 输入框显示为密码样式。
ignoreFocusOut: true — 焦点离开时输入框不自动关闭。
返回值是 string | undefined:undefined 表示用户按 Esc 取消了，所以代码里用 if (key) 判断后才写存储。
顺带：vscode.ExtensionContext 参数本身
getApiKey 和 promptForApiKey 都接收 context: vscode.ExtensionContext。它是扩展激活时 VS Code 传进来的上下文对象，是整个扩展的"资源入口"——除了 secrets，还提供 subscriptions（注册可释放资源）、globalState（持久化键值）、extensionUri（扩展安装路径）等。这些 API 都要通过它才能用，所以只能由激活函数（activate）往下传。

简单总结：设置（getConfiguration）读配置、SecretStorage 存密码、InputBox 收输入 —— 这三者正好是 VS Code 扩展处理"凭据型配置"的标准三件套。
