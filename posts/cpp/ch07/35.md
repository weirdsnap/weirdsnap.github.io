# `std::popcount`：数一个整数里有几个 1（C++20 `<bit>`）

`std::popcount(x)` 返回无符号整数 `x` 的二进制表示中 **1 的个数**。在 `<bit>` 头文件，C++20 起可用，**只接受无符号整数类型**，返回值是 `int`。

**场景示例：**

```cpp
#include <bit>

unsigned x = 0b10110110;        // 182
std::popcount(x);               // 5

// 刷题高频：状态压缩 / 子集枚举
int mask = 0b1101;
if (std::popcount(static_cast<unsigned>(mask)) == 2) { /* 选了两个元素 */ }

// 判 2 的幂的现代表法
std::has_single_bit(x);         // false，等价于 popcount(x) == 1
```

**原理解析 + 常见误区**

- ❌ `std::popcount(-1)` 直接传有符号数 — 编译错误。模板约束要求**无符号整数类型**（`unsigned char/short/int/long/long long`），有符号数要先 `static_cast<unsigned>(x)`。这是它和 `__builtin_popcount(int)` 最实用的区别：类型系统在编译期就拦住了"负数的 popcount 到底怎么算"这类歧义。
- ❌ `popcount(0)` 是 UB — 错误。`popcount(0) == 0`，良定义。同族的 `countl_zero(0)` 这类"数前导零"的函数对 0 也是良定义（返回位宽）；真正对 0 是 UB 的是 `bit_floor` 的反向预期——`bit_floor(0)` 返回 0 也是良定义的。
- ❌ `x & (x - 1)` 循环更快 — 实测（clang/g++ `-O2`）分三种情况：① x86-64 默认 baseline ABI 不含 POPCNT，`__builtin_popcount` 编成 ~12 条指令的 SWAR 位运算（仍是 O(1) 常数时间），而 Kernighan 循环保持真循环、耗时和 1 的个数成正比——`popcount` 赢。② 开 `-mpopcnt`（或 `-march=native` 且 CPU 支持）后，两者都被识别并编成单条 `popcntl`——打平。③ ARM64（armv8.4）上两者都编成相同的 `CNT/ADDV` 序列——打平。结论：手写循环在任何平台上都不会更快，只有"碰巧一样快"，但可读性和可移植性都输了，别写。
- ✅ 返回值是 `int` 不是 `unsigned`，和循环变量比较时不会触发符号转换警告。

**选型建议**：

| 场景 | 写法 |
|------|------|
| C++20+，标准可移植 | `std::popcount(static_cast<unsigned>(x))` |
| C++17 及以前 / GCC、Clang | `__builtin_popcount(x)`（int）、`__builtin_popcountll(x)`（long long） |
| `std::bitset<N>` | `bs.count()` |
| 判 2 的幂 | `std::has_single_bit(x)`（语义比 `popcount(x)==1` 更直白） |

**延伸点**：`<bit>` 全家桶还有 `countl_zero / countr_zero`（高/低位连续 0 个数，二分定位常用）、`bit_width`（最高位位置 +1）、`bit_floor / bit_ceil`（向下/向上取 2 的幂，`bit_ceil` 对应 3513（[ch56](./blog.html?post=leetcode/bit/ch56.md)）里手写的 `while (m <= n) m <<= 1`）、`rotl / rotr`（循环移位），C++23 再加 `std::byteswap`。全部只接受无符号类型，规则一致。
