# `map` 的 `operator[]`：查询背后的默认插入

## 问题从哪来

`m[k]` 看起来像一次查询，实际语义是"**有就返回引用，没有就插入一个再返回引用**"。标准里它的定义就一句话（[map.access]）：

> `operator[](k)` 等价于 `return try_emplace(k).first->second;`

key 不存在时 `try_emplace` 用空参数包构造一个 value，也就是**默认构造**（准确说是 value-initialize）。这个插入动作很容易被忽视，直到你统计构造次数或者拿一个不可默认构造的类型当 value。

## 一行代码触发三种函数

```cpp
bool default_constructed = false, constructed = false, assigned = false;

class C {
public:
    C() { default_constructed = true; }
    C(int) { constructed = true; }
    C& operator=(const C&) { assigned = true; return *this; }
};

int main() {
    std::map<int, C> m;
    m[7] = C(1);
    std::cout << default_constructed << constructed << assigned;  // 111
}
```

`m[7] = C(1)` 这一行拆成三步：

1. `m[7]`：key 不存在，**先默认构造**一个 `C` 插进 map，`default_constructed` 置位；
2. `C(1)`：调带参构造造出临时对象，`constructed` 置位；
3. `=`：把临时对象**拷贝赋值**给 map 里那个刚默认构造出来的 `C`，`assigned` 置位。

先默认构造再马上赋值覆盖，这一步是纯粹的浪费。

## 由此而来的两个硬约束

- **mapped_type 必须可默认构造**。不可默认构造的类型当 value，`m[k]` 直接编译失败，哪怕你紧跟一句赋值。
- **`operator[]` 只有非 const 版本**。它可能插入元素，所以 `const map` 上根本没有这个运算符，编译报 discard qualifiers。const 场景的查询用 `at()`（不存在则抛 `out_of_range`）或 C++20 的 `contains()`。

## 想避开"默认构造 + 赋值"的写法

| 需求 | 写法 | 说明 |
|------|------|------|
| 插入/覆盖，一步到位 | `m.insert_or_assign(k, C(1))`（C++17） | 存在则赋值，不存在则构造 |
| 只在不存在时构造 | `m.try_emplace(k, 1)`（C++17） | 直接把 `1` 转发给 `C(int)`，无默认构造、无临时；key 已存在时**什么都不做**，参数也不会被移动 |
| 只想查不想插 | `find` / `at` / `contains` | 不会改动 map |

`try_emplace` 和 `insert_or_assign` 的区别在 key 已存在时：前者完全不动（连参数都不求值移动），后者执行赋值。参数是 move-only 类型时这个区别是硬性的。

**常见误区**

- ❌ `m[k]` 只是查询 — 错误。key 不存在会插入一个默认构造的 value。
- ❌ `m[k] = v` 会先查再决定插不插 — 错误。无论如何先默认构造插入，再走赋值。
- ❌ 不可默认构造只是风格问题 — 错误。是编译期硬约束。
