# `std::function` 的值签名会"吃掉" lambda 的右值引用

`std::function<void(Q)>` 的 `operator()` 签名是 `void operator()(Q) const`——**按值**接收（`[func.wrap.func.general]`）。所以哪怕目标 lambda 的形参写的是 `Q&&`，中间也会被这次按值传递"截胡"：先拷贝一份，再把这份拷贝 `std::forward<Q>` 成右值引用绑给 lambda。lambda 改的是副本，外面的原对象纹丝不动。

**场景示例：**

```cpp
#include <functional>
#include <iostream>

struct Q {
    int v = 0;
    Q() { std::cout << "D"; }
    Q(const Q&) { std::cout << "C"; }
    Q(Q&&) { std::cout << "M"; }
    void change() { ++v; }
    void func() { std::cout << v; }
};

void takeQfunc(std::function<void(Q)> qfunc) {
    Q q;
    q.func();
    qfunc(q);
    q.func();
}

int main() {
    takeQfunc([](Q&& q) { q.change(); });
}
```

输出 `D0C0`：

- `D`：`takeQfunc` 里默认构造 `q`
- `0`：第一次 `q.func()`
- `C`：`qfunc(q)` 把 `q` **按值**拷进 `operator()` 的形参
- （lambda 对副本 `change()`，无输出；注意没有 `M`——`forward<Q>` 只是把已存在的副本转成右值引用直接绑定，不触发移动构造）
- `0`：第二次 `q.func()`，原 `q` 没被改过

**原理解析 + 常见误区**

- ❌ lambda 形参是 `Q&&`，会 move 或直接绑到外面的 `q` — 错误。`ArgTypes...` 被显式定为 `Q`，`operator()` 的形参就是普通 `Q`，调用 `qfunc(q)` 时拷贝已经发生，lambda 看到的从来只是副本。
- ❌ 转发副本时会调移动构造（输出含 `M`）— 错误。`INVOKE(f, std::forward<Q>(args))`（`[func.wrap.func.inv]/1`）里 `forward<Q>` 只是类型转换，把副本以右值引用形式传给 lambda，绑定引用不构造新对象。
- ✅ 陷阱的根源是 `std::function` 的类型擦除：签名写在 `std::function<void(Q)>` 里就定死了，和目标 lambda 实际的形参类型无关。若 `takeQfunc` 改成函数模板（参数类型推导），中间这层按值传递就不存在。

**延伸点**：想让 lambda 真正改到外部对象，签名得带引用——`std::function<void(Q&)>`（`ArgTypes` 可以是引用类型），lambda 侧对应改成 `Q&`。或者干脆不用 `std::function`，模板形参 + 完美转发，连类型擦除的运行时开销一起省掉。`std::function` 与 lambda 的类型机制差异见 [std_function_01](./blog.html?post=cpp/practices/std_function_01.md)。
