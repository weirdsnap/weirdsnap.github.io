# 转换函数的 const 正确性

转换函数若不修改对象状态，应标记为 `const`：否则 `const` 对象无法调用它，转换直接编译失败。

| 调用方 | `operator int()` | `operator int() const` |
|--------|-----------------|----------------------|
| `Foo f; int a = f;` | ✅ | ✅ |
| `const Foo f; int a = f;` | ❌ | ✅ |
| `int a = Foo();`（临时对象） | ✅ | ✅ |

注意第三行：临时对象（prvalue）**可以**调用非 const 成员函数——它有自己的存储，不存在"修改 const 对象"的问题。真正被非 const 版本拒之门外的只有 const 对象：

```cpp
#include <iostream>

struct Foo {
    int x = 42;
    operator int() { return x; }   // 非 const
};

int main() {
    int a = Foo();       // ✅ 合法：临时对象可以调非 const 成员函数
    const Foo f{};
    // int b = f;        // ❌ 编译错误：丢失 const 限定
}
```

如果想连临时对象（以及一切右值）也拒绝，给转换函数加左值引用限定符 `&`：

```cpp
operator int() & { return x; }   // 只有左值能调；Foo() 转换会编译失败
```

**常见误区**

- ❌ 临时对象只能调用 `const` 成员函数 — 错误。临时对象可以调非 const 成员函数；要限制右值调用，得用 ref-qualifier `&` / `&&`。
- ❌ 转换函数默认是 `const` — 错误。和普通成员函数一样，默认非 `const`。
- ✅ 不修改状态的转换函数应始终标记 `const`，否则 `const` 对象上的转换全部不可用。

**延伸点**：ref-qualifier（`&` / `&&`）对转换函数同样有效，可用来区分"从左值读取"和"从右值搬走"两种语义，例如自定义字符串类的 `operator const char*() &` 与 `operator std::string() &&`。
