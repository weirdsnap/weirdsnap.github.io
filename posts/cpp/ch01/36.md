# 值类别：lvalue、prvalue 与 xvalue

## 为什么需要这套概念

移动语义和重载决议都建立在表达式的值类别（value category）上：[右值引用](./blog.html?post=cpp/ch01/21.md)里 `T&&` 能绑什么、[移动语义](./blog.html?post=cpp/ch03/08.md)里 `std::move` 的产物是什么，追问到底都落在值类别上。C++11 把每个（非 void）表达式划归五种类别，日常记忆用三分法就够：lvalue、prvalue、xvalue。

## 两个判断维度

看一个表达式属于哪类，问两个问题：

1. 它有身份（identity）吗？有没有名字、能不能取地址，是不是"某个具体对象"。
2. 它的资源能被搬走吗？

两问的答案组合出三个主类别：

| 类别 | 有身份 | 可搬走 | 例子 |
|------|--------|--------|------|
| lvalue | ✔ | ✘ | 变量名 `i`、`*p`、`++i`、字符串字面量 |
| prvalue | ✘ | ✔ | `42`、`i + 1`、返回非引用的函数调用、`i++` |
| xvalue | ✔ | ✔ | `std::move(i)`、`static_cast<T&&>(i)`、返回 `T&&` 的函数调用 |

- lvalue（locator value）：有确定位置的对象，不能随便掏空它。
- prvalue（pure rvalue）：纯粹的临时值，没有身份，生来就是用于初始化别的东西的。
- xvalue（eXpiring value）：将亡值。有身份，但被标记为"可以搬走"。`std::move` 的产物就是它：既还指着原来那个对象（有身份），又承诺允许被掏空（可搬走）。

五种类别里剩下的两个是组合类别，不是并列的第四、第五种：

- glvalue = lvalue + xvalue（所有"有身份"的）
- rvalue = prvalue + xvalue（所有"可搬走"的）

所以"`T&&` 绑定右值"这句话展开是：`T&&` 能绑 prvalue 和 xvalue，不能绑 lvalue；`const T&` 三种全绑。这就是 [ch03/14](./blog.html?post=cpp/ch03/14.md) 里移动构造不可用时、拷贝构造能接住 `std::move` 产物的原因。

## 最关键的一条：值类别是表达式的属性，不是变量的

变量本身没有值类别，表达式才有。推论很反直觉：

**一个右值引用类型的变量，用它写出来的表达式是 lvalue**，因为它有名字。

```cpp
void f(int&)  { std::cout << "lvalue"; }
void f(int&&) { std::cout << "rvalue"; }

int main() {
    int i = 0;
    f(i);            // lvalue
    f(42);           // rvalue（prvalue）
    f(std::move(i)); // rvalue（xvalue）
}

template <typename T>
void g(T&& x) {
    f(x);  // lvalue：x 有名字，哪怕它的类型是 int&&
}
```

`g(42)` 里 `x` 的类型推导为 `int&&`，但 `f(x)` 调的是 `f(int&)`。想在 `g` 里保住实参原本的类别，就要 `std::forward`，这正是完美转发存在的原因（见 [ch04/08](./blog.html?post=cpp/ch04/08.md)）。

**常见误区**

- ❌ `int&&` 类型的对象就是右值 — 错误。类型和值类别是两回事；变量名表达式永远是 lvalue。
- ❌ 字符串字面量是 prvalue — 错误。`"hello"` 是 lvalue，它有存储位置，这也是它能绑定 `const char(&)[6]` 的原因。
- ❌ `std::move` 做了移动 — 错误。它只是把 lvalue 表达式转成 xvalue，标记"可搬走"；真正的移动发生在移动构造里（见 [ch03/08](./blog.html?post=cpp/ch03/08.md)）。
