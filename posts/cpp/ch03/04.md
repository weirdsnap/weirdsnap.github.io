# unique_ptr vs shared_ptr

`unique_ptr` 独占所有权零开销；`shared_ptr` 共享所有权，有控制块和原子引用计数的开销。

| 维度 | `unique_ptr` | `shared_ptr` |
|------|-------------|-------------|
| 所有权 | 独占，仅可移动 | 共享，可复制 |
| 自身大小 | 通常等于裸指针（64 位下 8 字节） | 固定两个指针（64 位下 16 字节） |
| 引用计数 | 无 | 控制块里，原子操作 |
| 删除器 | 类型的一部分，编译期确定 | 存在控制块里，运行时类型擦除 |
| 数组支持 | `unique_ptr<T[]>` | `shared_ptr<T[]>`（C++17 起） |
| 转换 | 可以隐式转成 `shared_ptr` | 不能转回 `unique_ptr` |

## 零开销到底是什么意思

说 `unique_ptr` 零开销，指三件事：

- **体积零开销**：默认删除器下 `sizeof(unique_ptr<T>) == sizeof(T*)`，对象里就存一个裸指针，没有控制块、没有计数器。
- **运行零开销**：解引用、`get()`、移动，编译出的机器码和手写裸指针完全一样。没有原子增减，没有间接跳转。
- **不为你不用的东西付钱**：这是 C++ 的零开销抽象原则。不需要共享所有权时，`unique_ptr` 不会暗地里给你多付一分钱成本。

对照看 `shared_ptr` 付了什么：对象本身 16 字节（对象指针 + 控制块指针），每次拷贝构造是一次原子自增，析构是一次原子自减加一次分支判断，最后还有一个控制块的堆分配（`make_shared` 时与对象合并成一次）。单个看都不贵，但热点路径上反复拷贝 `shared_ptr` 是真实可测的开销，所以传参时能用引用就不用值拷贝。

## 自定义删除器

两者都支持，但机制不同，这个差异直接影响类型和体积。

`unique_ptr` 的删除器是第二个模板参数，是类型的一部分：

```cpp
struct FILEDeleter {
    void operator()(std::FILE* p) const { if (p) std::fclose(p); }
};
std::unique_ptr<std::FILE, FILEDeleter> f(std::fopen("a.txt", "r"));
```

`shared_ptr` 的删除器是构造函数参数，类型被擦除掉，不影响 `shared_ptr<T>` 的类型：

```cpp
std::shared_ptr<std::FILE> f(std::fopen("a.txt", "r"), [](std::FILE* p){ std::fclose(p); });
// 类型还是 shared_ptr<FILE>，删除器存在控制块里
```

由此产生两个实际后果：

- **类型兼容性**：`unique_ptr<FILE, FILEDeleter>` 和 `unique_ptr<FILE, OtherDeleter>` 是两个不相关的类型，函数参数要写实对应类型。`shared_ptr` 没这个问题，装什么删除器都是 `shared_ptr<T>`。
- **体积**：`unique_ptr` 的删除器存在对象里。无状态删除器（空结构体、无捕获 lambda）靠空基类优化不占空间，`sizeof` 仍是 8；有状态删除器（带成员的仿函数、函数指针）会让 `unique_ptr` 变胖，比如函数指针删除器直接变成 16 字节。

注意 `make_unique` 和 `make_shared` 都不接受自定义删除器，分配和销毁由它们自己安排。需要自定义删除器时只能直接构造：`unique_ptr<T, D>(ptr, d)` 或 `shared_ptr<T>(ptr, d)`。

常见用途：包 C 接口资源（`FILE*`、`malloc` 的内存、文件描述符、socket、COM 指针），让 RAII 接管非 `new` 分配的资源。

## 怎么选

- 默认 `unique_ptr`：独占是大多数场景，开销最小，而且随时能转成 `shared_ptr`，反过来不行。
- 确实需要共享所有权（多处持有、谁先结束无法预判）才用 `shared_ptr`。
- 工厂函数返回 `unique_ptr`，把"要不要共享"的决定留给调用方。
- 要包 C 风格资源时，删除器选无捕获 lambda 或空仿函数，保持 `unique_ptr` 瘦身为 8 字节。

## 常见误区

- ❌ `shared_ptr` 总是用 `make_shared` 更好：错误。`make_shared` 一次性分配，但存在 `weak_ptr` 时对象内存被钉住，详见 shared_ptr 一篇。
- ❌ `unique_ptr` 完全无开销：有状态删除器会让它大于裸指针；另外 `unique_ptr` 本身不初始化时也需要手动置空习惯，零开销不等于零心智负担。
- ❌ 传参到处拷贝 `shared_ptr`：只是借用就传 `const shared_ptr<T>&` 或裸指针/引用，原子计数不是免费的。
