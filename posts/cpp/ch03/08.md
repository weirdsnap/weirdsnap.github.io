# 移动语义

通过右值引用和移动构造函数将资源所有权从临时对象转移至新对象，避免深拷贝开销。

| 维度 | 拷贝语义 | 移动语义 |
|------|----------|----------|
| 参数类型 | `const T&` | `T&&` |
| 资源行为 | 分配新资源，复制内容 | 掠夺源对象资源，置空源指针 |
| 复杂度 | O(n) 深拷贝 | O(1) 指针转移 |

**常见误区**

- ❌ 移动后源对象被销毁 — 错误。源对象仍在生命周期内，处于有效但未指定状态。
- ❌ `std::move` 是移动操作 — 错误。`std::move` 只是类型转换，真正的移动发生在移动构造函数中。

**延伸点**：移动构造必须标记 `noexcept`，否则标准库容器扩容时不会使用（回退到拷贝构造）。

一个能直接观察到的例子（`std::move_if_noexcept` 的效果）：

```cpp
struct Tracker {
    Tracker() { std::cout << "D"; }
    Tracker(const Tracker&) { std::cout << "C"; }
    Tracker(Tracker&&) noexcept { std::cout << "M"; }  // ← 去掉 noexcept 试试
};

int main() {
    std::vector<Tracker> v;
    v.reserve(2);
    v.emplace_back();
    v.emplace_back();
    v.emplace_back();  // 触发扩容
}
// 移动构造有 noexcept：输出 DDDMM（扩容时移动旧元素）
// 移动构造无 noexcept：输出 DDDCC（扩容时退化为拷贝）
```

`vector` 扩容要保证强异常安全：如果移动可能抛异常，搬了一半的旧内存已破坏、新内存不完整，无法回滚。所以只有移动构造承诺不抛（`noexcept`）时才敢用移动，否则宁可 O(n) 拷贝——失败了大不了扔掉新内存，原数组完好。
