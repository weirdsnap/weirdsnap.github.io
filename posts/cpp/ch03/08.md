# 移动语义：动机、移后状态与 noexcept

通过右值引用和移动构造函数将资源所有权从临时对象转移至新对象，避免深拷贝开销。

| 维度 | 拷贝语义 | 移动语义 |
|------|----------|----------|
| 参数类型 | `const T&` | `T&&` |
| 资源行为 | 分配新资源，复制内容 | 掠夺源对象资源，置空源指针 |
| 复杂度 | O(n) 深拷贝 | O(1) 指针转移 |

## 移后对象：有效但未指定

移动不销毁源对象，它还在生命周期内，处于**有效但未指定**（valid but unspecified）状态。这六个字拆开看：

- **有效**：对象没有坏。内部不变量还成立，不是悬垂、不是半销毁，调它的析构、赋值这类不要求前置条件的操作是安全的，不会 UB。
- **未指定**：它装着一个确定的值，但标准不告诉你是哪个。这不是随机：它有一个具体状态，只是你不能假设它是哪个。

真正坑人的地方在于：**读移后对象不是 UB，程序不会崩，只会返回一个错误答案**。`vector` 移后调 `size()` 返回 0，今天对；换个编译器、换个优化级别，可能就返回别的。代码看起来能跑，测试可能还过，但行为没有任何保证。

打个比方：移后对象像退过房的酒店房间。房间还在（有效），可以再入住（重新赋值），但屋里剩下什么你不该指望（未指定），更不能把"上次是空的"当成规矩。

标准对移后对象的保证只有一条底线：还能安全地析构、能重新赋值。各类型在这个底线之上的具体表现不同：

- `unique_ptr`：标准明确规定变 `nullptr`，可以依赖。
- `vector`、`string`：实现上通常变空，但标准不保证，别依赖。
- `int` 这种 trivial 类型：根本没有移动构造，`std::move` 之后走的就是拷贝，源值纹丝不动。

所以规则很简单：**移后的对象只用来做两件事，析构或重新赋值；别读它。** 想继续用就先赋个新值。

"别读它"的准确含义是：别调用**有前置条件**的函数，因为你没法确认前置条件还成立。按这个标准把成员函数分两类。

放心调（无前置条件）：

- `size()`、`empty()`、`capacity()`：返回某个合法值，是多少不保证
- `clear()`：把未指定的内容清成确定的空，是救回移后对象的标准手法
- `push_back()`、`+=`：在未指定的内容后面追加，之后对象照常可用
- 重新赋值、`swap`、析构

不能碰（有前置条件，而前提现在无法确认）：

- `front()`、`back()`、`operator[]`、`pop_back()`：要求非空，移后空不空你不知道，空了就 UB
- `*p`（`unique_ptr`）：移后是 `nullptr`，解引用直接崩
- `thread::join()`：移后 `joinable()` 为 false，对不可 join 的线程调 `join()` 直接 `terminate`

还有一类是专门给移后状态设计的"先问再用"接口：`unique_ptr::get()`（返回 `nullptr` 即空）、`future::valid()`（false 即被移走，此时再 `get()` 抛 `future_error`，是明确报错不是 UB）。

一个容易考到的变体：移动容器里的**元素**，容器本身不受影响。

```cpp
std::vector<std::string> v = {"a", "bb", "ccc"};
std::string s = std::move(v[1]);
// s 拿到 "bb"；v.size() 一定是 3，元素还在没有被删除
// v[1].size() 调用合法，但返回值未指定（主流实现是 0）
```

一个常见的隐蔽坑是循环里复用变量：

```cpp
for (auto& item : items) {
    queue.push(std::move(item));
    // item 从此刻起是移后状态，循环里别再碰它的内容
}
```

**常见误区**

- ❌ 移动后源对象被销毁 — 错误。源对象仍在生命周期内，见上面的移后状态。
- ❌ 移后对象一定是"空"的 — 错误。变空是具体类型的行为（如 `unique_ptr`），不是通用保证。
- ❌ `std::move` 是移动操作 — 错误。`std::move` 只是类型转换，真正的移动发生在移动构造函数中。

**延伸点**：移动构造必须标记 `noexcept`，否则标准库容器扩容时不会使用（回退到拷贝构造）。

一个能直接观察到的例子（`std::move_if_noexcept` 的效果）：

```cpp
struct Tracker {
    Tracker() { std::cout << "D"; }
    Tracker(const Tracker&) { std::cout << "C"; }
    Tracker(Tracker&&) noexcept { std::cout << "M"; }  // ← 去掉 noexcept 试试
};

int main() {
    std::vector<Tracker> v;
    v.reserve(2);
    v.emplace_back();
    v.emplace_back();
    v.emplace_back();  // 触发扩容
}
// 移动构造有 noexcept：输出 DDDMM（扩容时移动旧元素）
// 移动构造无 noexcept：输出 DDDCC（扩容时退化为拷贝）
```

`vector` 扩容要保证强异常安全：如果移动可能抛异常，搬了一半的旧内存已破坏、新内存不完整，无法回滚。所以只有移动构造承诺不抛（`noexcept`）时才敢用移动，否则宁可 O(n) 拷贝——失败了大不了扔掉新内存，原数组完好。
