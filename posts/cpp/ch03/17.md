# `std::exit` 不析构局部对象

`std::exit` 直接终止程序，**不做栈展开**：它只销毁静态存储期（和线程存储期）的对象、调用 `atexit` 注册的函数，**自动存储期的局部对象不会被析构**（`[support.start.term]/9.1`）。

**场景示例：**

```cpp
#include <cstdlib>
#include <iostream>

struct S {
    char s;
    S(char s): s{s} {}
    ~S() { std::cout << s; }
};

S a('a');

int main() {
    S b('b');
    std::exit(0);
}
```

输出只有 `a`：`a` 是全局对象，程序终止时由 `exit` 负责销毁；`b` 是局部对象，作用域从未"正常结束"，析构函数被跳过。

对比：`std::exit(0)` 换成 `return 0`，输出变为 `ba`——`return` 正常离开作用域，`b` 先析构，随后静态对象 `a` 在程序终止阶段析构。

**原理解析 + 常见误区**

- ❌ `exit` 会像 `return` 一样触发局部对象析构 — 错误。局部对象的析构依赖正常离开作用域（栈展开），`exit` 直接终止，不做栈展开。
- ❌ `exit` 销毁所有对象 — 错误。只销毁静态/线程存储期对象，顺序为构造的逆序，并与 `atexit` 注册函数按注册逆序交错执行。
- ✅ `std::_Exit` / `std::abort` 更激进：连静态对象都不析构、不调用 `atexit`，立即终止。

**延伸点**：`exit` 会跳过局部 RAII 对象的清理（文件句柄、锁、`unique_ptr` 等），资源回收全推给操作系统。析构函数里有必要清理逻辑的对象，绝不能让 `exit` 绕过它——这也是 C++ 中调用 `exit` 比在 C 中更危险的原因。
