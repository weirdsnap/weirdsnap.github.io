# `std::exit` 不析构局部对象

`std::exit` 直接终止程序，**不做栈展开**：它只销毁静态存储期（和线程存储期）的对象、调用 `atexit` 注册的函数，**自动存储期的局部对象不会被析构**（`[support.start.term]/9.1`）。

**场景示例：**

```cpp
#include <cstdlib>
#include <iostream>

struct S {
    char s;
    S(char s): s{s} {}
    ~S() { std::cout << s; }
};

S a('a');

int main() {
    S b('b');
    std::exit(0);
}
```

输出只有 `a`：`a` 是全局对象，程序终止时由 `exit` 负责销毁；`b` 是局部对象，作用域从未"正常结束"，析构函数被跳过。

对比：`std::exit(0)` 换成 `return 0`，输出变为 `ba`——`return` 正常离开作用域，`b` 先析构，随后静态对象 `a` 在程序终止阶段析构。

**各种存储期对象在 `std::exit` 下的命运**（实测验证，见下文）：

| 对象 | `std::exit` 时析构？ |
|------|----------------------|
| 局部变量（含局部智能指针） | ❌ |
| 堆对象（`new` 出来的） | ❌（内存由 OS 回收，**析构不跑**） |
| 静态局部变量 | ✅ |
| 全局/命名空间静态 | ✅ |
| thread_local（当前线程） | ✅，且**先于**静态对象 |
| 静态的智能指针（`static unique_ptr`） | ✅（指针本身被析构 → 连带释放堆对象） |

验证代码：

```cpp
struct S {
    char s;
    S(char s): s{s} {}
    ~S() { std::cout << s; }
};

S global('g');

void f() { static S local_static('s'); }

int main() {
    S* heap = new S('h');        // 没人 delete
    f();                         // 触发 local_static 构造
    thread_local S tl('t');
    std::exit(0);
}
// 输出：tsg —— thread_local 先析构，静态对象按构造逆序（s 晚于 g 构造，先析构）
// heap 的 'h' 永远不出现
```

两个容易想错的点：

- **堆对象连局部 `unique_ptr` 都救不了**：`unique_ptr` 本身是局部对象，`exit` 不析构它，它持有的堆对象自然也无人释放。要在 `exit` 路径下清理堆资源，只能用 `static`/全局智能指针，或 `atexit` 注册清理函数。
- **静态局部变量算"静态"不算"局部"**：存储期是静态的（程序终止时才销毁），"局部"只影响可见性。所以它在 `exit` 的清理范围内，析构顺序与全局对象统一按构造逆序。

**原理解析 + 常见误区**

- ❌ `exit` 会像 `return` 一样触发局部对象析构 — 错误。局部对象的析构依赖正常离开作用域（栈展开），`exit` 直接终止，不做栈展开。
- ❌ `exit` 销毁所有对象 — 错误。只销毁静态/线程存储期对象，顺序为构造的逆序，并与 `atexit` 注册函数按注册逆序交错执行。
- ✅ `std::_Exit` / `std::abort` 更激进：连静态对象都不析构、不调用 `atexit`，立即终止。

**延伸点**：`exit` 会跳过局部 RAII 对象的清理（文件句柄、锁、`unique_ptr` 等），资源回收全推给操作系统。析构函数里有必要清理逻辑的对象，绝不能让 `exit` 绕过它——这也是 C++ 中调用 `exit` 比在 C 中更危险的原因。
