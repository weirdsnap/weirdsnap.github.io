# weak_ptr

`weak_ptr` 不增加强引用计数，通过 `lock()` 安全观测对象生命周期，用于打破循环引用。

## 为什么需要弱计数

weak_ptr 不拥有对象，但它要能回答两个问题：对象还活着吗（`expired()`），以及给我一份临时使用权（`lock()`）。这两个动作都要读控制块里的计数状态，所以 weak_ptr 持有的是**控制块**的引用，计在 weak_count 上。

推论：强计数归零后对象就析构了，但只要 weak_count 不为零，控制块就一直活着。make_shared 场景下对象和控制块焊在一起，对象那块内存也会跟着被留下，见 shared_ptr 一篇。

| 维度 | `shared_ptr` | `weak_ptr` |
|------|-------------|-----------|
| 引用计数 | shared_count + 1 | weak_count + 1，shared_count 不变 |
| 对象释放权限 | ✅ 控制生命周期 | ❌ 仅观测 |
| 直接访问 | 可直接解引用 | 必须先 `lock()` |

## 循环引用与破环

互持 shared_ptr 的经典泄漏：

```cpp
struct Node {
    std::shared_ptr<Node> next;
    std::shared_ptr<Node> prev;  // 互指，计数永远到不了 0
    ~Node() { std::cout << "dtor\n"; }
};

auto a = std::make_shared<Node>();
auto b = std::make_shared<Node>();
a->next = b;
b->prev = a;
// 作用域结束 a、b 也不会析构：各自的强计数都被对方吊着
```

把 `prev` 改成 `std::weak_ptr<Node>` 就能正常析构。破环的原则是：**weak_ptr 放在不拥有所有权的那一端**。父持子用 shared_ptr，子回指父用 weak_ptr；观察者、回调注册这类"借用"语义也是 weak_ptr。

## 使用要点

- `lock()` 返回一个 shared_ptr：对象活着就拿到临时所有权，使用期间保证不析构；对象死了返回空。
- 别用 `expired()` 判完再 `lock()`：判断和取用之间对象可能刚好析构。直接用 `lock()` 的返回值判断，一步是原子的。
- `std::enable_shared_from_this` 内部就是一个 weak_ptr，shared_ptr 接管对象时回填，用它避免双控制块。

## 常见误区

- ❌ `weak_ptr` 不增加任何计数 — 错误。它增加 `weak_count`，控制块因此不会立即释放。
- ❌ 直接解引用 `weak_ptr` — 错误。必须先 `lock()` 转成 `shared_ptr`。
