# move-only 类型：unique_ptr、thread、future

## 什么是 move-only

拷贝构造和拷贝赋值被 `delete`，只保留移动操作的类型。设计动机是语义上的：**这类资源复制一个没有意义**。

标准库里的三个代表，各对应一种"不可复制"的理由：

| 类型 | 独占的东西 | 为什么不能复制 |
|------|-----------|----------------|
| `unique_ptr` | 一块堆内存的所有权 | 复制它，两个指针析构时双重释放 |
| `thread` | 一个执行线程 | 线程是操作系统实体，复制句柄语义不成立 |
| `future` | 对共享状态的消费权 | `get()` 只能调一次，复制后谁消费？ |

## 后果：能移动，照样能用

move-only 不等于"只能放栈上"。按值传参、按值返回、放进容器，全部可以，只要走移动：

```cpp
std::vector<std::unique_ptr<int>> v;
auto p = std::make_unique<int>(42);

v.push_back(std::move(p));      // 移动进去，p 此后为空
v.emplace_back(std::make_unique<int>(7));  // 直接造一个临时的再移动进去
```

**常见误区**

- ❌ move-only 类型不能放进容器 — 错误。`emplace` 或 `push_back(std::move(x))` 都可以。
- ❌ move-only 不能按值返回 — 错误。返回局部对象走 NRVO 或移动构造，不需要拷贝（见 [返回值优化](./blog.html?post=cpp/ch03/09.md)）。

## 顺带：`emplace_back` 和 `push_back` 的移动次数差

两者都能把 move-only 对象放进容器，但代价不同：

```cpp
struct Tracker {
    static int moves;
    Tracker() {}
    Tracker(const Tracker&) {}
    Tracker(Tracker&&) noexcept { ++moves; }
};

std::vector<Tracker> v;
v.push_back(Tracker{});   // 构造一个临时，再移动进容器：1 次移动
v.emplace_back();         // 参数直接转发到容器里原位构造：0 次移动
```

`push_back(T(...))` 是"先造好再搬进去"，`emplace_back(args...)` 是"把构造参数递进去就地造"。对 move-only 类型两者都能编译，对普通类型 emplace 省一次移动。注意 `emplace_back` 的构造函数调用是**显式也生效**的（`explicit` 构造可以直接用），这也是它偶尔出人意料的地方。
