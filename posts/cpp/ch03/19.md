# 移动不生效的几种情形

`std::move` 只是类型转换（见 [ch03/08](./blog.html?post=cpp/ch03/08.md)），转完能不能真的"移动"，取决于接收方有没有移动构造可绑。以下几种情形，写了 `std::move` 也拿不到移动的效果。

## 情形一览

| 情形 | 实际结果 | 原因 |
|------|----------|------|
| 对 `const` 对象 `std::move` | 静默回退拷贝 | `const T&&` 绑不上移动构造的 `T&&` 参数 |
| 类含 `const` 或引用成员 | 移动**赋值**被删除 | 隐式移动赋值无法给 `const` 成员赋值、无法重绑引用 |
| 用户声明了拷贝/析构 | 移动构造不生成 | 自动生成规则抑制（见 [ch03/13](./blog.html?post=cpp/ch03/13.md)） |
| trivial 类型（`int` 等） | 移动就是拷贝 | 根本没有移动构造，无资源可偷 |

## const 右值回退拷贝

```cpp
struct C {
    C() {}
    C(const C&) { std::cout << "copy\n"; }
    C(C&&)      { std::cout << "move\n"; }
};

const C c;
C c2(std::move(c));   // 输出 copy，不是 move
```

`std::move(c)` 的类型是 `const C&&`，移动构造的参数 `C&&` 绑不上 const 右值，重载决议落到 `const C&` 的拷贝构造。**编译通过，静默拷贝，没有任何警告**。返回值加 `const`（`const std::string getName();`）之所以是反模式，就是它把返回值优化之外的移动也一起废掉了。

## const / 引用成员删掉移动赋值

```cpp
struct WithConst { const int n = 0; };
struct WithRef   { int& r; };

static_assert(!std::is_move_assignable_v<WithConst>);   // 移动赋值被删除
static_assert( std::is_move_constructible_v<WithConst>); // 移动构造还在
static_assert(!std::is_move_assignable_v<WithRef>);
static_assert( std::is_move_constructible_v<WithRef>);
```

构造和赋值要分开看：

- **移动构造还在**：构造是初始化，`const` 成员可以用源对象的对应成员拷贝初始化，引用成员可以初始化绑定到同一个对象。
- **移动赋值没了**：赋值要修改已有成员，`const` 成员不能改、引用成员不能重绑，编译器直接把隐式移动赋值删除。

后果：含这类成员的类放进 `vector`，扩容、排序等需要移动/拷贝赋值的场景会报错或退化，排查时先看成员里的 `const` 和引用。

**常见误区**

- ❌ `std::move` 保证发生移动 — 错误。它只是把表达式转成 xvalue（见 [值类别](./blog.html?post=cpp/ch01/36.md)），const 对象上等于白转。
- ❌ 含 `const` 成员的类完全不能移动 — 错误。移动构造照常，被删的是移动赋值。
