# 拷贝构造 vs 拷贝赋值

拷贝构造函数用于初始化新对象；拷贝赋值运算符用于给已存在的对象重新赋值。

| 维度 | 拷贝构造函数 | 拷贝赋值运算符 |
|------|-------------|--------------|
| 调用时机 | 对象创建时 | 对象已存在时 |
| 自身资源 | 无需处理 | 必须先释放旧资源 |
| 自赋值安全 | 不涉及 | 必须处理 |
| 返回值 | 无 | `T&`（支持链式赋值） |

## 怎么分辨调用的是哪个

看目标对象是不是已经存在，和有没有写 `=` 无关：

```cpp
Buffer a(8);
Buffer b = a;   // 拷贝构造：= 在这里是初始化语法，b 正在被创建
Buffer c(4);
c = a;          // 拷贝赋值：c 已存在，要先扔掉旧资源再接新的
foo(a);         // 按值传参：拷贝构造（形参是新对象）
return a;       // 按值返回：拷贝构造（可能被 RVO 省掉，见 ch03/09）
```

函数按值传参和按值返回走的都是构造一侧，这是常被忽视的两个触发点。

## 拷贝赋值的传统写法

四步骨架，顺序不能乱：

```cpp
Buffer& operator=(const Buffer& other) {
    if (this != &other) {          // 1. 防自赋值
        delete[] data_;            // 2. 释放自己的旧资源
        data_ = new char[other.size_];  // 3. 拷贝新资源
        size_ = other.size_;
        std::memcpy(data_, other.data_, size_);
    }
    return *this;                  // 4. 返回 *this
}
```

少了第 1 步会怎样：`x = x` 时先 `delete[]` 把自己释放，第 3 步再从 `other`（就是自己）读，读的是悬垂内存。自赋值在指针、引用、容器迭代里很容易间接触发，不是只有字面写 `x = x` 才会碰上。

这个写法还有个微妙处：第 2 步先释放、第 3 步 `new` 如果抛异常，对象就停在一个半空状态，析构时再次 `delete` 已经释放过的指针。要保证强异常安全，得先 `new` 成功再释放旧的。

## 现代写法：copy-and-swap

```cpp
friend void swap(Buffer& a, Buffer& b) noexcept {
    std::swap(a.data_, b.data_);
    std::swap(a.size_, b.size_);
}

Buffer& operator=(Buffer other) noexcept {  // 注意：按值传参
    swap(*this, other);
    return *this;
}
```

按值传参这一步就隐式完成了拷贝，swap 之后旧资源跟着形参 `other` 析构。换来的好处：

- 自赋值天然安全：拷贝发生在 swap 之前，`x = x` 只是白白拷一份再换回来；
- 强异常安全天然成立：拷贝失败在函数体外就抛了，`*this` 没被动过；
- 拷贝赋值和移动赋值可以合一：`operator=(Buffer other)` 一个函数同时接住左值（拷贝）和右值（移动）。

代价是每次都会做一次完整拷贝，不能像传统写法那样在容量足够时复用旧资源。对 `vector` 这类追求极致的容器实现有意义，对普通资源类通常无所谓。

**常见误区**

- ❌ `T a = b;` 是赋值 — 错误。这是拷贝初始化，调用拷贝构造函数。
- ❌ 赋值运算符不需要返回值 — 错误。返回 `T&` 是标准约定，缺失会导致链式赋值编译失败。
- ❌ 自赋值检查是多余防御 — 错误。`delete` 之后再从 `other` 读，自赋值时 `other` 就是自己，读到的是悬垂内存。
