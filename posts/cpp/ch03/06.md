# 三/五/零法则

若类需自定义析构、拷贝或拷贝赋值中的任一，则几乎肯定需要全部三者（三法则）；C++11 起扩展为五法则，额外需自定义移动构造和移动赋值；现代 C++ 优先遵循零法则。

| 法则 | 涉及的特殊成员 | 核心思想 |
|------|---------------|----------|
| 三法则 | 析构、拷贝构造、拷贝赋值 | 管理原始资源时三者必须同步自定义 |
| 五法则 | 三法则 + 移动构造 + 移动赋值 | 资源类必须具备移动能力 |
| 零法则 | 均不自定义 | 用智能指针、标准容器避免自定义 |

## 移动构造和移动赋值怎么写

资源类的移动操作有一个标准骨架，四件套：接管、源置空、`noexcept`、（赋值时）自赋值检查。

```cpp
class Buffer {
public:
    // 移动构造：接管指针，源置空
    Buffer(Buffer&& other) noexcept
        : data_(other.data_), size_(other.size_) {
        other.data_ = nullptr;   // 源对象必须留在可析构的状态
        other.size_ = 0;
    }

    // 移动赋值：防自赋值，先释放自己，再接管
    Buffer& operator=(Buffer&& other) noexcept {
        if (this != &other) {
            delete[] data_;
            data_ = other.data_;
            size_ = other.size_;
            other.data_ = nullptr;
            other.size_ = 0;
        }
        return *this;
    }

private:
    char* data_ = nullptr;
    size_t size_ = 0;
};
```

逐条说：

- **接管，不复制**：把源对象的指针/句柄直接拿过来，O(1)，这是移动语义的价值所在。
- **源置空**：保证源对象析构时不重复释放已转移的资源。这也是"有效但未指定"状态的典型实现方式（见 [ch03/08](./blog.html?post=cpp/ch03/08.md)）。
- **`noexcept`**：不标记的话 `vector` 扩容时不敢用你的移动构造，会回退到拷贝（见 [ch03/08](./blog.html?post=cpp/ch03/08.md) 的 `move_if_noexcept` 部分）。
- **自赋值检查只有移动赋值需要**：移动构造的对象正在构造，手里还没有旧资源；移动赋值则必须先释放自己的旧资源再接管。少了检查，`x = std::move(x)` 会先 `delete` 再接管一个悬垂指针。这种自移动 gcc 和 clang 都有 `-Wself-move` 警告，编译期就能抓到。

**常见误区**

- ❌ 五法则意味着必须手写五个函数 — 错误。可通过 `= default` 显式恢复编译器生成，或遵循零法则。
- ❌ 定义了析构函数就必须定义拷贝 — 不严谨。三法则/五法则是设计信号而非语法强制。

**延伸点**：C++11 的特殊成员函数生成规则：用户声明析构、拷贝构造或拷贝赋值中的任一，编译器不会自动生成移动操作。老式资源类在 C++11 下会静默失去移动能力。
