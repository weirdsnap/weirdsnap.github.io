# 多重继承下的 vtable 布局

多继承时派生类为每个基类各备一张 vtable，对象内有多个 vptr；跨基类边界调用被重写的虚函数时需要 thunk 调整 `this`。

---

## 一、多重继承的对象布局

```cpp
struct Base1 {
    virtual void f1();
    virtual void g1();
    virtual ~Base1() = default;
};

struct Base2 {
    virtual void f2();
    virtual void g2();
    virtual ~Base2() = default;
};

struct Derived : Base1, Base2 {
    void g1() override;     // 重写 Base1::g1
    void f2() override;     // 重写 Base2::f2
    virtual void h();       // 新增虚函数
};
```

**对象内存布局（64 位 Itanium ABI）**：

```
Derived 对象：
┌────────────────────┐  ← this (Derived*)，也是 Base1 子对象起始
│ vptr_for_Base1     │  ← 指向 "Derived-in-Base1" 虚表
├────────────────────┤
│ Base1 members      │
├────────────────────┤
│ vptr_for_Base2     │  ← 指向 "Derived-in-Base2" 虚表（偏移处）
├────────────────────┤
│ Base2 members      │
├────────────────────┤
│ Derived members    │
└────────────────────┘
```

第一个基类（Base1）是**主基类**，与派生类共享起始地址，偏移为 0；Base2 子对象带偏移（本机实测为 8 字节，即一个 vptr 的大小），`Base2* pb2 = &d` 拿到的指针值和 `&d` 不同。

**两张虚表的内容**：

```
Derived-in-Base1 虚表:        Derived-in-Base2 虚表:
┌─────────────────────┐      ┌──────────────────────────┐
│ &Base1::f1          │      │ thunk → Derived::f2      │ ← f2 被重写，需调整 this
├─────────────────────┤      ├──────────────────────────┤
│ &Derived::g1        │      │ &Base2::g2               │ ← 未重写
├─────────────────────┤      └──────────────────────────┘
│ &Derived::h         │ ← 新增虚函数追加在主基类表尾
└─────────────────────┘
```

---

## 二、thunk 用在哪

规则：**被派生类重写的虚函数，经带偏移的基类子对象调用时，vtable 槽位里放 thunk**——先把 `this` 减去偏移回到 `Derived` 起始，再跳到派生类实现。

```cpp
Derived d;
Base1* pb1 = &d;
Base2* pb2 = &d;

pb1->g1();  // 主基类偏移为 0，槽位直接存 &Derived::g1，无调整
pb2->f2();  // f2 被重写，槽位存 thunk：this -= offset → Derived::f2
pb2->g2();  // g2 未被重写，调的就是 Base2::g2，无调整
```

thunk 的伪代码：

```cpp
// Derived-in-Base2 虚表中 f2 槽位的实际入口
void thunk_for_Derived_f2(Base2* this_) {
    Derived* real = reinterpret_cast<Derived*>(
        reinterpret_cast<char*>(this_) - offset_of_Base2_in_Derived);
    Derived::f2(real);   // 尾跳，开销通常一两条指令
}
```

反过来的调用不存在：`pb2->g1()` 编译就失败——静态类型 `Base2` 里没有 `g1`。thunk 只可能出现在"基类声明、派生类重写"的函数上。

## 三、delete 通过非最左基类指针

```cpp
Base2* pb2 = new Derived();
delete pb2;   // 虚析构的 deleting destructor 槽位同样是 thunk：
              // 调完 ~Derived() 后把指针减偏移回对象起始，再 operator delete
```

这也是"多态基类析构必须 virtual"在多继承下的具体原因：没有虚析构，`delete pb2` 按静态类型算地址，释放的是对象中间的地址。

---

## 四、常见误区

- ❌ 多继承的所有基类共享同一张 vtable — 错误。每个基类有自己的 vtable 和 vptr。
- ❌ 新增虚函数加到每张表里 — 错误。只追加在主基类（第一个基类）的表尾。
- ❌ 每次跨基类调用都走 thunk — 错误。只有"基类声明且被派生类重写"的函数经带偏移的子对象调用才走 thunk；未重写的、主基类上的调用都不需要。
- ❌ 多继承对象大小 = 各基类之和 — 错误。还要算额外的 vptr 和对齐填充。

---

## 五、一句话总结

> 多继承下每个基类一张虚表、对象内多个 vptr；经带偏移的基类子对象调用被重写的虚函数要走 thunk 调整 this——这是多继承最主要的内存和性能开销来源。
