# 名字查找的"找到即停"

派生类中声明的同名函数会在查找阶段"筑墙"，完全隐藏基类的同名函数；重载决议仅在可见候选集中进行。

**场景示例：**

```cpp
class Base { public: void f(int) {} };
class Derived : public Base {
public:
    void f(double) {}  // 隐藏了 Base::f(int)
};
Derived d;
d.f(1);  // ✅ 编译通过，但调的是 Derived::f(double)：1 被隐式转成 double
```

危险正在于它能编译。调用者的意图通常是 `Base::f(int)`，但名字查找在 `Derived` 作用域找到 `f` 就停了，不再去基类找；重载决议只在 `f(double)` 这一个候选上做，int→double 转换合法，于是静默调错函数。

想让基类版本重新参与重载，用 `using` 声明把名字引进来：

```cpp
class Derived : public Base {
public:
    using Base::f;          // Base::f(int) 重新可见
    void f(double) {}
};
Derived d;
d.f(1);   // ✅ Base::f(int)，按实参类型正常重载决议
```

**常见误区**

- ❌ 派生类 `f(double)` 和基类 `f(int)` 构成重载 — 错误。二者不在同一作用域，不构成重载。
- ❌ 签名不同就不会隐藏 — 错误。名字隐藏只看标识符名，不看签名。
- ❌ 隐藏的实参类型对不上才出问题 — 错误。能对上更危险：隐式转换后静默调错函数，如上例。

**延伸点**：ADL（参数依赖查找）是名字查找的例外扩展，使 `std::cout << obj` 和 `swap(obj1, obj2)` 惯用法得以工作。
