# 静态类型与动态类型

静态类型是编译期已知的声明类型；动态类型是运行期对象内存中实际的类型，仅对多态类型（含虚函数）的对象通过指针/引用访问时才有意义。

| 场景 | 静态类型 | 动态类型 |
|------|----------|----------|
| `Base* p = new Derived()` | `Base*` | `Derived*` |
| `Base b;` | `Base` | `Base`（非多态对象无动态类型差异） |

## 谁决定什么

先把口诀里的两个动作定义清楚：

- **重载（overload）**：编译期从一组同名函数里挑一个，挑选依据是实参的静态类型。
- **覆盖（override）**：派生类写一个与基类虚函数同签名的版本，把基类的实现顶替掉；运行时对象是什么类型，就执行哪个版本。

两者各管一段，记一句：**重载看静态，覆盖看动态**。

- 静态类型管编译期：能不能调用某个成员（成员可访问性）、重载决议选哪个函数，全部按静态类型来。
- 动态类型管运行期：被覆盖的虚函数最终执行基类版还是派生类版，按指针/引用实际指向的对象类型来。

```cpp
struct Base {
    void f()        { cout << "Base::f\n"; }     // 非虚
    virtual void g(){ cout << "Base::g\n"; }     // 虚
};
struct Derived : Base {
    void f()        { cout << "Derived::f\n"; }
    void g() override { cout << "Derived::g\n"; }
    void h()        {}                            // Base 没有
};

Base* p = new Derived;
p->f();   // Base::f    非虚，按静态类型 Base
p->g();   // Derived::g 虚函数，按动态类型 Derived
p->h();   // 编译错误：静态类型 Base 里没有 h
```

以 `p->h()` 为例，哪怕指针实际指向的对象有 `h`，编译器也只认声明类型 `Base*`，直接拒绝编译。反过来，非虚函数 `f` 即使派生类写了同名版本，也还是按静态类型调 `Base::f`——只有虚函数才把决定权推迟到运行期。

**常见误区**

- ❌ 所有变量都有动态类型 — 不准确。每个对象都有实际类型，但"动态类型"有别于静态类型只在多态对象经指针/引用访问时发生；非多态对象的静态类型就是它的全部，谈不上"动态"。
- ❌ 按值传递/返回多态对象安全 — 错误。按值接收基类会切片，派生类部分被静默抹除。
