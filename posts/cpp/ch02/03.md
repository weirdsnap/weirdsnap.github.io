# override 与虚函数重写

`override` 是编译期虚函数重写检查；派生类重写时省略 `virtual` 但永远写 `override`。

| 场景 | 是否必须写 `virtual` | 是否必须写 `override` |
|------|---------------------|----------------------|
| 基类声明虚函数 | ✅ 必须 | ❌ 无 |
| 派生类重写虚函数 | ❌ 可选（冗余） | ✅ **强烈推荐** |
| 派生类新增虚函数 | ✅ 需要 | ❌ 不写 |

## 一、怎样才算"重写"

重写要求签名完全一致：函数名、参数类型列表、const 限定、引用限定符（`&` / `&&`），`noexcept` 只能收紧不能放宽。任何一项差一点，就不是重写，而是在派生类里声明了一个新函数，把基类的虚函数隐藏掉：

```cpp
struct Base { virtual void f(int); };
struct Derived : Base {
    void f(long);   // 参数 int → long，不是重写！Base::f 被隐藏
};

Base* p = new Derived;
p->f(1);   // 调 Base::f(int)：Derived::f(long) 根本没参与多态
```

没写 `override` 时这件事静默发生，运行时行为和你想的完全不一样；写了 `override` 它就是编译错误。这就是 `override` 存在的全部意义。

警告层面的差异也值得知道：

- Clang 的 `-Wall` 会报 `-Woverloaded-virtual`，能抓住这种情况；
- GCC 的 `-Wall -Wextra` 对此完全沉默，要显式开 `-Woverloaded-virtual` 才有警告；
- GCC 的 `-Wsuggest-override` 只提示"确实重写了但忘写 override"的函数，对这种没重写上的反而不报。

## 二、返回类型唯一的例外：协变

重写时返回类型允许收窄为派生类的指针或引用（协变返回类型，covariant return）：

```cpp
struct Base    { virtual Base* clone(); };
struct Derived : Base { Derived* clone() override; };   // OK：Base* → Derived*
```

收窄方向是安全的：多态调用者拿到的是比承诺更具体的类型。除此之外返回类型必须一致，按值返回 `Base`/`Derived` 也不算协变。

## 三、访问控制与重写无关

虚函数可以是 private，派生类照样重写，多态调用照样走到派生类版本：

```cpp
struct Base {
    virtual void g() {}
    virtual ~Base() = default;
};
struct Derived : Base {
private:
    void g() override {}   // private，但 Base* p = ...; p->g() 仍调到这里
};
```

访问控制按静态类型检查（`p` 是 `Base*`，`Base::g` 是 public，放行），派发按动态类型（执行 `Derived::g`）。模板方法模式就靠这个：基类 public 非虚接口，内部调用 private 虚函数钩子，派生类只重写钩子。

## 四、override / final 是上下文关键字

它们只在成员函数声明尾部有特殊含义（`final` 还可跟在类名后），不是保留字，拿来当变量名完全合法：

```cpp
int override = 1, final = 2;   // 合法
```

`final` 的两种用法：`void f() final;` 禁止再被重写；`class D final {};` 禁止被继承。两者可组合：`void f() override final;`，向上检查重写、向下禁止再重写。

**常见误区**

- ❌ 派生类重写时 `virtual` 必须省略 — 错误。`virtual` 可选冗余，写了不会错，现代风格推荐省略。
- ❌ 返回类型改一下也算重写 — 错误。除协变返回外，返回类型必须一致，否则只是同名新函数。
