# DNS 怎么落到分流器手里：redir-host 和 fake-ip

分流规则里大量的条目是域名：`DOMAIN-SUFFIX,github.com,US`。问题是，路由器转发一个包的时候，手里只有 IP，没有域名。域名是在 DNS 阶段出现的，所以要按域名分流，就必须先把 DNS 的解析权握在自己手里。

这一篇讲 DNS 的接管路径，以及两种截然不同的返回策略。

---

## 家里的 DNS 是怎么走的

手机上设置的 DNS 一般是网关地址 192.168.5.1。路由器上跑着 dnsmasq，监听 53 端口，负责把域名解析成 IP，顺便按 `/etc/hosts` 和 DHCP 分配的主机名做本地解析。

默认情况下 dnsmasq 直接把查询转发给上游（运营商 DNS 或公共 DNS），返回真实 IP。整个过程中没有分流器什么事。

要让分流器参与，就得改 dnsmasq 的转发目标，让它把查询交给分流器的 DNS 监听端口（mihomo 默认 1053）：

```
# /etc/config/dhcp
list server '127.0.0.1#1053'
```

这样客户端查任何域名，都先经过分流器，它可以根据规则决定走哪个上游、要不要缓存，也顺便记下「这个 IP 对应哪个域名」。

---

## 方式一：redir-host

redir-host 的思路很直接：正常解析，把真实的 IP 返回给客户端。分流器同时在自己的内存里维护一张表：

```
93.184.216.34 -> example.com
```

等客户端真的发起连接，分流器收到包，拿目标 IP 去查这张表，找回域名，再用域名去匹配规则。

优点是客户端拿到的是真 IP，即使某些流量没走代理，它也能直接连上。缺点是这张表会过期、会冲突（一个 IP 可能对应多个域名，CDN 尤其严重），而且解析结果是真实的，理论上存在 DNS 污染的问题。

---

## 方式二：fake-ip

fake-ip 反着来。客户端查 `example.com`，分流器不给真 IP，而是从保留网段里挑一个地址返给它，比如 198.18.0.5，同时记下：

```
198.18.0.5 -> example.com
```

客户端拿着 198.18.0.5 去连，分流器看到目标是这个网段，直接查表知道用户要访问 example.com，于是按域名匹配规则、自己去做真正的 DNS 解析和连接。

好处很明显：

- 规则匹配一直是域名维度，不用反查
- 解析推迟到真正建连时，省一次查询
- 客户端拿到的地址根本没有真实意义，DNS 污染自然失效

坏处同样明显：**198.18.0.0/16 是一个不存在的网段**。所有拿到假 IP 的连接都必须由分流器接住并代为转发。如果客户端拿到假 IP 之后，流量没进代理，比如它自己不走代理直接发包，结果就是连不上，超时。

---

## 这就是「非 TUN 不能用 fake-ip」的原因

这句话我一开始没想明白，后来对着自己的网络配置才反应过来。

我们现在的做法是手机手动填代理：能配代理的 App 走代理，不配的就是直连。如果 DNS 返回假 IP，那些直连的流量拿着 198.18.0.5 发包出去，公网上根本没有这个地址，只能超时。

TUN 模式不存在这个问题，因为路由表把整个网段都指向 tun0，所有包都会被接管。所以 fake-ip 和 TUN 是一对：接管要彻底，才能用假地址。

非 TUN 的 HTTP 代理场景，客户端只有一部分流量进代理，DNS 就只能给真地址，也就是 redir-host。

---

## respect-rules 与循环依赖

分流器自己也要解析域名：上游节点服务器的域名、要直连的域名。这里有个循环：解析节点域名需要出网，出网又要经过分流器。

mihomo 从 1.16 开始提供了 `respect-rules`，让自身的 DNS 查询也遵循分流规则。配套还需要 `proxy-server-nameserver`，专门用于解析代理服务器的域名，这条路径必须直连，否则就是死循环。

`IP-CIDR,1.1.1.1/32,PROXY` 这类规则在 respect-rules 下才有意义：它是给分流器自己的 DoH 请求用的。在非 TUN 的场景里，客户端自己的 DNS 包根本没经过分流器，这条规则就是死的。

---

## 我们为什么没动 DNS

结论很朴素：不需要。

手动配代理加 PAC 分流的模式下，DNS 由 dnsmasq 正常解析，返回真实 IP，客户端拿到什么就用什么。规则匹配主要靠域名（PAC 里是 URL 层面的匹配，也不需要 IP），完全没有 fake-ip 的用武之地。

改 DNS 得动的是一整套东西：dnsmasq 转发、上游选择、fake-ip-filter 排除局域网域名、策略路由。任何一环没配好，表现都是「网页打不开」，而排查又得从头捋一遍。收益只是让规则匹配更精准一点，不值。

---

## 小结

- 按域名分流的前提是掌握 DNS，否则手里只有 IP。
- redir-host 返回真 IP，靠 IP 反查域名，适合部分流量走代理的场景。
- fake-ip 返回假地址，把解析推迟到建连时，但要求流量被完整接管。
- fake-ip 和 TUN 是绑在一起的，非 TUN 场景用它，直连流量会直接超时。
- 分流器自身的 DNS 查询要小心环路，respect-rules 和 proxy-server-nameserver 是为此而生的。
