# 分流规则的执行模型：第一条命中与兜底

规则文件的写法看起来很自由：一长串 `DOMAIN-SUFFIX`、`IP-CIDR`、`GEOIP`，想加就加。但它的执行模型其实非常死板：从上往下扫，第一条命中的规则生效，后面的全部不看。

几乎所有「规则明明写了却不生效」的问题，根源都是这一条。这篇讲清楚匹配顺序、几类规则的语义，以及兜底为什么最容易出事。

---

## 匹配是自上而下的短路求值

举个例子：

```yaml
rules:
  - GEOIP,CN,DIRECT
  - DOMAIN-SUFFIX,example.com,PROXY
  - MATCH,PROXY
```

看起来 example.com 走代理，国内走直连，其他走代理。实际运行的时候，`example.com` 的第一条连接会先被拿去匹配 `GEOIP,CN`。如果解析出的 IP 落在数据库标注为 CN 的网段里（CDN 服务经常把域名解析到离用户最近的一台国内服务器），第一条就命中了，走直连。第二条永远轮不到。

所以顺序不是「优先级提示」，而是硬性的执行顺序。规则的位置本身就是逻辑。

正确的写法是把具体的域名规则放在宽泛的 GEOIP 之前：

```yaml
rules:
  - DOMAIN-SUFFIX,example.com,PROXY
  - DOMAIN-SUFFIX,example.net,PROXY
  - GEOIP,CN,DIRECT
  - MATCH,DIRECT
```

---

## 几类规则的语义差别

| 类型 | 匹配对象 | 注意事项 |
|---|---|---|
| DOMAIN | 完整域名 | 精确相等，大小写不敏感 |
| DOMAIN-SUFFIX | 域名后缀 | `example.com` 能匹配 `api.example.com`，也能匹配 `notexample.com`（因为后缀是子串） |
| DOMAIN-KEYWORD | 域名子串 | 最容易误伤，`google` 会命中 `googlesource`、`mockgoogle.cn` |
| IP-CIDR | 目标 IP | 需要先解析；加 `no-resolve` 可避免额外查询 |
| GEOIP | IP 所属国家 | 依赖 GeoIP 数据库，只认国家分类 |
| GEOSITE | 域名集合 | 依赖 GeoSite 数据库，按站点分类匹配 |
| MATCH | 任何流量 | 兜底，必须放最后 |

`DOMAIN-SUFFIX` 那个坑值得多说一句。它的匹配方式是按后缀字符串比对，`example.com` 确实能覆盖 `api.example.com`，但也会覆盖 `evilexample.com`。所以写后缀规则时，别指望它做「子域名」的精确约束。

---

## IP 规则和 no-resolve

`IP-CIDR` 和 `GEOIP` 要判断目标 IP，就得先知道目标 IP。如果这个包是域名连接，分流器在匹配时会临时做一次 DNS 查询，这在规则很多的时候会造成大量查询和延迟。

加 `no-resolve` 的意思是：如果当前连接是按域名来的，不要为这条 IP 规则专门去解析，直接认为不匹配，继续往下走。它适合那种「只处理 IP 直连流量」的规则，比如：

```yaml
  - IP-CIDR,192.168.0.0/16,DIRECT,no-resolve
  - GEOIP,CN,DIRECT
```

局域网段那条加 `no-resolve` 是常识，否则每条域名连接都要先解析一遍才能判断。

---

## 兜底规则决定「漏网的命运」

`MATCH` 是所有规则都没命中时的最后一条。它的选择决定了整个分流的性格：

- `MATCH,PROXY`：默认走代理，直连的规则要写全。漏掉一个国内站点，它就走代理，多花一份转发成本。
- `MATCH,DIRECT`：默认直连，走代理的规则要写全。漏掉一个需要走代理的站点，它就连不上，得手动补。

我们一开始用的是 `MATCH,PROXY`，理由是「漏了还能用」。实际用下来发现问题：小红书的视频一直加载不出来。查日志发现，某些 CDN 域名不在我写的直连清单里，落到了兜底的代理分支，于是在有限的 CPU 上走了一遍用户态转发，卡得明显。

改成 `MATCH,DIRECT` 之后，国内流量全部直连，问题消失。代价是需要走代理的站点如果没写规则就打不开，得我看到之后手动补一条。

这就是白名单和黑名单的取舍。家用场景我倾向白名单：漏网的站点偶尔打不开，补一条就能解决；而国内大带宽流量每天都在跑，把它放到直连才是收益最大的事。

---

## 怎么确认某条流量走了哪条规则

别猜，看日志。分流器一般都会把命中情况写进日志，grep 一下域名就行：

```sh
grep -i xiaohongshu /tmp/mihomo.log | tail -3
```

输出会告诉你这次连接匹配到的是 `GeoIP(CN) using DIRECT` 还是某条 `DOMAIN-SUFFIX`。看到结论之后再决定要不要加规则、加在哪里。跳过这一步直接改配置，很容易改到一个本来就已经命中的位置上去，白改。

---

## 小结

- 规则是自上而下的短路匹配，位置即优先级。
- 具体域名规则要放在 GEOIP、GEOSITE 这类宽泛规则之前。
- `DOMAIN-SUFFIX` 是字符串后缀比对，会误伤相似域名。
- IP 类规则记得加 `no-resolve`，否则每条域名连接都要额外解析。
- 兜底用 PROXY 还是 DIRECT，本质是黑名单和白名单的取舍，看哪种漏网成本更低。
