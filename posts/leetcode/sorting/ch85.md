> **标签**：排序、扫描线、差分
# 会议室 II（253. Meeting Rooms II）

## 题意

给定会议时间区间，求**至少需要多少间会议室**——即任意时刻同时进行会议的峰值数量。端点相接不叠加（`[5,10]` 结束的同时 `[10,15]` 可以开始，不算两间）。

```
输入: intervals = [[0,30],[5,10],[15,20]]
输出: 2        （[0,30] 与 [5,10]/[15,20] 分别撞车）

输入: intervals = [[7,10],[2,4]]
输出: 1

输入: intervals = [[5,10],[10,15],[15,20]]
输出: 1        （端点相接，一间串行足够）
```

---

## 思路：差分 + 扫描线求并发峰值

把每个会议拆成两个事件：**起点 +1（占用一间）、终点 −1（释放一间）**。按时间顺序累加事件值，`cur` 就是当前并发会议数，历史峰值即答案。用 `map<int,int>` 聚合同一时间点的事件并自动按时间排序。

端点相接不出错的原因：同一时间点 t 上，终点事件 −1 和起点事件 +1 **先聚合再结算**——`cnt[t] = -1 + 1 = 0`，净效果为零，不会虚增并发。

## 解法：map 差分扫描

```cpp
class Solution {
public:
    int minMeetingRooms(vector<vector<int>>& intervals) {
        // 差分：每个时间点记录会议室数量变化
        map<int, int> cnt;
        for (const auto& interval : intervals) {
            cnt[interval[0]]++;   // 开始，+1
            cnt[interval[1]]--;   // 结束，-1
        }

        // 扫描线：按时间累加，峰值即所需会议室数
        int maxRooms = 0;
        int curRooms = 0;
        for (const auto& [point, value] : cnt) {
            curRooms += value;
            maxRooms = max(maxRooms, curRooms);
        }
        return maxRooms;
    }
};
```

---

## 核心理解

### 1. "最少会议室数" = "并发峰值"

这是一个转化：分配问题（把会议塞进房间）等价于计数问题（任一时刻最多几个会同时进行）。峰值 k 时必须有 k 间房（下界），而贪心分配（哪个房间空用哪个）恰好 k 间就够（上界）——两界相碰，答案就是峰值。理解这个等价性，才知道为什么数峰值而不是模拟分房。

### 2. 差分扫描线 vs 双指针/堆

同一件事还有两种常见写法：起点、终点各排序后**双指针**对扫；或起点排序 + **最小堆**维护"当前各房间的最早结束时间"。三者都是 O(n log n)。差分版代码最短、概念最通用（任何"区间覆盖计数"问题都能套）；堆版在"需要知道具体哪间房/哪个会议"时更灵活（比如要输出分配方案）。

### 3. 同点事件的聚合顺序 = 语义开关

本题"终点事件和起点事件同点先抵消"对应**半开区间** `[a, b)` 语义。如果题面改成"端点相接也算撞车"（闭区间），差分就要拆成"同点先 +1 结算再 −1"的两步——差分框架不变，**事件结算顺序**表达开闭语义。这也是 oracle 用 `a <= s < b` 判并发的原因。

## 复杂度

| | 时间 | 空间 |
|--|------|------|
| map 差分扫描 | O(n log n) | O(n) |

验证：对拍独立 oracle——峰值必出现在某个起点时刻 `s`（事件间计数恒定），对每个起点数 `a <= s < b` 的会议取最大，O(n²)。官方样例 + 手工边界（空、完全重合 ×3、端点三连接）+ **穷举端点 [0,5] 内全部区间（a<b）、数量 ≤ 3 的全部组合**（816 组）+ 500 组随机，**1,321 条断言全过**。

---

## 踩坑点 / 注意点

- ❌ **同点起止事件分开结算导致虚增**。若写成"遍历排序后的事件列表，逐条累加"，且把起点事件排在终点事件前面，`[5,10],[10,15]` 会在 t=10 处瞬间算出并发 2。map 聚合天然规避；手写事件排序时必须把终点事件排前面。
- ❌ **峰值更新漏了 `max`**。`cur` 只是当前值，答案要历史峰值——扫描中 `maxRooms = max(maxRooms, curRooms)` 每步都要做，不能只在最后取。
- ⚠️ **并发峰值与"时刻"的微妙处**：峰值出现在"起点事件刚结算完"的瞬间，所以 oracle 才选起点时刻采样。想自己写 oracle 对拍时，这是个容易想错的点。
