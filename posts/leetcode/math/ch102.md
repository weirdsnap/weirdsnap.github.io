# 下一个更大元素 III（556. Next Greater Element III）

## 题意

给定 32 位有符号整数 `n`，把它的十进制位重新排列，求比 `n` 大的最小数。不存在（或结果超出 32 位范围）返回 `-1`。

```
输入: n = 12       输出: 21
输入: n = 21       输出: -1     （21 已是最大排列）
输入: n = 1999999999  输出: -1  （下一个排列 9199999999 超出 INT_MAX）
```

- `1 <= n <= 2³¹ - 1`

## 思路

"重排数位求恰好更大的最小数"，就是 **next_permutation**（下一个排列）的数位版，标准四步：

1. 从右往左找第一个"突破口" `i`：满足 `bit[i] < bit[i+1]`。找不到说明整体降序，已是最大排列；
2. 从右往左找第一个比 `bit[i]` 大的 `bit[j]`（后缀里的最小够用者）；
3. 交换 `bit[i]`、`bit[j]`；
4. 把 `i+1` 到末尾的后缀反转——它原本是降序，反转即升序，保证增量最小。

最后把数位拼回整数，注意拼出的值可能超出 `INT_MAX`，要用 `long long` 接住再判断。

## 解法：手写 next_permutation + 溢出检查

```cpp
class Solution {
public:
    int nextGreaterElement(int n) {
        vector<int> bit;
        int temp = n;
        // 将 n 的每一位提取出来（此时是逆序：个位在前）
        while (temp > 0) {
            bit.push_back(temp % 10);
            temp /= 10;
        }
        // 翻转为正常的数字顺序（高位在前，低位在后）
        reverse(bit.begin(), bit.end());

        int m = bit.size();

        // 第 1 步：从右往左找到第一个递减的突破口 i（bit[i] < bit[i+1]）
        int i = m - 2;
        bool flag = false;
        while (i >= 0) {
            if (bit[i] < bit[i + 1]) {
                flag = true;
                break;
            }
            i--;
        }

        // 如果找不到这样的 i，说明已经是最大排列，直接返回 -1
        if (!flag ) {
            return -1;
        }

        // 第 2 步：从右往左找到第一个比 bit[i] 大的数 bit[j]
        int j = m  -1;
        while (bit[j] <= bit[i]) {
            j--;
        }

        // 第 3 步：交换 bit[i] 和 bit[j]
        swap(bit[i], bit[j]);

        // 第 4 步：反转 i+1 到末尾的部分，使它变成升序（最小的后缀）
        reverse(bit.begin() + i + 1, bit.end());

        // 第 5 步：把 bit 拼回一个整数，同时检查是否超出 INT_MAX
        long long ans = 0;
        for (int k = 0; k < m; k++) {
            ans = ans * 10 + bit[k];
        }
        return ans > INT_MAX ? -1 : ans;

    }
};
```

## 核心理解

### 1. 为什么突破口要从右往左找

要"恰好更大"，改动必须发生在**尽量靠右**的位置。`i` 右边是一段降序后缀（已经排不出更大的组合），`i` 是第一个还有余地的位置。找不到 `i` 意味着整个数降序，如 `21`、`321`，就是最大排列，返回 `-1`。

### 2. 第 2 步的 `<=` 和第 4 步为什么用 reverse 不用 sort

后缀 `i+1..m-1` 此时是降序的。从右往左第一个满足 `bit[j] > bit[i]` 的就是后缀里比 `bit[i]` 大的最小值——判断写成 `<=` 继续左移，等值跳过，保证交换后增量最小。

交换 `bit[i]` 和 `bit[j]` 之后，后缀**仍然是降序**（`bit[j]` 换到 `i` 位，`bit[i]` 插回后缀中它原来的相对位置，单调性不变——因为 `bit[j]` 是后缀中第一个大于 `bit[i]` 的，`bit[i]` 落回去恰好仍满足左右降序）。所以第 4 步一个 `reverse` 就得到升序后缀，O(n)，不需要 sort 的 O(n log n)。

### 3. 位数不变也会溢出——本题特有的坑

和 LC 31（纯数组版）不同，这里排列结果要和 `INT_MAX` 比。位数没变不代表值合法：`1999999999` 的下一个排列是 `9199999999`，十位没变多但值超了 32 位。所以拼接时用 `long long` 累加，最后 `> INT_MAX` 判 `-1`。这是 556 比 31 多出来的唯一一步，也是官方用例里专门卡的点。

### 4. STL 一行替代

比赛或工程里不用手写：转成字符串调 `std::next_permutation`，返回 `false` 就是最大排列：

```cpp
string s = to_string(n);
if (!next_permutation(s.begin(), s.end())) return -1;
long long v = stoll(s);
return v > INT_MAX ? -1 : (int)v;
```

手写版的价值在于搞清楚四步各自在干什么，下次遇到变体（比如"上一个更小"、"恰好第 k 个排列"）才知道改哪一步。

## 复杂度

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| 时间 | O(d) | d 为位数，最多 10；四步各扫一遍 |
| 空间 | O(d) | 数位数组 |

官方样例通过，另补了 `1999999999`（溢出边界）、`2147483647`（INT_MAX 本身）、`9`（单位数）三个定向用例，并和 STL `next_permutation` 参照实现对拍了两千组随机 32 位整数，结果一致。

## 踩坑点

### ❌ 拼接结果直接用 int 累加

`ans = ans * 10 + bit[k]` 若 `ans` 是 int，`1999999999` 拼到 `9199999999` 中途就溢出了，后面的 `> INT_MAX` 判断拿到的是 UB 之后的垃圾值。先 `long long` 接住，判完再转。

### ❌ 第 4 步用 sort 替换 reverse

结果对但慢，而且暴露了"没想清楚后缀性质"——交换后后缀仍是降序这一点没推到，就写不出 reverse。四步里每步都有非平凡的理由，值得推一遍。
