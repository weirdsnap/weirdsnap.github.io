# 阿姆斯特朗数（1134. Armstrong Number）

## 题意

`k` 位数 `n` 如果等于"每位数字的 `k` 次方之和"，就是阿姆斯特朗数（水仙花数）。给定 `n`，判断它是不是。

```
输入: n = 153
输出: true
解释: 153 = 1³ + 5³ + 3³

输入: n = 123
输出: false
解释: 1³ + 2³ + 3³ = 36 ≠ 123
```

约束：`1 <= n <= 10⁸`。

---

## 思路：两趟扫描

第一趟数出位数 `k`，第二趟逐位求 `digit^k` 累加，最后和 `n` 比较。幂次手写整数循环即可，别碰 `pow`（浮点）。

## 解法：模拟 + 手写整数幂

```cpp
class Solution {
public:
    bool isArmstrong(int n) {
        int temp = n;
        int sum = 0;
        int k = 0;
        while (temp != 0) {
            temp /= 10;
            k++;
        }
        temp = n;
        while (temp != 0) {
            sum += power(temp % 10, k);
            temp /= 10;
        }

        return n == sum;
    }
    int power(int base, int exp) {
        int res = 1;
        while (exp--) res *= base;
        return res;
    }
    /*
    // 不会溢出的快速幂：中间变量改用 long long
    int power(int base, int exp) {
        long long res = 1;
        long long b = base;
        while (exp) {
            if (exp & 1) res *= b;
            b *= b;
            exp >>= 1;
        }
        return (int)res;
    }
    */
};
```

---

## 核心理解

### 1. `int` 在本题约束下恰好安全，但很悬

`n <= 10⁸`，位数最多 9，而 9 位数只有 `10⁸` 本身（和为 `1⁹ = 1`）。真正的上限在 8 位数：`8 × 9⁸ = 344,373,768`，离 `INT_MAX`（约 21 亿）还有余量。所以 `int sum` 不会溢出。但这个"安全"是算出来的不是猜出来的：约束稍微放宽（比如 `n <= 10⁹`），`10 × 9⁹ ≈ 39 亿`就越界了。注释里那个 long long 快速幂版本就是为这种情况备的——顺手一提，快速幂在这里完全没必要（`k <= 9`，朴素循环最多乘 8 次），它的价值只在防溢出。

### 2. 为什么不用 `pow`

`pow` 返回 `double`，虽然 2⁵³ 以内的小整数幂在常见实现里通常是精确的，但标准不保证，`pow(9, 8)` 算出 `43046720.9999...` 再强转 int 就是差 1 的惨案。数位题一律手写整数幂或累乘，和 [ch95](./blog.html?post=leetcode/math/ch95.md) 里 `p *= 10` 替代 `pow(10, k)` 是同一条纪律。

### 3. 这题其实可以打表

10 进制下阿姆斯特朗数是有限的（数学上已证明只有 88 个），`10⁸` 以内只有 27 个：1-9、153、370、371、407、1634、8208、9474、54748、92727、93084、548834、1741725、4210818、9800817、9926315、24678050、24678051、88593477。把这 27 个数存成集合查表是 O(1)。当然面试场景还是老老实实写模拟，打表只是知道一下"这题的答案空间有多稀疏"。

## 踩坑点 / 注意点

- ❌ **用 `pow(digit, k)` 再强转 int**。浮点幂的精度没有标准保证，边界上差 1 就会误判。
- ❌ **一趟循环里既数位数又求幂和**。`k` 没数完之前幂次未知，必须两趟；或者转成字符串一次拿长度（`to_string(n).size()`）。
- ⚠️ **溢出分析和约束绑定**。`int` 够用是 `n <= 10⁸` 推出来的结论，不是通用结论；换约束先重算 `9ᵏ × k` 的上界。
