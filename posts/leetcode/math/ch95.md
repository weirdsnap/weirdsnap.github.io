# 区间内的逗号计数（3870. Count Commas in Range）

## 题意

把 `[1, n]` 的每个整数按标准千分位格式写出来（从右往左每三位一个逗号，不足四位的数没有逗号），问一共用了多少个逗号。

```
输入: n = 1002
输出: 3
解释: "1,000" "1,001" "1,002" 各含 1 个逗号

输入: n = 998
输出: 0
```

约束：`1 <= n <= 10⁵`。

---

## 思路一：看清约束，一行出答案

一个 `d` 位数的逗号数是 `(d-1)/3`。约束里 `n <= 10⁵`，最多 6 位数，而 6 位数的逗号数 `(6-1)/3 = 1`。所以只要超过 3 位就恰好 1 个逗号，答案就是"四位及以上的数有几个"：`max(0, n - 999)`。

## 解法一：脑筋急转弯版

```cpp
class Solution {
public:
    int countCommas(int n) {
        return max(0, n - 999);
    }
};
```

## 解法二：按位数分段的通用公式

如果约束放到 `10¹⁸`，一行版就失效了（7 位数以上逗号数不再恒为 1）。通用做法按**位数分段**：`d` 位数有 `9 × 10^(d-1)` 个，每个贡献 `(d-1)/3` 个逗号；最后一段是不完整的 `d` 位段，共 `n - 10^(d-1) + 1` 个数。

```cpp
class Solution {
public:
    int countCommas(int n) {
        int temp = n;
        int d = 0;
        while (temp > 0) {
            temp = temp / 10;
            d++;
        }
        int cnt = 0;
        long long p = 10; // 当前段起始值 10^(i-1)
        for (int i = 2; i < d; i++) {
            temp = (i - 1) / 3;
            // 用整数 p 替代 pow(10, i-1)，避免浮点误差
            cnt += (int)(9 * p * temp);
            p *= 10; // 累乘得到下一段起点
        }
        int rem = 0;
        if (d > 3) {
            temp = (d - 1) / 3;
            // p 此时恰好为 10^(d-1)，即 d 位段的起点
            rem = (int)((n - p + 1) * temp);
        }
        return cnt + rem;
    }
};
```

---

## 核心理解

### 1. 这题的难度是约束给的

`n <= 10⁵` 把逗号数锁死在 0 和 1，题目退化成一个观察题。周赛 Q1 的常见设计：公式能写，但看清约束的人可以 30 秒交卷。拿到题先算一遍"约束下答案能取哪些值"，值得成为肌肉记忆。

### 2. 位数分段是数位统计的通用手法

"按位数分段，完整段用公式、末段单独算"是这一类题的固定结构：完整 `d` 位段有 `9 × 10^(d-1)` 个数（首位 1-9，其余位 0-9），末段从 `10^(d-1)` 到 `n` 共 `n - 10^(d-1) + 1` 个。数字 1 的个数（233）、各位不同的数字（357）这些数位统计题都是同一个骨架，只是每段的贡献函数不同。

### 3. `pow(10, k)` 的浮点坑

`pow` 返回浮点，`pow(10, 5)` 在某些平台会得到 `99999.999...`，强转 int 变 99999。数位题里一律用整数累乘（这里的 `p *= 10`），或者干脆预计算 10 的幂表。

---

## 踩坑点 / 注意点

- ❌ **完整段计数忘了 ×9**。`d` 位数是 `9 × 10^(d-1)` 个，不是 `10^(d-1)` 个（首位不能为 0）。
- ❌ **末段个数写成 `9p`**。最后一段不完整，个数是 `n - p + 1`，套完整段公式会多算。
- ❌ **`pow(10, i-1)` 直接转 int**。浮点误差在 `10⁵` 这种边界上真实存在，用整数累乘替代。
- ⚠️ **一行版只对当前约束成立**。`max(0, n-999)` 依赖"逗号数 ≤ 1"，约束放宽就要换回分段公式，面试时说明这一点比直接给公式更稳。
