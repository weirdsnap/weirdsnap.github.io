> **标签**：贪心、排序、哈希表
# 按键次数最少的打字方案 I & II（3014 / 3016. Minimum Number of Pushes to Type Word）

## 题意

老式手机键盘：数字键 2~9 共 **8 个键**，每个键可以映射若干个字母。按键上的字母按顺序排列，敲第 1 层的字母按 1 次，第 2 层按 2 次，依此类推。

给定字符串 `word`，设计一种字母到按键的映射，使得打出 `word` 的**总按键次数最少**，返回这个最小次数。

两题题面完全一样，差别只在约束：

| | I（3014） | II（3016） |
|--|-----------|------------|
| `word` 中的字母 | **各不相同** | 可以重复 |
| `word.length` | ≤ 26 | ≤ 10⁵ |

### I 的样例

```
输入: word = "abcde"
输出: 5
解释: 5 个字母各占一个键的第 1 层，总次数 = 5×1 = 5 。

输入: word = "xycdefghij"
输出: 12
解释: 10 个不同字母，前 8 个放第 1 层（×1），剩 2 个放第 2 层（×2）。
     总次数 = 8×1 + 2×2 = 12 。
```

### II 的样例

```
输入: word = "xyzxyzxyzxyz"
输出: 12
解释: x、y、z 各占一个键的第 1 层，总次数 = 4×(1+1+1) = 12 。

输入: word = "aabbccddeeffgghhiiiiii"
输出: 24
解释: a~h 各出现 2 次，i 出现 6 次，共 9 种字母。
     前 8 种放第 1 层（×1），频率最低的一种放第 2 层（×2）。
     总次数 = (22 - 2) × 1 + 2 × 2 = 24 。
```

---

## 思路

### 关键观察

1. 只有 **8 个键 × 层数** 个"槽位"，槽位的代价是 `1, 1, ..., 1, 2, 2, ..., 2, 3, ...`（每层 8 个）。
2. **频率高的字母必须配代价小的槽位**——交换论证：若低频字母占了 ×1 槽、高频字母占了 ×2 槽，交换它们总代价一定变小（或不差）。
3. 所以按频率**降序排序**，前 8 个 ×1、接下来 8 个 ×2、依此类推，`i / 8 + 1` 就是第 `i` 个字母的代价。
4. **I 题是特例**：字母各不相同，频率全是 1，排不排序都一样——前 8 个字母 ×1、后面每 8 个加一层，**逢 8 进 1** 直接算，连频率统计都不需要。

---

## 解法一：I 的特判版——逢 8 进 1

字母互不相同，第 `i` 个字母的代价就是 `i / 8 + 1`：

```cpp
class Solution {
public:
    int minimumPushes(string word) {
        int result = 0;
        for (int i = 0; i < word.size(); i++) {
            result += i / 8 + 1;  // 前 8 个 ×1，接着 8 个 ×2，依此类推
        }
        return result;
    }
};
```

不统计频率、不排序，O(n) 一趟走完。这就是 I 题"各不相同"约束的全部意义。

---

## 解法二：频率降序贪心（II 的通用做法）

```cpp
class Solution {
public:
    int minimumPushes(string word) {
        // 用数组替代 unordered_map，直接索引 26 个字母，省去哈希开销
        int cnt[26] = {0};
        for (const auto& c: word) {
            cnt[c - 'a']++;
        }
        // 直接对频率数组降序排序，无需 pair<char,int>
        sort(begin(cnt), end(cnt), greater<int>());
        int result = 0;
        for (int i = 0; i < 26; ++i) {
            if (cnt[i] == 0) break;       // 后续全是 0，提前结束
            result += cnt[i] * (i / 8 + 1); // 前8个 ×1，接着8个 ×2，依此类推
        }
        return result;
    }
};
```

**注意**：直接对频率数组排序（不需要 `pair<char,int>` 保留字母身份）——因为答案只和**频率的多重集**有关，和具体是哪个字母无关。`cnt[i] == 0` 时 `break`，未出现的字母不占槽位。

这个做法对 I 当然也正确（频率全 1 时排序无效果），但属于杀鸡用牛刀——I 用解法一就够。

---

## 关键细节

### 1. 为什么贪心成立（交换论证）

设字母 A 频率 `f1`、字母 B 频率 `f2`，`f1 > f2`。若 A 放在代价 `c2` 槽、B 放在代价 `c1` 槽（`c1 < c2`），交换前后的差：

```
交换前: f1·c2 + f2·c1
交换后: f1·c1 + f2·c2
差值:   f1(c2-c1) - f2(c2-c1) = (f1-f2)(c2-c1) > 0
```

交换后严格更小，所以最优解一定是"频率降序 = 代价升序"。对 I 题这个论证退化为显然——频率全相等，谁占哪个同层槽位都一样。

### 2. 为什么可以丢掉字母身份

映射关系本身不要求输出，只要求最小次数。两个频率相同的字母谁占哪个同层槽位，代价完全一样，所以排序只需对频率值排序。

### 3. 看清题号约束再动手

这题最容易踩的坑不在算法，在**读题**：I 和 II 题面一字不差，但 I 保证字母各不相同，于是频率统计和排序全是多余动作。反过来，把 I 的"逢 8 进 1"搬到 II 就错了——II 有重复字母，频率决定槽位分配，必须排序。

## 复杂度

| | 解法一（I 特判） | 解法二（II 通用） |
|--|------------------|-------------------|
| 时间 | O(n) | O(n + 26 log 26) = O(n) |
| 空间 | O(1) | O(26) |

---

## 踩坑点 / 注意点

- ❌ **没注意到 I 的"字母各不相同"**。题面和 II 一样，但约束决定了简单做法的存在。
- ❌ **按字母顺序而不是频率排序**（II）。键盘映射和字母顺序无关，只看频率。
- ❌ **层数算错**。`i / 8 + 1`（0-indexed 除 8 加 1），不是 `i / 9`——是 8 个键（2~9），不是 9 个。
- ❌ **未出现的字母也占槽**（II）。频率 0 的字母要跳过（`break`），否则白占低成本槽位。
