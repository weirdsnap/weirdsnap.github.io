# 求和游戏（1927. Sum Game）

## 题意

偶数长度字符串 `num`，由数字和 `?` 组成。Alice 和 Bob 轮流把一个 `?` 换成 `0~9` 的数字，Alice 先手。填完后若**左半和 == 右半和**则 Bob 赢，否则 Alice 赢。双方都最优，问 Alice 是否必胜。

```
输入: num = "5023"     输出: false   （没有 '?'，5+0 == 2+3，Bob 直接赢）
输入: num = "25??"     输出: true
输入: num = "?3295???" 输出: false
```

约束：长度 `2 <= n <= 10⁵`，`n` 为偶数。

---

## 思路：一个公式

```
diff     = 左半已知数字和 − 右半已知数字和
diff_cnt = 右半 '?' 数 − 左半 '?' 数

Alice 必胜  ⟺  diff != diff_cnt * 4.5
```

```cpp
class Solution {
public:
    bool sumGame(string num) {
        int left = 0, right = 0, left_cnt = 0, right_cnt = 0;
        int half = num.size() / 2;
        for (int i = 0; i < (int)num.size(); i++) {
            if (i < half) {
                if (num[i] != '?') left += num[i] - '0';
                else               left_cnt++;
            } else {
                if (num[i] != '?') right += num[i] - '0';
                else               right_cnt++;
            }
        }
        return (left - right) != (right_cnt - left_cnt) * 4.5;
    }
};
```

**特点**：一趟扫描出四个计数，公式判断，O(n) 完事。`4.5 = 9/2` 在二进制浮点下精确，但整数写法 `2*(left-right) != 9*(right_cnt-left_cnt)` 更干净，连类型转换都不用想。

---

## 核心理解：4.5 从哪来

### 差值视角

盯住 `d = 左半和 − 右半和`。填左边的 `?` 为 `x`，`d += x`；填右边的 `?` 为 `x`，`d −= x`。**Bob 的目标是终局 `d = 0`，Alice 的目标是 `d ≠ 0`。**

### Bob 的镜像策略：每一对贡献 9

只要某侧还剩两个以上未填的 `?`，Bob 就能**同侧镜像**：Alice 在这侧填 `x`，Bob 就在同侧填 `9 − x`。这一对操作对 `d` 的贡献恒为 `±9`（左侧 +9，右侧 −9），**与 Alice 填了什么完全无关**。

于是整个游戏被 Bob 压缩成：

- 左侧每凑出一对 `?` → 固定贡献 `+9`
- 右侧每凑出一对 `?` → 固定贡献 `−9`
- Alice 的单手选择被镜像中和，改变不了大局

### 奇偶收尾

- `?` 总数为奇：Alice 填最后一个。此时 `d` 离 0 差某个值，她有 10 个数字可选，最多一个数字会把 `d` 打成 0，**总能躲开** → Alice 必胜。公式自动覆盖这种情况：总数奇 ⟺ `diff_cnt` 奇 ⟺ `diff_cnt * 4.5` 是半整数，不可能等于整数 `diff`。
- 总数为偶且两侧各为偶数 `lc = 2p, rc = 2q`：全部配成对，终局 `d = diff + 9p − 9q = diff − 4.5·diff_cnt`。Bob 赢 ⟺ 这个值为 0。
- 总数为偶但两侧各为奇数：每侧各剩一个未配对，最后两手 Alice 先填一侧、Bob 后填另一侧——Bob 末手精确瞄准 `d = 0` 需要的值是否在 `[0,9]`，化简后落到同一个公式。

三种情形合并，就是 `diff == diff_cnt * 4.5` 时 Bob 胜，否则 Alice 胜。

### 家族里的位置

这是"博弈题先想结构捷径"（[ch57](./blog.html?post=leetcode/dp/interval/ch57.md) 心法）最极端的案例：连 877 的"分组配对"都升级成了"镜像中和"，O(n) 数学秒杀，DP 连出场机会都没有。

## 复杂度

| 指标 | 公式版 | 博弈树暴力 |
|------|--------|-----------|
| 时间 | O(n) | O((10·m)ᵐ) 级，m 为 `?` 数 |
| 空间 | O(1) | O(m) 递归栈 |

验证：随机 400 组（`?` ≤ 4）+ 总长 4 的全量空间（每位 ∈ {0,1,9,?}，256 组）与博弈树全枚举（Alice 存在性 / Bob 全称性递归）对拍一致；官方三个样例命中。1038 条断言全过。

---

## 踩坑点 / 注意点

- ❌ **把"平局归谁"搞反**。两半相等是 **Bob** 赢，Alice 要的是不等。公式方向写反直接全错。
- ❌ **用浮点还要 `==` 比**。本题 `4.5` 精确可表示，侥幸安全；换成 `9` 以外的配对基数（比如每对贡献 7）就会出半精度坑。整数形式 `2*diff != 9*diff_cnt` 是一劳永逸的写法。
- ❌ **镜像方向搞错**：是**同侧**填 `9 − x` 中和贡献，不是对侧。对侧填会把差值推得更远。
- ❌ **忘了 `?` 总数为奇的情形**也想套配对。奇数时 Alice 末手必躲得开，这是公式里"半整数 ≠ 整数"那一段在兜底。
