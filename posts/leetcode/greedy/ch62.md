# 石子游戏 VI（1686. Stone Game VI）

## 题意

`n` 堆石子，第 `i` 堆对 Alice 价值 `aliceValues[i]`，对 Bob 价值 `bobValues[i]`（同一堆对两人价值不同）。Alice 先手轮流拿，拿走就获得**自己眼中**的价值。双方都最优，Alice 赢返回 1，Bob 赢返回 -1，平局返回 0。

```
输入: aliceValues = [1,3], bobValues = [2,1]
输出: 1
解释: a+b 为 [3,4]，Alice 先拿堆 1 得 3，Bob 拿堆 0 得 2 → 3:2 获胜

输入: aliceValues = [2,4,3], bobValues = [1,6,7]
输出: -1
```

约束：`1 <= n <= 10⁵`。

---

## 思路：按 `a[i] + b[i]` 降序，轮流取

```cpp
class Solution {
public:
    int stoneGameVI(vector<int>& aliceValues, vector<int>& bobValues) {
        int n = aliceValues.size();
        vector<int> idx(n);
        for (int i = 0; i < n; i++) idx[i] = i;
        sort(idx.begin(), idx.end(), [&](int x, int y) {
            return aliceValues[x] + bobValues[x] > aliceValues[y] + bobValues[y];
        });
        int a = 0, b = 0;
        for (int i = 0; i < n; i++) {
            if (i % 2 == 0) a += aliceValues[idx[i]];
            else            b += bobValues[idx[i]];
        }
        return a > b ? 1 : (a == b ? 0 : -1);
    }
};
```

**特点**：用索引排序而非 `pair` 数组——不拷价值对，比较器里直接查原数组。`i % 2` 奇偶轮流结算。

---

## 核心理解：为什么是 `a + b`

### 推导：净胜分变形

设 Alice 最终拿到集合 `S`（|S| 由先后手固定），净胜分：

```
net = Σ_{i∈S} a_i − Σ_{i∉S} b_i
    = Σ_{i∈S} a_i − (Σ_all b_i − Σ_{i∈S} b_i)
    = Σ_{i∈S} (a_i + b_i) − Σ_all b_i
```

`Σ_all b_i` 是常数，所以 **Alice 最大化 net ⟺ 让她拿到的堆的 `a+b` 之和最大**；Bob 最小化 net 同理。双方争抢的目标完全一致：`a+b` 大的堆。于是每回合拿剩余堆里 `a+b` 最大的就是最优——贪心成立。

直觉版：拿堆 `i` 的收益是"自己得 `a_i`"**加上**"对手永远拿不到 `b_i`"，一拿两得，总价值 `a_i + b_i`。

### 交换论证（严格性）

设某回合玩家拿了堆 `j`，而场上还剩堆 `i` 且 `a_i + b_i > a_j + b_j`。把这次选择换成拿 `i`：由上面的净胜分式，自己集合的 `a+b` 总和变大（对手集合的相应变小），net 严格变好。所以任何"没拿当前最大 `a+b`"的策略都可改进，贪心最优。

### 家族里的位置

石子游戏 VI 和前五个（ch41/57/58/59/60/61）机制完全不同：没有行结构、没有取堆顺序约束，是纯粹的**抢占博弈**。按心法先想结构捷径——这次捷径真的存在（净胜分变形 + 交换论证），DP 反而多余。

## 踩坑点 / 注意点

- ❌ **只按 `a[i]`（自己的价值）排序**。漏掉了"剥夺对手 `b_i`"这一半收益。经典反例：`a=[1,3], b=[2,1]`，按 `a` 排 Alice 拿堆 1 得 3、Bob 拿堆 0 得 2，赢——这例碰巧对；但 `a=[1,2], b=[100,1]` 时按 `a` 排 Alice 拿堆 1（`a+b=3`）放过堆 0（`a+b=101`）给 Bob，血亏。
- ❌ **排序方向写反**（升序）。等于把大蛋糕拱手让人。
- ❌ **忘记平局分支**。返回 `1 / 0 / -1` 三个值，`a == b` 是真实可达的。
