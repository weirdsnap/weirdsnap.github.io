# 最小整除数位积 I（3345. Smallest Divisible Digit Product I）

## 题意

给定两个整数 `n` 和 `t`，返回**大于等于 n 的最小整数**，使其**各位数字的乘积**能被 `t` 整除。

```
输入: n = 10, t = 2
输出: 10
解释: 数位积 1 * 0 = 0，0 能被任何非零整数整除

输入: n = 15, t = 3
输出: 16
解释: 15 的数位积是 5，16 的数位积 1 * 6 = 6 能被 3 整除
```

约束：`1 <= n <= 100`，`1 <= t <= 10`。

---

## 思路

数据范围极小，直接**从 n 开始枚举**，逐个检查数位积即可。唯一值得讲的是枚举上界。

### 为什么枚举到 n + 10 就够了？

任意 10 个连续整数中必有一个以 0 结尾，而含 0 的数数位积为 0，`0 % t == 0` 对任意 `t >= 1` 成立。所以答案一定存在，且**不超过 n 之后的下一个整十数**。

```cpp
class Solution {
public:
    int smallestNumber(int n, int t) {
        for (int x = n; x < n + 10; x++) {
            if (digitProduct(x) % t == 0) return x;
        }
        return -1;  // 不会执行到这里
    }

private:
    int digitProduct(int x) {
        int p = 1;
        while (x != 0) {
            p *= x % 10;
            x /= 10;
        }
        return p;
    }
};
```

本地用 `n ∈ [1,200] × t ∈ [1,10]` 全量验证过：`答案 <= (n / 10 + 1) * 10` 恒成立（4006 条断言全过）。

---

## 关键细节

### 1. 数位积的初始值是 1，不是 0

累乘初始值必须是乘法单位元 1。写成 `int p = 0` 会让所有结果都是 0——虽然这题里 0 恰好能被整除反而"蒙对"，但逻辑是错的，换个题就露馅。

### 2. 含 0 的数立即命中

这是本题的"逃生通道"：只要枚举到含 0 的数（如 20、101），数位积归零直接命中。这也是上界 n + 10 成立的原因。

### 3. x = 0 不在枚举范围

`while (x != 0)` 对 `x = 0` 返回初始值 1。但本题 `n >= 1`，枚举从 n 开始，不会遇到 0，无需特判。

|------|--------|

| 空间 | O(1) |

## 踩坑点 / 注意点

- ❌ **把数位积写成数位和**（`i += j % 10`）。我贴的第一版就犯了这个错，对拍立刻暴露：

  ```
  n=10 t=2 : sum版=11  prod版=10   ← 期望 10（1*0=0 可被 2 整除）
  n=15 t=3 : sum版=15  prod版=16   ← 期望 16（1*6=6）
  n=21 t=6 : sum版=24  prod版=23   ← 期望 23（2*3=6）
  ```

  数位和完全错过了"含 0 命中"这条捷径，而且整除性质和乘积毫无关系。
- ❌ **枚举上界写成 n + 100 或死循环**。能 AC 但没必要——想清楚 n + 10 的数学理由，代码才有说服力。
- ❌ **忘记积可能很大溢出**。本题 `n <= 100`，答案 x ≤ n + 9 ≤ 109，最大数位积出现在 x = 99，为 `9*9 = 81`，int 绰绰有余；但 II（3348）里 `n <= 10^18`，积会爆 int，需要换 long long 或换思路。
