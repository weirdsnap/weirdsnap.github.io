# 有效的单词方块（422. Valid Word Square）

## 题意

给定字符串数组 `words`，若**第 k 行与第 k 列读出完全相同的字符串**（`0 <= k < max(行数, 最长行长)`），则为有效的单词方块，返回 `true`。注意 k 的上界是行数和最长行长的**较大者**——某行比行数还长时，超出的列也要参与比较。

```
输入: words = ["abcd","bnrt","crmy","dtye"]
输出: true

输入: words = ["abcd","bnrt","crm","dt"]      # 行可以比 n 短
输出: true

输入: words = ["ball","area","read","lady"]
输出: false    （第 1 行 "area" vs 第 1 列 "alea"）

输入: words = ["abc","b","c"]
输出: true     （第 1 列 "b"、第 2 列 "c"，短行视为补空）

输入: words = ["abcd"]    # 行数 1 但行长 4
输出: false
```

约束：`1 <= words.length <= 500`，行长 `1..500`，只含小写字母。

---

## 思路：n×n 对称比较 + 缺失补哨兵

把"第 i 行 == 第 i 列"翻译成逐格对称：`words[i][j]` 必须等于 `words[j][i]`。短行补空的语义用哨兵处理：**一侧下标越界就取 `'\0'`**，两侧都越界则 `'\0' == '\0'` 自然相等。

唯一漏网的情况是"行长 > n"——这时第 i 行存在第 n 列字符，而对侧根本没有第 n 行，直接判负。

## 解法：对称遍历 + 哨兵比较

```cpp
class Solution {
public:
    bool validWordSquare(vector<string>& words) {
        int n = words.size();
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {
                // 行长超过 n：第 n 列字符没有对称行，必不合法
                if (words[i].size() > n) {
                    return false;
                }
                // 缺失侧用哨兵 '\0'，两侧都缺则相等
                char a = (j < words[i].size()) ? words[i][j] : '\0';
                char b = (i < words[j].size()) ? words[j][i] : '\0';
                if (a != b) {
                    return false;
                }
            }
        }
        return true;
    }
};
```

---

## 核心理解

### 1. 定义里的 `max(行数, 最长行长)` 是题眼

直觉写法只扫 `n × n`，漏掉"某行比行数长"的情形（`["abcd"]` 一行四字符，第 1、2、3 列根本不存在）。补上 `words[i].size() > n` 的提前判负后，剩余情况全部落在 n×n 网格内，对称比较才完整。**读题面定义时盯住每一个"不显然的上界"**。

### 2. 哨兵值的合法性依赖字符集

`'\0'` 能当"缺失"哨兵，是因为题面限定只含小写字母，`'\0'` 绝不会和真实字符撞车。换个"可含任意字符"的题面就得换方案（比如用 `optional<char>` 或单独的存在性标志）。用哨兵前先确认**哨兵不在值域内**。

### 3. 行长检查的位置可以提

`words[i].size() > n` 与 j 无关，写在 j 循环里每行重复判断 n 次。功能没错（n ≤ 500 无感），但提到 i 循环开头意图更清晰：先剪"行长超界"的行，再做对称比较。

---

## 复杂度

| | 时间 | 空间 |
|--|------|------|
| n×n 对称扫描 | O(n²) | O(1) |

验证：对拍一个**严格按题面定义**的 oracle（k 取到 max(行数, 最长行长)，列串由"长度 > k 的行"逐字拼出）。官方样例 + 手工边界（`["abc","b","c"]` 短行合法、`["abcd"]` 行超界判负）+ 穷举 {a,b} 上 1~3 长单词、n ≤ 3 的全部组合（2,954 组）+ 500 组随机，**3,459 条断言全过**。

---

## 踩坑点 / 注意点

- ❌ **k 的上界当成 n**。见核心理解 1——"行比行数长"是唯一逃出 n×n 网格的情形，必须单独处理。
- ❌ **只比较到两侧较短的长度**。`["abc","b","c"]` 这类短行方阵，一侧有字符一侧没有就是不对称；用哨兵把"缺失"也纳入比较才完整。
- ⚠️ **哨兵与值域撞车**。见核心理解 2。
- ⚠️ **行列搞反**：`a = words[i][j]`、`b = words[j][i]`，写成同向遍历就变成"每行和自己比"，永远 true。
