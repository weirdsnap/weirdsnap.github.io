# 最小回文重排 II（3518. Smallest Palindromic Rearrangement II）

## 题意

给定回文字符串 `s` 和整数 `k`，在 `s` 的**所有不同回文重排**中，返回字典序第 `k` 小的；如果不足 `k` 个，返回空字符串。

```
输入: s = "abba", k = 2
输出: "baab"
解释: 回文重排有 "abba" 和 "baab"，第 2 小是 "baab"。

输入: s = "aa", k = 2
输出: ""
解释: 只有 1 种回文重排。

输入: s = "bacab", k = 1
输出: "abcba"
```

---

## 思路

### 关键观察

1. 和 3517 一样，回文由**左半 + 中间字符**唯一决定。不同的回文重排 ⇔ 左半字符串的**不同排列**（多重集排列）。
2. 问题转化为：求多重集 `{half}` 的第 `k` 小排列——经典的**逐位确定**枚举。
3. 确定第 `i` 位时，从小到大尝试每个候选字符 `j`：若 `j` 固定在 `i`，剩余位置的排列数是 `total`；`total < k` 说明目标在更靠后的字符里，跳过（`k -= total`），否则锁定 `j`。

### 多重集排列数

剩余 `rem` 个位置、各字符剩 `cnt[t]` 个时：

```
total = rem! / (cnt[0]! × cnt[1]! × ... × cnt[25]!)
```

**两个工程要点**：

- 分母是**阶乘** `c!`，不是 `c` 本身
- `21!` 就已溢出 `long long`，而 `k ≤ 10⁶`，所以计数时**超过 k 就截断**——反正只和 k 比大小

---

## 代码

```cpp
class Solution {
public:
    string smallestPalindrome(string s, int k) {
        // 取前一半和mid
        string mid = s.size() % 2 == 1 ? s.substr(s.size()/2, 1) : "";
        string half = s.substr(0, s.size() / 2);
        
        vector<int> cnt(26, 0);
        for (const auto& c : half) cnt[c - 'a']++;

        int remaining = half.size();  // 剩余位置数，避免每次重算
        for (int i = 0; i < (int)half.size(); i++) {
            bool flag = false;
            for (int j = 0; j < 26; j++) {
                if (cnt[j] == 0) continue;
                
                cnt[j]--;      // 试把 j 固定在 i
                remaining--;
                
                // 剩余位置的排列数（超过 k 截断防溢出）
                long long total = perms(cnt, remaining, k);
                
                if (total < k) {
                    k -= total;  // 目标在更靠后的字符里
                    cnt[j]++;    // 回溯
                    remaining++;
                } else {
                    half[i] = 'a' + j;  // 锁定 j
                    flag = true;
                    break;
                }
            }
            if (!flag) return "";  // k 超出总排列数
        }

        // 组装半个+mid+半个反转
        return half + mid + string(half.rbegin(), half.rend());
    }

private:
    // remaining! / ∏cnt[t]!：按 C(rem, cnt[t]) 逐步累乘，每步保持整数
    // 结果 > cap 时返回 cap + 1，防阶乘溢出
    long long perms(const vector<int>& cnt, int remaining, long long cap) {
        long long total = 1;
        int rem = remaining;
        for (int t = 0; t < 26; t++) {
            int r = cnt[t];
            for (int d = 1; d <= r; d++) {
                total = total * (rem - r + d) / d;
                if (total > cap) return cap + 1;
            }
            rem -= r;
        }
        return total;
    }
};
```

**注意**：`perms` 不直接算阶乘再相除，而是按组合数 `C(rem, cnt[0]) × C(rem - cnt[0], cnt[1]) × ...` 累乘——每步 `total * (rem - r + d) / d` 都是整数且增长平缓，配合截断不会溢出。

## 关键细节

### 1. 逐位确定的正确性

固定前缀后，剩余位置的排列数只和**剩余多重集**有关，和已固定的前缀无关。所以从小到大枚举当前位、累减跳过的排列数，最终得到的恰好是第 `k` 小排列（`k` 是 1-indexed）。

### 2. 排列数怎么算：从阶乘公式到组合数累乘

直觉写法是"先算 `rem!` 再逐个除 `c!`"，但这条路线有个死穴：**溢出发生在除法开始之前**。`rem` 上千时 `rem!` 是天文数字，`long long` 在 21! 就爆了；而截断后的"假阶乘"再去除 `c!`，结果是错的——只有精确值相除才是排列数。所以想截断，必须换一种**中间结果永远是"部分答案"**的算法。

多重集排列数可以改写成一串组合数的乘积：

```
rem! / (c1! c2! c3!) = C(rem, c1) × C(rem - c1, c2) × C(rem - c1 - c2, c3) × ...
```

直觉：先从 `rem` 个位置选 `c1` 个放字符 1，再从剩下位置选 `c2` 个放字符 2……和阶乘公式是**同一个数的两种算法**。分母的 `c!` 并没有消失，而是拆进了每个组合数里（`C(rem, c) = rem! / (c! · (rem-c)!)`），26 个乘起来分母自动拼成 `∏c!`——**边算边约分**，中间永不出现完整阶乘。

单个 `C(n, r)` 的算法是逐步乘除：

```cpp
for (int d = 1; d <= r; d++) {
    total = total * (n - r + d) / d;
}
```

每步先乘一个因子、立刻除掉一个因子。关键性质：**每一步除法都是整除**——第 `d` 步结束时 `total` 恰好等于 `C(n - r + d, d)`（可归纳证明），组合数天然是整数。以 `C(5, 2)` 为例：

```
d=1: total = 1 × 4 / 1 = 4    (= C(4,1))
d=2: total = 4 × 5 / 2 = 10   (= C(5,2))
```

外层再按每个字符的剩余数量 `c` 逐个处理，`c = 0` 内层不执行（乘 1 跳过），处理完把 `rem` 减掉。

完整走一遍 `rem = 5, cnt = {a:2, b:2, c:1}`：

```
t=a: C(5,2) → d=1: 1×4/1=4;   d=2: 4×5/2=10    rem 变 3
t=b: C(3,2) → d=1: 10×2/1=20; d=2: 20×3/2=30   rem 变 1
t=c: C(1,1) → d=1: 30×1/1=30
返回 30 ✓（= 5!/(2!2!1!)）
```

### 3. 为什么截断是安全的

`total` 只用于和 `k` 比较（`total < k` 则跳过）。一旦 `total > k`，精确值不再影响任何分支决策，返回 `cap + 1` 等价。这是**语义安全**。

截断插在每步乘除之后：截断前 `total ≤ cap`，再乘一个最大为 `rem`（≤ 2500）的因子，峰值约 `10⁶ × 2500 = 2.5 × 10⁹`，离 `long long` 上限很远，**瞬时溢出也没有**。这是**数值安全**。

### 4. 调试实录（WA 排查点）

初版代码有两个 bug，恰好都在排列数计算里：

- ❌ **分母除的是 `c` 而不是 `c!`**：`total /= c` 只除了计数一次，多重集排列数的分母是每个 `cnt[t]` 的阶乘
- ❌ **没有截断**：`total *= cur_num` 连乘阶乘，`half` 稍长就溢出 `long long`。有符号整数溢出在 C++ 里是**未定义行为**——优化器可基于"无溢出"假设做任何变换，后果远不止"得到一个错乱的比较结果"

---

## 踩坑点 / 注意点

- ❌ **多重集排列数公式写错**：`rem! / ∏cnt[t]!`，阶乘一个都不能少。
- ❌ **阶乘直接连乘**：必须换组合数累乘或中途约分，并加截断。
- ❌ **试完没回溯**：`total < k` 跳过时要 `cnt[j]++` 恢复计数（以及维护的 `remaining`）。
- ❌ **k 越界没处理**：所有字符都跳完还没锁定（`!flag`），说明排列总数 < k，返回 `""`。
- ✅ `substr(pos, len)` 第二参数是长度不是结束下标，取左半用 `s.substr(0, s.size() / 2)`。
