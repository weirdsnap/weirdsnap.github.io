# 回文排列（266. Palindrome Permutation）

## 题意

给定只含小写字母的字符串 `s`，判断它**能否重排成回文串**。

```
输入: s = "code"
输出: false

输入: s = "aab"
输出: true   （重排为 "aba"）

输入: s = "carerac"
输出: true
```

约束：`1 <= s.length <= 5000`。

---

## 思路：奇数频次的字符至多一个

回文串关于中心对称，字符必然**成对出现**；唯一例外是正中心的位置，可以落一个落单的字符。所以：

- 偶数长度：所有字符频次都是偶数；
- 奇数长度：恰好一个字符频次为奇数（坐中心）。

合起来就是充要条件：**频次为奇数的字符 ≤ 1 个**。数一遍计数即可。

## 解法：计数 + 扫描 26 个槽位

```cpp
class Solution {
public:
    bool canPermutePalindrome(string s) {
        vector<int> cnt(26, 0);
        for (const auto& c : s) {
            cnt[c - 'a']++;
        }
        bool odd = false;
        for (const auto& c : cnt) {
            // 出现奇数次的字符至多只能有一个
            if (c & 1) {
                if (!odd) {
                    odd = true;
                } else {
                    return false;
                }
            }
        }
        return true;
    }
};
```

---

## 核心理解

### 1. 充要条件要双向都想一遍

必要性（回文 ⇒ 奇数频次 ≤ 1）由对称性显然；**充分性**（奇数频次 ≤ 1 ⇒ 能排成回文）需要构造保证：把每个字符分一半到左半段，右半段反转照抄，奇数次的那个放中心——这就是 3517/3734 里实际造回文的套路。只想必要性会漏掉"条件是否足够"这一半，对充要条件类结论，养成"反方向用构造法确认"的习惯。

### 2. 只判断不构造，计数就够了

这题和 3517（要输出最小字典序回文）是同一枚硬币的两面：那边必须真的把字符减半、挑中心、拼串，这边只问"能不能"，于是`cnt` 扫一遍出答案，O(n + 26)。**看清题目要"判断"还是"构造"，决定做到哪一步**。

### 3. 早退的写法

扫描计数数组时第二个奇数频次一出现就可以 `return false`，不用再往后看。用布尔标记 + 早退比"数完再判断 odds <= 1"省一个计数变量，意图也更直接。

---

## 复杂度

| | 时间 | 空间 |
|--|------|------|
| 计数扫描 | O(n + 26) = O(n) | O(26) = O(1) |

验证：穷举 {a,b,c} 上全部长度 ≤ 8 的字符串（9,840 个）与**暴力枚举全部排列查回文**对拍；再加 500 组随机长串做**构造性验证**——答案为 true 时按计数实际拼出一个回文排列，断言它既是 `s` 的排列又是回文。共 10,391 条断言全过。

---

## 踩坑点 / 注意点

- ❌ **只统计了奇数个数，没想清楚"≤1"还是"==1"**。奇数长度允许一个、偶数长度不允许，合起来是 ≤ 1；写成"必须恰好一个"会把偶数长度的合法串（如 "aabb"）误判为 false。
- ⚠️ **暴力对拍时空串下溢**：`j = s.size() - 1` 在空串上得到 `SIZE_MAX`，循环条件瞬间成立、越界访问。这是测试侧的坑（题目约束 len ≥ 1），但写双指针回文检查时养成 `i < j` 之前先确认非空的习惯没坏处。
