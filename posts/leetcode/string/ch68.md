# 最短且字典序最小的美丽字符串（2904. Shortest and Lexicographically Smallest Beautiful String）

## 题意

二进制串 `s` 的子串如果恰好包含 `k` 个 `1`，称为**美丽字符串**。返回 `s` 的美丽子串中**长度最短**的；有多个时返回**字典序最小**的。不存在则返回空串。

```
输入: s = "100011001", k = 3
输出: "11001"

输入: s = "1011", k = 2
输出: "11"

输入: s = "000", k = 1
输出: ""
```

约束：`1 <= s.length <= 100`，`1 <= k <= s.length`。

---

## 思路：滑动窗口 + 候选比较

右端 `j` 扩张数 `1` 的个数，凑够 `k` 个就从左端收缩：先剥掉前导 `0`（它们只会让窗口变长），得到一个候选窗口，再按（长度，字典序）维护最优。

## 解法一：滑窗收集候选（提交版）

```cpp
class Solution {
public:
    string shortestBeautifulSubstring(string s, int k) {
        const int n = s.size();
        int i = 0, j = 0;
        int cnt = 0;
        map<int, vector<string>> result;   // 按窗口长度收集候选
        int min_len = n;
        while (j < n) {
            if (s[j] == '1') cnt++;
            while (cnt >= k) {
                if (cnt == k && s[i] == '0') {   // 剥前导 0
                    i++;
                    continue;
                }
                if (cnt == k) {
                    result[j - i + 1].push_back(s.substr(i, j - i + 1));
                    min_len = min(min_len, j - i + 1);
                }
                if (s[i] == '1') cnt--;
                i++;
                if (cnt < k) break;
            }
            j++;
        }
        sort(result[min_len].begin(), result[min_len].end());
        return result[min_len].empty() ? "" : result[min_len][0];
    }
};
```

**注意**：`result[min_len]` 在无解时由 `map` 的 `operator[]` 默认构造出空 vector，正好落到 `""` 分支——行为正确，但依赖"map 查不存在的键会插入默认值"这一副作用，写法偏巧。

## 解法二：1 的位置枚举（更直白）

```cpp
class Solution {
public:
    string shortestBeautifulSubstring(string s, int k) {
        vector<int> ones;
        for (int i = 0; i < s.size(); i++)
            if (s[i] == '1') ones.push_back(i);
        if (ones.size() < k) return "";
        string best;
        for (int t = 0; t + k - 1 < ones.size(); t++) {
            string cand = s.substr(ones[t], ones[t + k - 1] - ones[t] + 1);
            if (best.empty() || cand.size() < best.size() ||
                (cand.size() == best.size() && cand < best)) {
                best = cand;
            }
        }
        return best;
    }
};
```

---

## 核心理解

### 1. 最短窗口必然以 `1` 开头、以 `1` 结尾

端点是 `0` 就可以剥掉，窗口更短且 `1` 的个数不变。所以最短候选只有 `[ones[t], ones[t+k-1]]` 这些"恰好包住 k 个连续 1"的窗口——解法二直接枚举它们，正确性一目了然。

### 2. 字典序 tie-break 为什么不用管前导 0

`'0' < '1'`，等长时带前导 `0` 的串字典序更小——但带前导 `0` 意味着窗口能剥短，**长度关就输了**，根本进不了字典序比较。所以最优窗口不含前导 `0`，两级比较的顺序（先长度后字典序）不能换。

### 3. 解法一里的不变量：`cnt` 永远不会超过 k

内层循环退出时 `cnt == k - 1`，外层每轮 `j` 最多让 `cnt` 加 1，所以 `cnt >= k` 实际等价于 `cnt == k`——代码里 `> k` 的分支是死代码。想清楚这个不变量，内层写成 `while (cnt == k)` 更诚实。

## 复杂度

| | 解法一 | 解法二 |
|--|--------|--------|
| 时间 | O(n²)（substr 拷贝主导） | O(n²) 同左，但候选更少 |
| 空间 | O(n²)（存所有候选） | O(1) 额外（只存最优） |

约束 n ≤ 100，两版都是秒过；解法二的价值在结构清晰，不在性能。

验证：穷举全部长度 ≤ 12 的二进制串 × 所有 k（含 k > 1 总数的无解分支）+ 300 组随机长串，解法一与解法二逐一对拍。98,607 条断言全过。

---

## 踩坑点 / 注意点

- ❌ **收缩判据写成 `cnt > k`**。凑够 k 个就该触发收缩，写成 `>` 会漏掉恰好 k 的窗口（提交前的真实改动：`>` 改 `>=`）。
- ❌ **忘记剥前导 0**。窗口以 `0` 开头不是最短形态，会带着多余长度进候选。
- ❌ **无解分支漏判**。`1` 的总数不足 k 时返回 `""`；解法一靠 map 空 vector 兜底，解法二显式 `ones.size() < k` 提前返回。
- ❌ **先比字典序再比长度**。两级比较顺序固定是（长度，字典序），换序即错。
