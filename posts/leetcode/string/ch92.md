# 恰好 K 对相等相邻的旋转计数（4043. Count Rotations With Exactly K Equal Adjacent Pairs）

## 题意

给定长度 `n` 的字符串 `s` 和整数 `k`。`s` 的一个**循环旋转**是把某个前缀（长度 0 到 n-1）原序搬到末尾。对每个旋转，定义它的**得分**为下标 `0 <= i < n-1` 中 `s[i] == s[i+1]` 的个数。问有多少个旋转的得分恰好等于 `k`。

```
输入: s = "aab", k = 1
输出: 2
解释: 三个旋转 "aab"(1对) "aba"(0对) "baa"(1对)，两个得分为 1

输入: s = "abca", k = 0
输出: 1
```

约束：`2 <= n <= 100`，仅小写字母，`0 <= k <= n - 1`。

---

## 思路：旋转就是环上切一刀

把 `s` 首尾相接看成一个环，环上有 `n` 对循环相邻（包括 `s[n-1]` 和 `s[0]` 这对）。一个旋转等价于在环上选一个**切开点**：切开之后拉成线性串，线性串的 `n-1` 对相邻就是环上的 `n` 对里去掉被切开的那一对。

设环上相等的循环相邻对有 `cnt` 个。那么每个旋转的得分只有两种可能：

- 切开点是**不相等**的对：这对本来就不得分，切掉不影响，得分 = `cnt`；
- 切开点是**相等**的对：这对被拆掉，得分 = `cnt - 1`。

所以答案根本不需要逐旋转计算，看 `k` 落在哪一档：`k == cnt` 时有 `n - cnt` 个切法（不相等对的位置数），`k == cnt - 1` 时有 `cnt` 个切法，其余为 0。

## 解法：一次扫描 + 三分支

```cpp
class Solution {
public:
    int countRotations(string s, int k) {
        const int n = s.size();

        // 统计原字符串中「循环相邻相等」的对数（把首尾也视作相邻）
        // 先判断首尾这对（s[n-1] 和 s[0]）是否相等
        int cnt = s[0] == s[n - 1] ? 1 : 0;

        // 再依次统计中间相邻的每一对是否相等
        char last = s[0];
        for (int i = 1; i < n; i++) {
            if (last == s[i]) {
                cnt++;
            }
            last = s[i];
        }

        // cnt 即某个基准旋转的相等相邻对数量。
        // 每次循环移位，相等相邻对的数量变化量是固定的：
        // 要么是 cnt（不作「切开」的旋转），要么是 cnt-1（在某处切开导致该对不再相邻）。

        if (k == cnt) {
            // 要求相等对数与基准完全一致：切开点不能落在相等对中间，
            // 共有 n - cnt 个这样的位置
            return n - cnt;
        }
        if (k == cnt - 1) {
            // 要求少一对：切开点必须落在某一相等对中间，共 cnt 个位置
            return cnt;
        }
        return 0;
    }
};
```

---

## 核心理解

### 1. 为什么 score 只取两个值

切一刀最多断开一对相邻，所以得分相对基准 `cnt` 最多减 1；而环上每一对非此即彼（相等或不相等），切到不相等对时一分不减。这是"旋转"这个操作的不变量结构：**n 个旋转的得分分布被 `cnt` 一个数字完全决定**。看出这一点，O(n) 枚举旋转的模拟法就退化成了 O(n) 数对 + O(1) 出答案。

### 2. 和模拟法对照

官方题解（doocs）用的是另一种 O(n)：先算原串得分，然后每次左移一位，得分只在两个位置变化（移走的那对消失、尾部新增一对），O(1) 增量更新，扫 n 个旋转。两种方法复杂度相同，但视角不同：模拟法跟踪"得分怎么变"，本解法直接回答"得分能取哪几个值"。n ≤ 100 时随便选，n 大到 10⁵ 也一样都是 O(n)，差别只在代码长度。

### 3. 两个边界检查

- **全同串**（`"aaaa"`）：`cnt = n`，此时 `k == cnt` 永远无解（切哪都至少剩 n-1 对相等），`k == cnt - 1` 时答案是 `n`。公式自然覆盖，不用特判。
- **首尾对**：环上计数最容易漏的就是 `s[n-1]` 和 `s[0]` 这对，代码里把它单独放在循环外统计，就是防这个。

| 一次扫描 + 三分支 | O(n) | O(1) |

---

## 踩坑点 / 注意点

- ❌ **漏掉首尾循环对**。只数线性相邻对，`cnt` 就少算了"切开后首尾相接"的那对，整个公式的基础就错了。
- ❌ **真的去生成每个旋转串**。O(n²) 的字符拷贝在 n ≤ 100 也能过，但完全没必要；看出"旋转即切开"的结构后连模拟都可以省掉。
- ⚠️ **`k` 的范围约束帮了忙**。题目保证 `0 <= k <= n - 1`，所以 `k == cnt`（即不切相等对）和 `k == cnt - 1` 两个分支已经覆盖全部合法输入，`return 0` 实际只兜非法 k；没有这层约束时三分支才是完整逻辑。
