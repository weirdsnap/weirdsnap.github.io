> **标签**：字符串、哈希表
# 句子相似性（734. Sentence Similarity）

## 题意

两个单词数组表示的句子 `sentence1`、`sentence2`，以及一组**相似词对** `similarPairs`。两个句子相似，当且仅当：长度相等，且每个位置上的单词要么**完全相同**，要么**出现在同一对相似词对**里。注意：相似关系**没有传递性**（a 相似 b、b 相似 c，不代表 a 相似 c）。

```
输入: sentence1 = ["great","acting","skills"], sentence2 = ["fine","drama","talent"],
      similarPairs = [["great","fine"],["drama","acting"],["skills","talent"]]
输出: true

输入: sentence1 = ["great"], sentence2 = ["great"], similarPairs = []
输出: true    （相同单词不需要相似对）

输入: sentence1 = ["great","fine"], sentence2 = ["great"], similarPairs = [["great","fine"]]
输出: false   （长度不同）
```

---

## 思路：词 → 相似词集合，逐位核对

把相似词对建成 `词 → 相似词集合` 的映射（无向关系，**双向插入**），然后逐位比较：相同就跳过；不同就查集合里有没有对方，没有立即判负。

## 解法一：unordered_map + unordered_set

```cpp
class Solution {
public:
    bool areSentencesSimilar(vector<string>& sentence1, vector<string>& sentence2,
                             vector<vector<string>>& similarPairs) {
        if (sentence1.size() != sentence2.size()) return false;
        // unordered_set：查找 O(1) 均摊
        unordered_map<string, unordered_set<string>> similarMap;
        for (const auto &pair: similarPairs) {
            similarMap[pair[0]].insert(pair[1]);
            similarMap[pair[1]].insert(pair[0]);  // 无向：双向都插
        }
        for (int i = 0; i < sentence1.size(); i++) {
            if (sentence1[i] == sentence2[i]) continue;
            if (similarMap[sentence1[i]].count(sentence2[i]) == 0) return false;
        }
        return true;
    }
};
```

## 解法二：unordered_map + set（有序集合）

结构完全一样，只把内层换成 `set<string>`，查找从 O(1) 均摊变成 O(log n) 确定界：

```cpp
unordered_map<string, set<string>> similarMap;   // 其余代码一字不动
```

---

## 核心理解

### 1. 没有传递性，所以禁止"建图求连通"

看到"词与词相似"容易条件反射想并查集或 DFS 连通分量——那是 737（Sentence Similarity II）的模型，**传递闭包是那边题面明确给的性质**。本题直接命中才算数：a~b、b~c 推不出 a~c。所以映射到"每个词的邻居集合"就够了，多做的连通性计算不仅是过度设计，**语义上就是错的**。

### 2. 无向关系的两种等价处理

要么**插入时双向**（`map[a] += b; map[b] += a`），查找时单向查一次；要么插入单向、**查找时两个方向都试**。两版用户代码都用前者，代价是集合大一倍、换来查询端干净。选哪个都行，混用才出事（单向插 + 单向查，方向一错就漏判）。

### 3. 相同词直接放行，不需要相似对兜底

`"great" == "great"` 时即使 pairs 里没有这个词也算合法。先 `continue` 再查集合，顺带把"词不在 map 里"的情况也正确处理了——`similarMap[missing].count(x)` 会得到空集合的 0，行为正确（靠的是 `operator[]` 自动插入空值，见踩坑点）。

### 4. set 还是 unordered_set

n 最多一千级别时两者无感。工程口径：无序需求用 `unordered_set`（O(1) 均摊），需要"最坏情况确定界"或顺带有序遍历才用 `set`。这题纯查找，前者更贴切；两版都验证过，行为完全一致。

## 复杂度

| | 解法一 | 解法二 |
|--|--------|--------|
| 建表 | O(P) 均摊 | O(P log P) |
| 逐位查询 | O(L) 均摊 | O(L log P) |
| 空间 | O(P) | O(P) |

（L = 句子长度，P = 相似词对涉及的不同词数）

验证：两版解法互拍 + 对拍一个**不建任何索引、直接扫描原始 pairs 数组**的暴力 oracle。穷举 {a,b,c} 词表、句长 ≤ 2、3 种无序对的全部 8 种子集 × 全部句对组合，再加 400 组随机（允许重复对、自相似对、1/4 概率长度不同）。**3,111 条断言全过**。

---

## 踩坑点 / 注意点

- ❌ **先查词再判长度**。长度不等可以直接返回 false，别等循环里越界。
- ❌ **把相似当传递关系处理**。见核心理解 1——这是本题最大的语义陷阱，也是它和 737 的唯一区别。
- ⚠️ **`similarMap[sentence1[i]]` 的 `operator[]` 有副作用**：词不在表里时会**插入一个空集合**。功能上无害（`count` 照样返回 0），但查询本身修改了容器——若后续要遍历这个 map 或在意内存，先 `find` 再查更干净。
- ❌ **相似对里出现 `[x, x]` 自对或重复对时假设不存在**。重复 `insert` 幂等、自对也只是集合里多一个自己，两版都天然安全；但若改用"查找时双向试"写法，记得自对 `(x,x)` 会被相同词分支提前拦截，不会走到查询。
