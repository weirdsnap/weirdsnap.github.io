# 回文重排家族：识别信号、四步流水线与题目地图

这不是题解，是"回文重排/排列"类题目的公共流水线：266（判断）、3517（最小）、3518（第 k 小）、3734（大于 target）四道题共用同一副骨架，差异只在最后一步。读法：先看流水线，再按题目地图去看每题的第 4 步换成了什么。

---

## 什么时候想到这套

三个信号同时出现：

1. 题目允许**任意重排**字符（顺序不重要，计数才重要）
2. 目标是**回文**（或回文的某个字典序变体）
3. 字符集小（26 个小写字母）

只要"任意重排 + 回文"出现，问题就几乎必然坍缩成计数问题，与原串顺序无关。

## 四步流水线

```cpp
// 1. 计数：值域 26，定长数组
int cnt[26] = {};
for (char c : s) cnt[c - 'a']++;

// 2. 奇偶总开关：频次为奇数的字符至多一个，否则无可行回文
char mid = 0;
for (int i = 0; i < 26; i++) {
    if (cnt[i] % 2) {
        if (mid) return 不可行;      // 第二个奇数频次 → 判负
        mid = 'a' + i;
    }
    cnt[i] /= 2;                     // 3. 减半：得到"前半段库存"
}

// 4. 只构造前半段 p，再拼出整个回文
string p = solveHalf(cnt /*, 各题自己的参数*/);
return p + (mid ? string(1, mid) : "") + string(p.rbegin(), p.rend());
```

核心不变量：**回文由前半段唯一决定**（右半是左半的反转，中心最多一个字符）。所以"判断/构造回文"的全部难度都退化成"前半段怎么选"，右半永远不用想。

## 各题的第 4 步（可变点）

| 可变点 | 选项 | 注意 |
|--------|------|------|
| 目标 | 可行性判断 / 最小字典序 / 第 k 小 / 大于 target 的最小者 | 决定第 4 步策略，前三步不动 |
| 前半段策略 | 不构造 / 各字符一半升序 / 逐位确定 + 排列数 / 分界点枚举 | 见题目地图 |
| 计数结构 | `int[26]` / `map` | 26 字母用数组；map 的唯一好处是遍历时自然有序，但 `for i in 0..26` 一样有序 |
| 拼装的 mid 处理 | `mid` 可能为空字符 | 偶数长度没有中心，拼接时跳过 |

## 踩坑速查

- ❌ 奇偶开关写成"恰好一个"：偶数长度合法串有**零个**奇数频次字符，判据是 ≤ 1（[ch77](./blog.html?post=leetcode/string/ch77.md) 踩坑点 1）
- ❌ 只验证了必要性没验证充分性：充要条件的充分方向靠"减半 + 中心 + 反转"的构造兜底（[ch77](./blog.html?post=leetcode/string/ch77.md) 核心理解 1）
- ❌ 第 k 小时把多重集排列数的分母写成 `∏cnt` 而不是 `∏cnt!`；以及忘记 `21!` 溢出 `long long`，必须超过 k 就截断（[ch39](./blog.html?post=leetcode/string/ch39.md) 关键细节 2）
- ❌ 3734 里漏掉"前半段等于 target 前半段"的合法性检查，直接跳到"严格大于"分支（[ch72](./blog.html?post=leetcode/string/ch72.md) 核心理解 1）
