# 大于 target 的最小字典序排列（3720. Lexicographically Smallest Permutation Greater Than Target）

## 题意

给定等长字符串 `s` 和 `target`（小写字母）。返回 `s` 的排列中**严格大于** `target` 的、字典序最小者；不存在返回 `""`。

```
输入: s = "abc", target = "bba"
输出: "bca"

输入: s = "leet", target = "code"
输出: "eelt"

输入: s = "baba", target = "bbaa"
输出: ""
```

约束：`1 <= n == s.length == target.length <= 300`。

---

## 思路：从右往左找"能放大的分界位"

答案与 `target` 必然有第一个不同的位置 `i`，且 `ans[i] > target[i]`。要让答案字典序最小：

- `i` **越靠右越好**（公共前缀越长）→ 从右往左枚举
- 位置 `i` 放**比 `target[i]` 大的最小可用字符**
- 右侧剩下的字符**按升序**填，是这个 `i` 下的最小尾巴

第一个可行的 `i` 就是答案。可行需要两个条件同时成立：

1. 前缀 `[0, i-1]` 能照搬 `target`（每种字符库存够）
2. 库存里存在字符 `> target[i]`

## 解法一：双数组增量版

```cpp
class Solution {
public:
    string lexGreaterPermutation(string s, string target) {
        vector<int> cnt(26, 0);
        for (const auto& c : target) cnt[c - 'a']++;   // 先装整个 target
        vector<int> s_cnt(26, 0);
        for (const auto& c : s) s_cnt[c - 'a']++;

        for (int i = s.size() - 1; i >= 0; i--) {
            cnt[target[i] - 'a']--;   // cnt 变为 target[0..i-1] 的计数
            // 库存 = s 的计数 - 前缀用掉的
            bool valid = true;
            vector<int> right(26, 0);
            for (int j = 0; j < 26; j++) {
                right[j] = s_cnt[j] - cnt[j];
                if (right[j] < 0) { valid = false; break; }
            }
            if (!valid) continue;
            // 位置 i 放大于 target[i] 的最小可用字符
            valid = false;
            char mid;
            for (int j = target[i] - 'a' + 1; j < 26; j++) {
                if (right[j] > 0) {
                    valid = true;
                    right[j]--;
                    mid = 'a' + j;
                    break;
                }
            }
            if (!valid) continue;
            // 拼装：照搬前缀 + mid + 右侧升序
            string ans = target.substr(0, i);
            ans += mid;
            for (int j = 0; j < 26; j++) ans.append(right[j], 'a' + j);
            return ans;
        }
        return "";
    }
};
```

## 解法二：单数组差值版

直接维护**库存差** `left[c] = s_cnt[c] − target_cnt[c]`（对当前前缀而言，还剩什么字符可用），一个数组一趟初始化，回退时把 `target[i]` 还回库存：

```cpp
class Solution {
public:
    string lexGreaterPermutation(string s, string target) {
        int n = s.size();
        int left[26] = {};
        for (int i = 0; i < n; i++) {
            left[s[i] - 'a']++;        // s 的字符：加
            left[target[i] - 'a']--;   // target 的字符：减
        }

        for (int i = n - 1; i >= 0; i--) {
            left[target[i] - 'a']++;   // 前缀缩短一位，还回 target[i]

            // 有负数说明前缀 [0..i-1] 照搬不动，继续往左
            bool ok = true;
            for (int c : left) {
                if (c < 0) { ok = false; break; }
            }
            if (!ok) continue;

            for (int j = target[i] - 'a' + 1; j < 26; j++) {
                if (left[j] == 0) continue;
                left[j]--;
                target[i] = 'a' + j;   // target 按值传递，直接当工作区
                target.resize(i + 1);
                for (int k = 0; k < 26; k++) {
                    target += string(left[k], 'a' + k);
                }
                return target;
            }
        }
        return "";
    }
};
```

## 核心理解

### 1. 这是 31. 下一个排列的同族骨架

31 题（数组的下一个排列）：从右找第一个"可以放大"的位置，换成最小的大者，右侧升序。3720 把"数组自身"换成了"target 给定的前缀约束"，多出来的工作只有一件事——**用计数数组判断前缀能否照搬**。骨架完全一致。

### 2. 双数组是直观基准，单数组是空间优化

- **双数组**（解法一）：`s_cnt` 和 `cnt` 各管各的，语义一眼见底——"s 有什么"减去"前缀用掉什么"就是库存。先写这版，不容易错。
- **单数组**（解法二）：观察到两个数组永远只以**差值**的形式被使用，于是合并成一份 `left[c] = s_cnt[c] − target前缀[c]`。计数数组从两份减到一份，回退从"减 cnt 再重算 26 格差"变成一次 `left[target[i]]++`。空间减半（都是 O(26) 的常数级优化），代码反而更短——但"left 可能为负、为负即前缀不可行"这层语义不如双数组直白，建议在双数组想通之后再改写。

还有个更直白的中间形态——每个 i 都复制 `s_cnt` 再逐位扣前缀，O(n²)，n ≤ 300 能过但 n 到 10⁵ 量级就危险，不推荐。

解法二另一个细节：`target` 是**按值传递**的形参，直接 `target[i] = ...; resize; +=` 原地改造成答案，白得一块可写工作区。这个技巧成立的前提是签名按值传；改成 `const string&` 就得自己开副本了。

### 3. 无解的快速判定

无解 ⟺ 连 `s` 的最大排列（降序）都不大于 `target` ⟺ 所有分界位都不可行。循环跑完自然返回 `""`，不需要特判；但可以拿 `sort(s.rbegin(), s.rend()) <= target` 一句话预检（本题没写，属于可读性选择）。

## 复杂度

| | 解法一（双数组） | 解法二（单数组） |
|--|------------------|------------------|
| 时间 | O(n × 26) | O(n × 26)，常数更小 |
| 空间 | O(26) × 2 | O(26) |

验证：穷举 {a,b,c} 上全部长度 ≤ 6 的 (s, target) 配对（597,870 对）× 双数组版与单数组版 + 300 组字母表 26 的随机对（另含复制重算的中间形态版），与 `next_permutation` 暴力枚举参考版逐一对拍。1,794,516 条断言全过。

## 踩坑点 / 注意点

- ❌ **`mid` 从 `target[i]` 开始枚举**。要的是严格大于，起点是 `target[i] + 1`；从 `target[i]` 起会把"等于"混进来，得到 `>=` 的答案。
- ❌ **右侧任意顺序填**。右侧必须升序才是该分界位下的最小尾巴；顺序一乱，字典序就不是最小。
- ❌ **只查"有没有大字符"，不查前缀可行性**。库存不够照搬前缀时这个位置根本走不通，必须 `continue` 往左找。
- ❌ **解法一里 `cnt[target[i]]--` 放错位置**。它必须先减再算——减完之后 `cnt` 才是 `target[0..i-1]` 的计数；放到循环末尾语义全错。解法二的 `left[target[i]]++` 同理，先还回再判断。
- ❌ **解法二里 `left` 检查写成 `> 0`**。可行性的判据是"没有负数"（`>= 0` 全成立），写成检查正数会把恰好用光的合法前缀误判成不可行。
