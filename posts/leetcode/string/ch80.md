# 单行键盘（1165. Single-Row Keyboard）

## 题意

单行键盘上 26 个小写字母以**任意排列**给出（`keyboard` 是 26 字母的一个排列）。手指初始在位置 0，移动代价为位置差的绝对值。求打完 `word` 的总代价。

```
输入: keyboard = "abcdefghijklmnopqrstuvwxyz", word = "cba"
输出: 4        （0→2 两步到 c，2→1 一步到 b，1→0 一步到 a，共 4）

输入: keyboard = "pqrstuvwxyzabcdefghijklmno", word = "leetcode"
输出: 73
```

约束：`keyboard.length == 26`（每字母恰一次），`1 <= word.length <= 10⁴`。

---

## 思路：字符 → 位置的直接定址表

每个字符的位置查一次太贵，先把 `keyboard` 翻成 `key_pos[26]`（字符直接当下标），然后遍历 `word` 累加 `|pos[i] - pos[i-1]|`，起点位置 0。

## 解法：数组定址 + 一趟累加

```cpp
class Solution {
public:
    int calculateTime(string keyboard, string word) {
        int index = 0;
        int count = 0;
        // 用数组替代哈希表：字符集固定 26，直接以字符作索引
        int key_pos[26];
        for (int i = 0; i < 26; i++) {
            key_pos[keyboard[i] - 'a'] = i;
        }
        for (int i = 0; i < word.size(); i++) {
            count += abs(key_pos[word[i] - 'a'] - index);
            index = key_pos[word[i] - 'a'];
        }
        return count;
    }
};
```

## 核心理解

### 1. 小字符集：数组全面优于哈希表

字符集固定 26 个小写字母时，`int key_pos[26]` 直接定址：O(1) 且无哈希计算、无冲突、无堆分配，`cache` 友好到几乎免费。这是"**值域小且已知 → 数组替代 unordered_map**"套路的又一例（1100 的计数数组、266 的 26 槽位同理）。哈希表的用武之地是值域大或稀疏的场合。

### 2. 模拟题的关键是忠实翻译，不是优化

这题没有算法含量：手指从 0 开始，每步代价是 |目标位置 − 当前位置|。唯一的"坑位密度"在翻译准确性——起始位置、`keyboard` 不是字母序、累加的是**相邻按键间**的距离。先写对，再谈快。

### 3. 建表方向别反

`key_pos[keyboard[i] - 'a'] = i` 是"字符 → 位置"。反成 `key_pos[i] = keyboard[i]` 就建成了"位置 → 字符"，查询端完全没法用。键值映射建表时默问自己一句：**查询端拿什么来查？** 拿字符查，字符就是键。

---

## 复杂度

| | 时间 | 空间 |
|--|------|------|
| 建表 + 一趟 | O(26 + L) = O(L) | O(26) = O(1) |

（L = word 长度）

验证：对拍一个**不建表、每次线性扫描 keyboard 找位置**的朴素 oracle。官方 2 样例 + 3 种固定键盘（字母序/逆序/旋转序）× {a,b,c} 上全部长度 ≤ 6 的单词（3,276 组）+ 400 组随机键盘随机单词，**3,678 条断言全过**。

---

## 踩坑点 / 注意点

- ❌ **假设 keyboard 是字母序**。题面明确是任意排列，"c 在位置 2" 这种直觉只在样例 1 成立。
- ❌ **忘记手指初始在位置 0**，第一个字符的代价是 `key_pos[word[0]] - 0`，不是 0。
- ⚠️ **重构后遗留死代码**。提交版里 `unordered_map<int, int> key_map;` 声明了但没再使用——哈希版改数组版时残留的。编译器不报错（最多 `-Wunused-variable` 警告），但 reviewer 会困惑"这表在哪用"。换实现时顺手删干净。
- ❌ **`key_pos` 不初始化就指望默认值**。本题 keyboard 恰好覆盖 26 字母所以安全；换个"字符集不完整"的题，未初始化槽位就是野值，应该 `int key_pos[26] = {-1};` 或 `= {}`。
