# 安排电影院座位（1386. Cinema Seat Allocation）

## 题意

电影院 `n` 排座位，每排 10 个（编号 1~10）。四人家庭只能坐 **[2,5] / [4,7] / [6,9]** 三个块之一。给定已预订座位 `reservedSeats`，求最多能安排多少个四人家庭。

```
输入: n = 3, reservedSeats = [[1,2],[1,3],[1,8],[2,6],[3,1],[3,10]]
输出: 4

输入: n = 2, reservedSeats = [[2,1],[1,8],[2,6]]
输出: 2
```

约束：`1 <= n <= 10⁹`（**排数巨大**，不能逐排遍历），`|reservedSeats| <= 10⁴`。

---

## 思路：每排一个位图，基线 2n 减损失

- 没预订的排一律坐 2 个家庭 → 基线 `2n`
- 有预订的排用哈希表攒一个 **8 位掩码**（座位 1 和 10 不挡任何四人块，直接跳过）
- 逐排算损失几个家庭，从基线里扣

```cpp
class Solution {
public:
    int maxNumberOfFamilies(int n, vector<vector<int>>& reservedSeats) {
        unordered_map<int, unsigned int> cnt;   // 值用 unsigned，喂给 popcount 免强转
        for (const auto& seat : reservedSeats) {
            if (seat[1] == 1 || seat[1] == 10) continue;
            cnt[seat[0]] += 1 << (9 - seat[1]);   // 座位 2→bit7 ... 座位 9→bit0
        }
        int lost = 0;
        for (const auto& [k, v] : cnt) {
            bool left   = std::popcount(0b11110000 & v) > 0;  // 块 [2,5] 有占用
            bool right  = std::popcount(0b00001111 & v) > 0;  // 块 [6,9]
            bool middle = std::popcount(0b00111100 & v) > 0;  // 块 [4,7]
            if (middle) {
                lost += (left && right) ? 2 : 1;
            } else {
                if (left || right) lost += 1;
            }
        }
        return n * 2 - lost;
    }
};
```

**特点**：值类型直接声明 `unsigned int`，配合 `std::popcount` 的类型约束（见 [popcount 篇](./blog.html?post=cpp/ch07/35.md)）不用再 `static_cast`。

---

## 核心理解

### 1. 每排的最大数只有三种结果

- 左块、右块都空 → **2**（左右两块不重叠）
- 三个块全堵 → **0**
- 其余 → **1**（中块空就坐中块，否则左/右谁空坐谁）

### 2. 分支里藏着一个不变量

注意代码的 `if (middle)` 分支没有处理"中堵但左右都空"——因为**这个情形不可达**：中块 [4,7] 的座位 4、5 属于左块，6、7 属于右块，中块被堵必然连带左或右被堵。所以"中堵"时只可能丢 1 个（左或右还有一个空块可坐）或 2 个（全堵）。八种真假组合验证过全部正确。

### 3. `popcount(...) > 0` vs `(mask & v) != 0`

这里用 `popcount` 纯属刚学完 `<bit>` 顺手练手——我们只需要"块内**有没有** 1"，不需要 1 的具体数量，最直接、意图最清晰的写法其实是零比较：

```cpp
bool left   = (0b11110000 & v) != 0;  // 块 [2,5] 有占用
bool right  = (0b00001111 & v) != 0;  // 块 [6,9]
bool middle = (0b00111100 & v) != 0;  // 块 [4,7]
```

一条 `AND` + 一条条件跳转就完事（x86 上融合成单条 `TEST`），还免去 `popcount` 的无符号类型约束。真要**数**"堵了几个座位"时，`popcount` 才是正主——工具按需求选，不是按新鲜感选。

## 复杂度

| 指标 | 值 |
|------|----|
| 时间 | O(m)，m = 预订数（和 n 无关，10⁹ 排也不怕） |
| 空间 | O(有预订的排数) ≤ O(m) |

验证：500 组随机对拍（popcount 版 vs 直接块检查版）+ **单行 256 种掩码全枚举**（盯住每个分支组合）。759 条断言全过。

## 踩坑点 / 注意点

- ❌ **逐排遍历**。`n` 到 10⁹，必须只处理有预订的排（哈希表），其余走基线。
- ❌ **漏掉座位 1 和 10 的 `continue`**。这不是"白造 map 条目"的小事，是实打实的 UB：座位 10 会算出 `1 << (9 - 10)` = `1 << (-1)`，**负数移位是未定义行为**——UBSan 直接报 `runtime error: shift exponent -1 is negative`；本机（x86-64，clang/g++ 均同）实际行为是移位计数被截成 31、结果为 `0x80000000`，恰好不碰任何块掩码，所以"看起来能跑"，但换平台/换优化级别就可能变脸。座位 1 的 `1 << 8 = 256` 合法但多余（bit 8 不属任何块掩码）。两头都该 `continue`。
- ❌ **"中块堵了"就以为只能坐 0 个**。左、右块可能还有一个空着，只丢 1 个家庭，别写成丢 2。
- ❌ **位序写反**。`1 << (9 - seat[1])` 让座位号和 bit 高低位是镜像的，掩码 `0b11110000` 对应座位 2~5；改成 `1 << seat[1]` 之类就要重算所有掩码。
