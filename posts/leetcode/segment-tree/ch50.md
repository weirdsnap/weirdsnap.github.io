# 区域和检索 - 数组可修改（307. Range Sum Query - Mutable）

## 题意

实现 `NumArray` 类，支持两种操作：

- `update(index, val)`：把 `nums[index]` 改成 `val`
- `sumRange(left, right)`：返回 `nums[left..right]` 的和

```
输入: ["NumArray", "sumRange", "update", "sumRange"]
      [[[1,3,5]], [0,2], [1,2], [0,2]]
输出: [null, 9, null, 8]
```

约束：数组长度 `<= 3 * 10⁴`，操作总数 `<= 3 * 10⁴`。朴素做法 update O(1) / sumRange O(n) 会被卡，需要**两个操作都 O(log n)** 的结构——线段树。

---

## 思路：线段树的三个操作

线段树把区间 `[0, n-1]` 递归二分，每个节点存一段区间的和。叶子是单个元素，内部节点 = 左右子之和。三个操作都是递归，核心框架一致：

```
build(pos, i, j):   建 [i,j] 的子树，存到 pos
update(pos, i, j, index, val):  修改叶子 index，回溯时更新路径上的和
query(pos, i, j, l, r):  查 [l,r]，不相交返回 0，全覆盖返回节点和，否则递归两边
```

### 堆式索引：像堆一样存树

节点不存指针，用数组下标模拟完全二叉树：**根在 1，pos 的左右子是 `pos*2` 和 `pos*2+1`**。

```
        [1]
       /   \
     [2]   [3]
    /  \   / \
  [4] [5] [6] [7]
```

为什么从 1 不从 0 开始？从 0 开始的话子节点公式是 `2i+1 / 2i+2`，而 `0*2+1 = 1`、`0*2+2 = 2` 也没问题——但 1 起根的公式 `pos*2` 更简洁，而且 `pos=0` 永远不会被用到，等于天然留了一个"空节点哨兵"。代价是空间要多开：**最坏约 4n**（n 不是 2 的幂时，最后一层大量位置空着）。

### 完整实现

```cpp
class NumArray {
    struct Node { int sum, len; };
    vector<Node> node;
    vector<int> nums;

public:
    NumArray(vector<int>& nums) {
        this->nums = nums;
        node.resize(nums.size() * 4);  // 1 起根，4n 才够
        build(1, 0, nums.size() - 1);  // 根传 1 不是 0
    }

    void build(int pos, int i, int j) {
        if (i == j) { node[pos] = {nums[i], 1}; return; }
        int mid = (i + j) / 2;
        build(pos * 2, i, mid);
        build(pos * 2 + 1, mid + 1, j);
        node[pos] = {node[pos*2].sum + node[pos*2+1].sum,
                     node[pos*2].len + node[pos*2+1].len};
    }

    void update(int index, int val) {
        update_helper(1, 0, nums.size() - 1, index, val);
    }

    void update_helper(int pos, int i, int j, int index, int value) {
        if (i == j) {
            nums[i] = value;
            node[pos].sum = value;
            return;
        }
        int mid = (i + j) / 2;
        if (index <= mid)   // index == mid 归左侧！左区间是 [i, mid]
            update_helper(pos * 2, i, mid, index, value);
        else
            update_helper(pos * 2 + 1, mid + 1, j, index, value);
        node[pos].sum = node[pos*2].sum + node[pos*2+1].sum;  // 回溯更新
    }

    int sumRange(int left, int right) {
        return query(1, 0, nums.size() - 1, left, right);
    }

    int query(int pos, int i, int j, int left, int right) {
        if (left > j || right < i) return 0;               // 不相交
        if (left <= i && right >= j) return node[pos].sum; // 全覆盖
        int mid = (i + j) / 2;
        return query(pos*2, i, mid, left, right)
             + query(pos*2+1, mid+1, j, left, right);      // 部分重叠，拆两边
    }
};
```

---

## 关键细节

### 1. 三个递归入口都要传根 `1`

`build(1, ...)`、`update_helper(1, ...)`、`query(1, ...)`——1 起根的约定下，传 0 会静默建出一棵位置全错的树（0 的"左子"还是 0，直接死递归或数据错乱）。这是最隐蔽的坑：不报错，答案错。

### 2. 区间拆分的两个边界

- **左闭右闭** `[i, mid]` 和 `[mid+1, j]`：mid 本身属于左区间。
- update 的方向判断 `index <= mid` 走左边——等号必须在左侧，因为左区间包含了 mid。写成 `index < mid` 就会把 `index == mid` 错分到右区间，右区间起点是 `mid+1`，永远找不到这个叶子（递归到 `i == j == mid+1` 卡住或写错位置）。

### 3. query 的三分类

| 区间关系 | 动作 |
|----------|------|
| `[i,j]` 与 `[left,right]` 不相交 | 返回 0（加法单位元） |
| `[i,j]` 被完全覆盖 | 返回 `node[pos].sum`，不再深入 |
| 部分重叠 | 递归两边，结果相加 |

"全覆盖就停"是线段树 O(log n) 的来源：每层最多只深入 2 条路径，访问节点数 O(log n)。

### 4. 回溯更新不可少

`update_helper` 递归返回后必须重算 `node[pos].sum`——叶子变了，从叶子到根的整条路径上的和都过期了。这一行忘了，update 之后 query 拿到的是旧值。

## 复杂度

| 操作 | 朴素数组 | 前缀和 | 线段树 |
|------|---------|--------|--------|
| update | O(1) | O(n)（重建前缀和） | **O(log n)** |
| sumRange | O(n) | O(1) | **O(log n)** |
| 空间 | O(n) | O(n) | O(4n) |

前缀和在"只查不改"时最优（ch19/53 的前缀和技巧），一旦混入 update 就废了——这题的本质是**查改混合**，线段树/树状数组的主场。

---

## 踩坑点 / 注意点

- ❌ **1 起根但入口传 0**。静默错误，见关键细节 1。
- ❌ **`index < mid` 走左侧**。`index == mid` 被错分到右区间，见关键细节 2。
- ❌ **数组只开 2n**。1 起根 + n 非 2 的幂时索引会超 2n，**开 4n 是安全的通用上界**。
- ❌ **update 忘记回溯更新内部节点**。路径上的和全部过期。
- ❌ **query 忘记"不相交返回 0"**。0 是加法的单位元，返回别的值会污染结果。

## 延伸

- **树状数组（Fenwick）**：同样 O(log n) 查改，代码只有线段树 1/3 长，但只支持"前缀和可减"的查询（`sumRange(l,r) = prefix(r) - prefix(l-1)`）。线段树通用性更强（区间最值、区间修改、懒惰标记）。
