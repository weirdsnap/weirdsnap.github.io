# 由单个字符重复的最长子字符串（2213. Longest Substring of One Repeating Character）

## 题意

给定字符串 `s`，依次执行 `k` 次修改：第 `i` 次把 `s[queryIndices[i]]` 改成 `queryCharacters[i]`。**每次修改后**，返回整个字符串中最长连续相同字符子串的长度。

```
输入: s = "babacc", queryCharacters = "bcb", queryIndices = [1,3,3]
输出: [3,3,4]
解释: 
  改 s[1]='b': "bbbacc" → 最长连续段 "bbb"，长度 3
  改 s[3]='c': "bbbccc" → 3
  改 s[3]='b': "bbbcbc"... 实际 "bbbbc c"→ "bbbbc" 长度 4
```

约束：`s` 长度和修改次数都到 `10⁵`，每次修改后全串扫描的 O(n·k) 暴力会被卡。

---

## 思路：只读根节点的线段树

307 题（ch50）的线段树是**查子区间**：`query(l, r)` 沿树下潜，只访问覆盖 `[l,r]` 的 O(log n) 个节点。这题是另一种形态——**每次修改后只要全局答案**，根本不需要 query 函数，读完根节点的 `best` 就完事。

难点全在 **merge 怎么设计**：两个子区间的"最长连续段"合起来，不是简单取 max，因为答案可能**横跨拼接缝**。

### Node 设计：五个字段

```
┌──────────── 区间 [l, r] ────────────┐
│ preChar sufChar  最左/最右字符       │
│ preLen           前缀连续段长度      │
│ sufLen           后缀连续段长度      │
│ best             区间内最长连续段    │
│ len              区间长度            │
└─────────────────────────────────────┘
```

`preLen`/`sufLen` 是为了算"横跨拼接缝"的候选：`L 的后缀段 + R 的前缀段`（当 `L.sufChar == R.preChar` 时）。

### merge 的两种情况

```cpp
auto merge = [](const Node& L, const Node& R) -> Node {
    Node res;
    res.preChar = L.preChar;
    res.sufChar = R.sufChar;
    res.len = L.len + R.len;

    if (L.sufChar == R.preChar) {
        int cross = L.sufLen + R.preLen;
        res.best = max(max(L.best, R.best), cross);
        // 前缀延续：仅当 L 整个区间都是同一字符时，前缀段才能延伸进 R
        res.preLen = (L.preLen == L.len) ? L.preLen + R.preLen : L.preLen;
        res.sufLen = (R.sufLen == R.len) ? L.sufLen + R.sufLen : R.sufLen;
    } else {
        res.best = max(L.best, R.best);
        res.preLen = L.preLen;
        res.sufLen = R.sufLen;
    }
    return res;
};
```

### 完整实现（deducing this 递归 lambda）

```cpp
class Solution {
public:
    vector<int> longestRepeating(string s, string queryCharacters,
                                 vector<int>& queryIndices) {
        int n = s.size();
        vector<Node> tree(4 * n);

        // merge 同上，略

        auto build = [&](this auto&& self, int node, int l, int r) -> void {
            if (l == r) {
                tree[node] = {s[l], s[l], 1, 1, 1, 1};
                return;
            }
            int mid = (l + r) / 2;
            self(node * 2, l, mid);
            self(node * 2 + 1, mid + 1, r);
            tree[node] = merge(tree[node * 2], tree[node * 2 + 1]);
        };

        auto update = [&](this auto&& self, int node, int l, int r,
                          int pos, char c) -> void {
            if (l == r) {
                tree[node] = {c, c, 1, 1, 1, 1};
                return;
            }
            int mid = (l + r) / 2;
            if (pos <= mid) self(node * 2, l, mid, pos, c);
            else            self(node * 2 + 1, mid + 1, r, pos, c);
            tree[node] = merge(tree[node * 2], tree[node * 2 + 1]);
        };

        build(1, 0, n - 1);

        vector<int> res;
        for (int i = 0; i < queryIndices.size(); i++) {
            update(1, 0, n - 1, queryIndices[i], queryCharacters[i]);
            res.push_back(tree[1].best);  // 答案永远在根上
        }
        return res;
    }
};
```

## 关键细节

### 1. merge 里最容易错的两行

`preLen` 的延续条件 `L.preLen == L.len`：只有 **L 整个区间全是同一字符**时，合并后的前缀段才能延伸进 R 的前缀段。否则合并后的前缀段就是 L 自己的前缀段，原样继承。

直观例子：`L = "aaab"`（preLen=3, len=4），`R = "aaa"`。合并后 `"aaabaaa"` 的前缀段还是 3（被 `b` 挡住），不能因为两边都是 `a` 开头就加成 6。

`sufLen` 同理对称。

### 2. "整体 best 型" vs "子区间查询型"

| | 307（ch50） | 2213（本题） |
|--|------------|-------------|
| 关注点 | 任意子区间 `[l, r]` 的和 | 全局最长连续段 |
| query 函数 | 需要，沿树下潜 | **不需要**，读 `tree[1].best` |
| Node 内容 | 一个 `sum` 就够 | 需要前缀/后缀信息支撑 merge |
| merge 复杂度 | `L.sum + R.sum` | 要处理拼接缝 |

判断依据：**答案能不能从两个子区间的答案"合并"出来**。区间和天然可合并（`sum = L + R`）；最长连续段不行（横跨拼接缝的候选），所以要给 Node 加前缀/后缀字段。设计线段树 Node 的通用思路：先写 merge，发现信息不够就往 Node 里加字段。

### 3. 递归 lambda 用 `this auto&& self`

`build`/`update` 是递归 lambda，用 C++23 的 deducing this（`this auto&& self`）把自身作为显式对象参数传入——这是 [Lambda 递归](./blog.html?post=cpp/practices/lambda_01.md) 三种写法里最推荐的一种。本题 lambda 体短，比写成成员函数少了一层类封装的样板。

注意 `-> void` 返回类型必须显式写：递归调用 `self(...)` 时返回类型还在推导中，会触发 "function with deduced return type cannot be used before it is defined"——这是 lc2140（ch34）踩过的同一个坑。

## 复杂度

| 操作 | 暴力 | 线段树 |
|------|------|--------|
| 单次修改 + 查询 | O(n) 全串扫描 | O(log n) |
| 总复杂度 | O(n·k) ≈ 10¹⁰ | O(n + k·log n) |
| 空间 | O(n) | O(4n) |

对拍验证：200 轮随机（小字符集 + 随机修改），与暴力版完全一致。

## 踩坑点 / 注意点

- ❌ **merge 忘记处理拼接缝**。`best = max(L.best, R.best)` 漏掉 `cross`，`"aa|aa"` 这种会少算一半。
- ❌ **`preLen` 无条件延伸**。忘记 `L.preLen == L.len` 的前提，见关键细节 1。
- ❌ **递归 lambda 不写 `-> void`**。deduced return type 的编译错误，ch34 同款坑。
- ❌ **写完 update 忘了回溯 merge**。和 307 的回溯 `sum` 更新同构——叶子变了，路径上所有祖先都要重算。
