# 替换字符串中的括号内容（1807. Evaluate the Bracket Pairs of a String）

## 题意

字符串 `s` 里有一些 `(key)` 形式的括号对，另给一份键值对表 `knowledge`。把每个括号对替换成对应的 value，查不到的 key 替换成 `?`，返回结果。

```
输入: s = "(name)is(age)yearsold", knowledge = [["name","bob"],["age","two"]]
输出: "bobistwoyearsold"
输入: s = "hi(a)", knowledge = [["a","b"]]
输出: "hib"
输入: s = "(a)(a)(a)aaa", knowledge = [["a","yes"]]
输出: "yesyesyesaaa"
```

- `s`、`knowledge` 长度均不超过 `10^5`，括号保证配对且不嵌套，括号内只有小写字母

## 思路

先把 `knowledge` 灌进哈希表，然后一趟扫描：括号外的字符直接追加到结果；遇到 `(` 开始攒 key，遇到 `)` 查表替换。

```cpp
class Solution {
public:
    string evaluate(string s, vector<vector<string>>& knowledge) {
        // 构建 key -> value 的映射表
        unordered_map<string, string> dict;
        dict.reserve(knowledge.size() * 2); // 预分配，避免 rehash
        for (const auto& pair : knowledge) {
            dict[pair[0]] = pair[1];
        }

        string result;
        result.reserve(s.size()); // 预分配结果容量

        bool insideBracket = false; // 是否位于括号内部
        string key;                // 当前括号内积累的 key

        for (char ch : s) {
            if (ch == '(') {
                insideBracket = true;
            } else if (ch == ')') {
                insideBracket = false;
                // 查询 key，存在则替换，否则用 '?'
                auto it = dict.find(key);
                result += (it != dict.end()) ? it->second : "?";
                key.clear(); // 清空以复用下一次
            } else {
                // 普通字符：括号内积累 key，括号外直接拼接
                if (insideBracket) {
                    key += ch;
                } else {
                    result += ch;
                }
            }
        }
        return result;
    }
};
```

## 关键点

- 状态就一个 `insideBracket`：在不在括号里。题目保证括号配对且不嵌套，所以不需要栈来记层数。
- 两个 `reserve` 都是常数级的小优化，复杂度不变，省的是 rehash 和扩容时的搬移，原理见下节。
- key 是边扫边攒的，`)` 收尾后记得 `key.clear()`，不然下一个 key 会叠在上一个后面。
- 查表用 `find` 而不是 `operator[]`：`[]` 会把不存在的 key 插进表里，虽然这题插了也不影响结果，但语义上"只查不改"用 `find` 更干净。

## reserve 和 rehash

哈希表内部是一个桶数组，元素落在哪个桶由 `hash(key) % bucket_count` 决定。插入的元素多了，桶拥挤、碰撞变多，负载因子超过阈值就触发 rehash：分配一个更大的桶数组，把每个元素按新桶数重新取模、搬到新位置，一次 O(n)。灌 `knowledge` 的过程中要是触发好几次 rehash，就是反复的分配和搬移。

注意 rehash 前后哈希函数没变，同一个 key 的哈希值还是那个值，变的是取模的分母。桶数从 7 变 14，`hash = 10` 的 key 就从桶 3 挪到桶 10。所以 `reserve(knowledge.size() * 2)` 做的事就是一开始把桶数定够，分母从头到尾不变，插入过程零 rehash。

哈希函数本身确实可以换，`unordered_map` 的第三个模板参数就是 Hash 函数对象，传自定义实现就行（比如担心碰撞攻击、或者数据分布特殊时）。这题默认的 `std::hash<string>` 够用，不用折腾。

reserve 的使用分寸也值得说一句。LC 的数据范围写在约束里，reserve 是白捡的常数优化；实际开发里数据规模往往不可预估，默认不预留、让容器自动扩容就好，profiler 指出扩容是热点时再针对性加。

## 复杂度

- 时间：O(n + Σ|value|)，扫一遍 `s`，替换值拷贝的总长度取决于答案长度
- 空间：O(k)，哈希表存 `knowledge`
