# 前五科的均分（1086. High Five）

## 题意

`items` 里每条记录是 `[学生 id, 某一科的分数]`，同一个学生可能出现在多条记录里。对每个学生取**分数最高的 5 科**求平均（整数除法，向下取整），按 id **升序**返回 `[id, 均分]`。每个学生至少有 5 条记录。

```
输入: items = [[1,91],[1,92],[2,93],[2,97],[1,60],[2,77],[1,65],[1,87],[1,100],[2,100],[2,76]]
输出: [[1,87],[2,88]]

输入: items = [[1,100],[7,100],[1,100],[7,100],[1,100],[7,100],[1,100],[7,100],[1,100],[7,100]]
输出: [[1,100],[7,100]]
```

约束：`1 <= items.length <= 1000`，`items[i].length == 2`，`1 <= id <= 1000`，`0 <= score <= 100`，每个 id 至少出现 5 次。

---

## 思路

两件事拼起来：把记录**按 id 分组**，再在每组里**取最大的 5 个**。

分组用 `map<int, priority_queue<int>>`：key 是学生 id，value 是该学生的分数大顶堆。`std::priority_queue` 默认最大堆，分数一进桶就随时能取当前最大值，取前 5 大就是连续 `top()` + `pop()` 五次。而 `std::map` 按 key 有序遍历，输出要求的"按 id 升序"是白送的。

## 解法：map 分组 + 大顶堆

```cpp
class Solution {
public:
    vector<vector<int>> highFive(vector<vector<int>>& items) {
        map<int, priority_queue<int>> m;
        for (const auto& item: items) {
            m[item[0]].push(item[1]);
        }
        vector<vector<int>> result;
        for (auto& [k, v]: m) {
            int temp = 0;
            for (int i = 0; i < 5; i++) {
                temp += v.top();
                v.pop();
            }
            result.push_back({k, temp / 5});
        }
        return result;
    }
};
```

---

## 核心理解

### 1. 为什么用 map 而不是 unordered_map

输出要按 id 升序。`std::map` 的遍历顺序就是 key 升序，遍历时直接 push 进结果数组即可；换成 `unordered_map` 就得在最后补一次 `sort`，或者另存一组 key 再排。本题 id 只有 1000 量级，红黑树的 log 开销感觉不到，有序性却是实打实的收益。

### 2. 每个桶挂大顶堆，等于把 top-K 的活外包给容器

组内记录数不定（可能远超 5 条），要的是"最高的 5 科"。大顶堆提供的性质正好是"每次都能拿到当前最大"，pop 五次即得，不需要把整组排好序。

三种等价写法的取舍：

| 写法 | 每组代价 | 感受 |
|------|----------|------|
| 大顶堆 + pop 5 次 | 建桶时逐步插入 O(m log m)，取值 5 log m | 代码最短，本题的默认选法 |
| 小顶堆只留 5 个 | O(m log 5) | 数据量大时更省，但本题每组都要取满 5 个，多余 |
| 整组排序后取前 5 | O(m log m) | 最直白，m 小的时候和堆没区别 |

约束下 m 不会大，三种都能过。选大顶堆是因为它表达的正是"从大到小拿五个"这句话本身，而不是绕一圈去维护 top-K 的边界。

### 3. `m[item[0]]` 的 `operator[]` 在这里是特性

`map::operator[]` 在 key 不存在时会**默认构造**一个 value，也就是一个空的大顶堆，于是 `m[item[0]].push(item[1])` 一行同时完成"找到或创建这个学生的桶"和"把分数塞进去"。这是分组桶最顺手的写法。

它的前提是"不会出现只有桶、没有分数的空组"（本题每个 id 至少 5 条，成立）。如果数据里可能出现空组，遍历时就得先判空，那时更适合 `find`/`try_emplace` 而不是无脑 `[]`。

### 4. 整数除法在这里正好是向下取整

`temp / 5` 对非负整数就是 floor，分数区间是 `[0, 100]`，和不可能为负，所以不用 `floor` 也不用 `double` 中转。反过来，值域带负数时 C++ 的除法是向零截断，和"向下取整"不是一回事，那时才需要额外处理。除不尽时小数部分直接丢弃，比如 99.4 → 99。

## 复杂度

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| 时间 | O(n log n) | n 条记录，每条插入自己的桶 O(log m)；每组再出堆 5 次 |
| 空间 | O(n) | 所有分数都落在堆里 |

（m 为单个学生的记录数，最坏情况等于 n）

---

## 踩坑点 / 注意点

- ❌ **取了 `top()` 忘记 `pop()`**：`temp += v.top()` 后面漏掉 `v.pop()`，五次循环加的都是同一个堆顶，分数被重复计入，均值偏大。堆只有 pop 过之后 `top()` 才会变。
- ❌ **图省事用了 `unordered_map` 却不排序**：遍历顺序和 id 升序对不上，输出顺序随机。要么用 `map`，要么最后显式 `sort`。
- ❌ **`item[0]` 和 `item[1]` 写反**：`items[i]` 的第一个元素是 id，第二个才是分数；写反后分组和取值同时错位，样例都过不了。
