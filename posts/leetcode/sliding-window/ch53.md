# 每个元素最多出现 K 次的最长子数组（2958. Length of Longest Subarray With at Most K Frequency）

## 题意

给定数组 `nums` 和整数 `k`。一个数组是**好的**，当其中每个元素的出现次数都不超过 `k`。返回 `nums` 的最长好子数组的长度。

```
输入: nums = [1,2,3,1,2,3,1,2], k = 2
输出: 6
解释: [1,2,3,1,2,3] 中每个值恰好出现 2 次。

输入: nums = [1,2,1,2,1,2,1,2], k = 1
输出: 2
解释: k=1 时任何值都不能重复，最长好子数组长度是 2。
```

约束：`n <= 10⁵`，`1 <= nums[i] <= 10⁹`，`1 <= k <= n`。

---

## 思路：滑动窗口（3090 的数组版）

和 [3090 每个字符最多出现两次](./blog.html?post=leetcode/sliding-window/ch51.md) 是同一个模板，两处变化：

1. 字符数组换成整数数组，频率上限从固定的 2 变成参数 `k`
2. 值域到 `10⁹`，不能用 26 槽位的数组，换 `unordered_map` 计数

```cpp
class Solution {
public:
    int maxSubarrayLength(vector<int>& nums, int k) {
        const int n = nums.size();
        int i = 0, j = 1, len = 1;

        unordered_map<int, int> cnt;
        cnt[nums[0]] = 1;
        while (j < n) {
            cnt[nums[j]] += 1;              // 扩张
            while (cnt[nums[j]] > k) {      // 收缩到合法
                cnt[nums[i]] -= 1;
                i++;
            }
            len = max(j - i + 1, len);      // 记录
            j++;
        }
        return len;
    }
};
```

---

## 关键细节

### 1. 模板三段式没变

扩张（`cnt[nums[j]]++`）→ 收缩（`while` 循环把超限值降回 k）→ 记录（`len = max(...)`）。和 3090 逐字符对比，结构一模一样。这类"子数组内每元素频率受限"的问题都是这个模板。

### 2. 为什么这次必须用哈希表

3090 的字符集是 26 个小写字母，`vector<int>(26)` 直接索引最优。本题值域到 `10⁹`，只能哈希。约束反过来时的决策逻辑：**值域小且密集 → 数组；值域大或稀疏 → 哈希表**。

### 3. 初始化方式的一个小变体

这版写法把 `nums[0]` 预先放进窗口（`i=0, j=1, len=1`），循环从第二个元素开始。3090 那版是空窗口起步（`left=right=0`），从第一个元素开始扩张。两种初始化都正确，但第一种依赖 `n >= 1`（本题约束保证），空数组会越界——空窗口起步的写法对 `n=0` 天然免疫，更防御性。

---

## 复杂度

| 指标 | 滑动窗口 | 暴力枚举 |
|------|---------|---------|
| 时间 | O(n) | O(n²) |
| 空间 | O(n)（哈希表） | O(n) |

`n = 10⁵` 时暴力约 10¹⁰ 次操作必然超时，滑动窗口每个下标只被两个指针各访问一次。

对拍验证：500 组随机（小值域 + 随机 k ∈ [1,4]）与暴力版完全一致。

---

## 踩坑点 / 注意点

- ❌ **收缩用 `if` 不用 `while`**。一个值的频率从 k 超到 k+1 时，要把窗口里该值的**上一次出现**挤出去才算完——收缩可能要多步，`if` 只走一步窗口仍不合法。和 3090 完全同款坑。
- ❌ **收缩条件写错位置**。检查的是刚加入的 `cnt[nums[j]] > k`，不是扫全表——加入前窗口合法，唯一可能被破坏的就是新加的值。
- ❌ **值域没看约束就用数组**。`10⁹` 的值域开数组直接 MLE/RE。
