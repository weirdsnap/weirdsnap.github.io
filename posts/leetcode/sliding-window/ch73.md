# 长度为 K 的无重复字符子串（1100. Find K-Length Substrings With No Repeated Characters）

## 题意

给定字符串 `s`（小写字母）和整数 `k`，统计 `s` 中有多少个**长度为 k** 且**字符互不相同**的子串。

```
输入: s = "havefunonleetcode", k = 5
输出: 6

输入: s = "home", k = 5
输出: 0
解释: k > len(s)，不存在长度为 5 的子串。
```

约束：`1 <= s.length <= 10⁴`，小写字母。

---

## 思路：定长窗口

窗口长度固定为 `k`，每步"右进一个、左出一个"，检查窗内是否有重复字符。这是[滑动窗口模板](./blog.html?post=leetcode/sliding-window/template.md)的**退化形态**：不需要收缩循环（窗口长度卡死），答案是计数型。

## 解法一：每步全表扫描（提交版）

```cpp
class Solution {
public:
    int numKLenSubstrNoRepeats(string s, int k) {
        if (k > s.size()) return 0;

        int i = 0, j = 0, result = 0;
        unordered_map<char, int> cnt;
        while (j < k - 1) {          // 先装前 k-1 个
            cnt[s[j] - 'a']++;
            j++;
        }
        while (j < s.size()) {       // 之后每步凑满 k 个就检查
            cnt[s[j] - 'a']++;
            bool valid = true;
            for (const auto& [c, time] : cnt) {
                if (time > 1) { valid = false; break; }
            }
            if (valid) result++;
            cnt[s[i] - 'a']--;       // 左端出窗
            i++;
            j++;
        }
        return result;
    }
};
```

## 解法二：`dup` 计数器，O(1) 判合法

合法性判据"没有字符出现超过一次"不需要扫全表：维护一个 `duplicates`（当前窗内**计数 ≥ 2 的字符种数**），只在计数变化时增量更新。保留解法一的两段式结构，只换判合法的部分：

```cpp
class Solution {
public:
    int numKLenSubstrNoRepeats(string s, int k) {
        if (k > s.size()) return 0;

        int i = 0, j = 0, result = 0;
        int duplicates = 0;                     // 窗口内重复字符的种类数
        int cnt[26] = {0};                      // 仅小写字母，定长数组替代哈希表

        while (j < k - 1) {
            // 计数从 1 变 2 时产生一个重复
            if (++cnt[s[j] - 'a'] == 2) duplicates++;
            j++;
        }
        while (j < s.size()) {
            if (++cnt[s[j] - 'a'] == 2) duplicates++;   // 右端进窗
            if (duplicates == 0) result++;
            if (--cnt[s[i] - 'a'] == 1) duplicates--;   // 左端出窗，重复消除
            i++;
            j++;
        }
        return result;
    }
};
```

**再精简的方向**（参考实现里用了）：初始化循环可以并回主循环：用 `j >= k` 判断出窗、`j >= k - 1` 判断首次凑满，两段式变单循环。属于写法收敛，不影响复杂度。

---

## 核心理解

### 1. 定长窗口 = 不需要收缩的滑窗

变长窗口的"右扩左缩"里，收缩循环是为了恢复合法性；定长窗口的出窗由长度卡死（`j - i + 1 == k` 时左端必出），循环退化成每步各一格。写法也随之简化：单循环形态下用 `j >= k` 判断出窗、`j >= k - 1` 判断首次凑满结算（参考实现的写法），两段式形态则用初始化循环先装 `k - 1` 个。两个下标条件替代了整个收缩循环。

### 2. `duplicates` 增量的时机条件不能写宽

- 进窗：`++cnt == 2` 才 `duplicates++`——第三次、第四次进窗时这个字符已经记过了，写 `>= 2` 会重复计数
- 出窗：`--cnt == 1` 才 `duplicates--`——从 3 减到 2 时重复还在，写 `<= 1` 会提前消除

这两个条件分别刻画"从无到有"和"从有到无"的瞬间，是增量维护的典型写法。

### 3. 鸽巢彩蛋：k > 26 时答案必为 0

只有 26 个字母，长度超过 26 的子串必然有重复字符。代码不用特判（扫描/`duplicates` 自然判出全部非法），但读题时想到这点可以直接心算掉一批 case。

---

## 复杂度

| | 解法一（全表扫描） | 解法二（duplicates 计数） |
|--|--------------------|---------------------------|
| 时间 | O(n × 26) | O(n) |
| 空间 | O(26) | O(26) |

验证：穷举 {a,b,c} 上全部长度 ≤ 11 的串 × k∈[1, len+2]（含 k > n 分支）× 三版（全表扫描 / dup+map / dup+数组）+ 300 组字母表 26 的随机串（k 到 30，覆盖鸽巢无解区），与参考实现逐一对拍。9,965,114 条断言全过。

---

## 踩坑点 / 注意点

- ❌ **初始化循环的 off-by-one**。先装 `k - 1` 个再进主循环，写成 `j < k` 会让第一个窗口多装一个字符。
- ❌ **漏掉 `k > n` 提前返回**。本题约束下无所谓（主循环自然不进），但语义上"长度为 k 的子串不存在"应该显式返回 0。
- ❌ **扫描判合法时把计数为 0 的键当问题**。解法一不 `erase` 归零键，`size()` 失真——但判据是 `time > 1`，0 键无害，只是每步多扫几个格子。
