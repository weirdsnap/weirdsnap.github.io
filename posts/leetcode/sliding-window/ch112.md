# 数据流中的移动平均值（346. Moving Average from Data Stream）

## 题意

设计一个类 `MovingAverage`，构造时给定窗口大小 `size`，每次调用 `next(val)` 送入一个整数，返回数据流中最近至多 `size` 个值的平均值。

```
MovingAverage m = new MovingAverage(3);
m.next(1);  // 返回 1.0        窗口 [1]
m.next(10); // 返回 5.5        窗口 [1, 10]
m.next(3);  // 返回 4.66667    窗口 [1, 10, 3]
m.next(5);  // 返回 6.0        窗口 [10, 3, 5]，1 被移出
```

- `1 <= size <= 1000`，`-10^5 <= val <= 10^5`，`next` 最多调用 `10^4` 次

## 解法一：queue，真出队

典型的定长滑动窗口，载体是队列：新值入队、加入窗口和 `sum`；队列长度超过 `size` 就把队首弹出并从 `sum` 里减掉。平均值就是 `sum / q.size()`。

```cpp
class MovingAverage {
public:
    MovingAverage(int size) {
        this->cap = size;
    }
    
    double next(int val) {
        q.push(val);
        this->sum += val;
        // 超过窗口大小则移除最早进入的元素，保持窗口内最多 cap 个
        if (q.size() > cap) {
            this->sum -= q.front();
            q.pop();
        }
        // 用 double 除法得到正确的浮点结果；窗口未满时按实际个数求平均
        return this->sum / q.size();
    }
private:
    queue<int> q;
    int cap = 0;
    double sum = 0;
};
```

关键点：

- 窗口和是增量维护的：进一个加一个，出一个减一个，`next` 做到 O(1)。每次都遍历队列重新求和就是 O(size)，没有必要。
- 窗口未满时 `q.size()` 自然小于 `cap`，分母用队列的实际长度就行，不用对"还没填满"做特判。
- 只需要队首弹出、队尾插入，`queue` 正合适。要遍历窗口或者两端操作才轮到 `deque`。

## 解法二：vector + head 指针，假出队

用 `vector` 当队列使：元素只往尾部 `push_back`，"出队"不把元素删掉，只是把 `head` 指针往后挪。有效窗口是 `[head, q.size())`，长度即 `q.size() - head`。

```cpp
class MovingAverage {
public:
    MovingAverage(int size) {
        this->cap = size;
    }
    
    double next(int val) {
        q.push_back(val);   // 尾部入队（vector 的 push_back）
        sum += val;
        // 超出窗口：移动 head 指针跳过队头，而不是真正删除
        if ((int)q.size() - head > cap) {
            sum -= q[head];
            head++;
        }
        return sum / ((int)q.size() - head);
    }
private:
    vector<int> q;  // 用 vector 模拟队列
    int head = 0;   // 队头指针
    int cap = 0;
    double sum = 0;
};
```

关键点：

- 逻辑和解法一一模一样，`q.size() - head` 替代了 `q.size()` 的角色。写这种模拟时所有用到"当前队列长度"的地方都要换成它，漏一处就错。
- 代价是内存：`vector` 只增不减，`next` 调了 n 次它就占 n 个元素的内存，空间从 O(size) 变成 O(n)。LC 上最多 10^4 次调用无所谓，长期运行的服务里要定期压缩，比如 `head == q.size()`（窗口全废）时 `q.clear()` 并把 `head` 归零。
- 好处是 `vector` 内存连续，`push_back` 摊还 O(1) 且没有队列节点的指针开销，常数上略快。

## 关键点

- `sum` 两个解法都声明成 `double`，顺手把最后的浮点除法解决了。更讲究的写法是 `sum` 用整型（窗口最大 1000 × 10^5 = 10^8，`int` 都够），return 时再转 `double`，累加过程完全没有精度问题；现在这样写在这题的数据范围下也不会出错。

## 复杂度

| | 时间（单次 `next`） | 空间 |
|---|---|---|
| 解法一（queue） | O(1) | O(size) |
| 解法二（vector + head） | O(1)，摊还 | O(n)，n 为调用次数 |
