# 滑动窗口：识别信号、代码骨架与题目地图

这不是题解，是这个分类下所有题解的**公共骨架**——每篇题目文章都是在这个骨架上改一两处。读法：先看骨架，再按题目地图表去看每篇改了哪里。

---

## 什么时候想到滑动窗口

三个信号同时出现，基本就是滑窗：

1. 求的是**连续**子数组 / 子串（不是子序列）
2. 带一个"至多 / 恰好 K 个……"型的**约束**（种类数、频次、元素和）
3. 问**最长** / **最短** / **有几个**

## 代码骨架

```cpp
int i = 0, result = 0;
unordered_map<X, int> cnt;             // 计数结构，值域小就换定长数组
for (int j = 0; j < n; j++) {
    cnt[a[j]]++;                        // 右端进窗
    while (违反约束(cnt)) {              // 收缩判据
        if (--cnt[a[i]] == 0) cnt.erase(a[i]);
        i++;
    }
    result = max(result, j - i + 1);    // 答案更新（时机按题型变，见下）
}
return result;
```

核心性质：每个位置最多进窗一次、出窗一次，**均摊 O(n)**。所有文章里"时间 O(n)"的底气都来自这一句。

## 骨架上的三个可变点

| 可变点 | 选项 | 注意 |
|--------|------|------|
| 计数结构 | `unordered_map` / `map` / 定长数组 | 值域已知且小（26 字母、0~100）就用数组，省哈希开销 |
| 收缩判据 | `cnt.size() > k` / `cnt[x] > k` | 用 `size()` 就必须 `erase` 归零键，否则失真 |
| 答案更新时机 | 收缩后 / 达标时 / 每次都更 | 见下面三种题型 |

## 答案更新的三种时机（题型分水岭）

- **最长型**（至多 K 个……）：收缩**之后**窗口必然合法，`result = max(result, j - i + 1)`。159、340、3090、2958 都是这个。
- **最短型**（恰好满足……的最短窗口）：在**达标时**进入内层收缩，收缩过程中更新答案（`min`），收缩到不达标为止。209、2904 是这个。
- **计数型**（有多少个合法窗口）：最长型收缩完后，以 `j` 结尾的合法窗口有 `j - i + 1` 个，直接累加。

还有一个通用转化：**恰好 K 个 = 至多 K 个 − 至多 K−1 个**（`exactly(k) = atMost(k) - atMost(k-1)`），计数型题（如 992）靠它把"恰好"化成两遍骨架。

## 踩坑速查

- ❌ 用 `cnt.size()` 判据却忘记 `erase` 归零键（[ch69](./blog.html?post=leetcode/sliding-window/ch69.md) 核心理解 2）
- ❌ 手写 `++j` 扩张，越界读 `s[s.size()]`——C++11 起合法返回 `'\0'` 但脆弱（[ch67](./blog.html?post=leetcode/sliding-window/ch67.md) 核心理解 3）
- ❌ `k = 0`、空串画蛇添足加特判——模板天然覆盖（[ch69](./blog.html?post=leetcode/sliding-window/ch69.md) 核心理解 3）
- ❌ 最短型把答案更新放在收缩循环外——达标状态在收缩过程中被破坏，必须在循环内更新
