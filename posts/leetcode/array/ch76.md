> **标签**：数组、一次遍历
# 删除最小值和最大值的最少次数（2091. Removing Minimum and Maximum From Array）

## 题意

数组 `nums` 元素**互不相同**。每次操作可以从**头部或尾部**删除一个元素，求删除最小值和最大值所需的**最少操作次数**。

```
输入: nums = [2,10,7,5,4,1,8,6]
输出: 5
解释: 最小值 1 在下标 5，最大值 10 在下标 1。
      最优：删 3 次头部（2,10,7）+ 删 2 次尾部（6,8），共 5 次。

输入: nums = [0,-4,19,1,8,-2,-3,5]
输出: 3

输入: nums = [101]
输出: 1
```

约束：`1 <= n <= 10⁵`，`-10⁹ <= nums[i] <= 10⁹`，元素互不相同。

---

## 思路：只关心两个下标

删除只能发生在两端，所以答案只取决于最小值下标 `min_idx` 和最大值下标 `max_idx`，**和具体的值无关**。一次遍历同时定位两者，然后枚举三种删除策略取最小：

设 `i1 = min(min_idx, max_idx)`，`i2 = max(min_idx, max_idx)`：

- **两侧夹击**：从左边删 `i1 + 1` 次（删掉 i1），从右边删 `n - i2` 次（删掉 i2），共 `i1 + 1 + n - i2`；
- **全从左边删**：删掉 i2 时 i1 必然已被删掉，共 `i2 + 1`；
- **全从右边删**：同理，共 `n - i1`。

答案 = 三者最小值。

## 解法：一次遍历 + 三策略取最小

```cpp
class Solution {
public:
    int minimumDeletions(vector<int>& nums) {
        const int n = nums.size();
        if (n == 1) return 1;
        int min_idx = 0, max_idx = 0;
        // 单次遍历同时定位最小值和最大值的下标
        for (int i = 0; i < n; i++) {
            if (nums[min_idx] > nums[i]) min_idx = i;
            if (nums[max_idx] < nums[i]) max_idx = i;
        }
        int i1 = min(min_idx, max_idx);
        int i2 = max(min_idx, max_idx);
        int both_sides = (i1 + 1) + (n - i2);  // 两侧夹击
        int left_only  = i2 + 1;               // 全从左边删
        int right_only = n - i1;               // 全从右边删
        return min({both_sides, left_only, right_only});
    }
};
```

---

## 核心理解

### 1. 三种策略为什么够

任何删除序列都可以看成"从左边删了 a 次、从右边删了 b 次"（交错顺序不影响总次数）。要删掉 i1 和 i2：若 a ≤ i1 则左边没删到任何目标，i1、i2 都得靠右边，即 b ≥ n - i1，这正是"全从右"；对称地 a > i2 时是"全从左"；i1 < a ≤ i2 时左边删掉 i1，右边至少删 n - i2 次删掉 i2，即"两侧夹击"。**所有情况被三条直线覆盖，最优必在其中**，所以不用搜索。

### 2. 同时求 min/max 下标：两个独立的 if

`if (nums[min_idx] > nums[i])` 和 `if (nums[max_idx] < nums[i])` 必须写成**两个独立 if**，不能 `else if`——比较方向相反，互斥写法在遇到"当前元素同时刷新两者"或首元素场景会漏更新。另外维护的是**下标**不是值：后面算删除次数要用位置。

### 3. `n == 1` 的特判其实冗余

代公式：i1 = i2 = 0，三策略分别得 2、1、1，min 已经是 1。开头那行 `if (n == 1) return 1;` 删掉也对。留着无害，但知道公式**天然覆盖边界**说明推导是闭合的——这也是"公式法"相比"模拟法"的好处：边界情况自动落在公式里，不用挨个特判。

## 复杂度

| | 时间 | 空间 |
|--|------|------|
| 一次遍历 + 三策略 | O(n) | O(1) |

验证：对拍一个 BFS 模拟真实删除过程的 oracle（状态为剩余窗口 `[l, r]`，每步删左或删右，首次让 min/max 都出窗即最少次数）。穷举 `[1..n]` 全排列（n ≤ 7，共 5,913 组）+ 500 组随机排列（n ≤ 60），**6,416 条断言全过**。

---

## 踩坑点 / 注意点

- ❌ **把删除次数和下标搞混**。从左边删掉下标 i 需要 `i + 1` 次（下标从 0 起），从右边删掉下标 i 需要 `n - i` 次。三个公式都是"+1 / n−i"形态，推一遍再写。
- ❌ **只求了值没求下标**。`min_element` 拿到的值对算次数毫无用处，这题的位置信息才是答案。
- ❌ **忘了"两侧夹击"策略**，只比较"全左"和"全右"。两个目标分居数组两端附近时，两侧夹击严格更优（如样例 1），漏了它就是错答。
- ⚠️ **对拍 oracle 的教训**（测试侧）：BFS 里把"剩一个元素"当立即返回的终态是错的。同深度的另一个状态可能 0 额外代价就终结。要把"删到空窗口"建成正常状态，让 BFS 按深度自然选出最小值，别加人为捷径。
