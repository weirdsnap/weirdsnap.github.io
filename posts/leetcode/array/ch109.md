# 图像重叠（835. Image Overlap）

## 题意

两个 `n × n` 的二值矩阵 `img1`、`img2`。可以把 `img1` 上下左右平移任意格数（移出边界的部分丢弃），问平移之后，两个矩阵重叠区域里"1 对着 1"的格子最多有多少对。

```
输入: img1 = [[1,1,0],[0,1,0],[0,1,0]], img2 = [[0,0,0],[0,1,1],[0,0,1]]
输出: 3   （img1 向右下各平移一格）
输入: img1 = [[1]], img2 = [[1]]
输出: 1
```

- `1 <= n <= 30`，矩阵元素只有 0 和 1

## 思路

平移量 `(i, j)` 各只有 `2n - 1` 种取值（`[-n+1, n-1]`，再大两图就完全错开了）。偏移总量是 O(n²) 级别，全枚举就行，剩下的问题是：给定偏移，怎么数重叠区里的 1-1 对。

重叠区是一个矩形子块，不用逐个格子判越界，边界可以直接 clamp 出来。`img1` 的格子 `(k, l)` 平移后对应 `img2` 的 `(k+i, l+j)`，两边下标都要落在 `[0, n-1]`，对 `k` 来说就是 `0 <= k <= n-1` 和 `0 <= k+i <= n-1` 取交集，即 `k ∈ [max(0, -i), min(n-1, n-1-i)]`。`l` 同理。

```cpp
class Solution {
public:
    int largestOverlap(vector<vector<int>>& img1, vector<vector<int>>& img2) {
        int result = 0;
        const int n = img1.size();
        // 固定 img2，img1 相对偏移 (i, j)，i、j 独立取 [-n+1, n-1]
        for (int i = -n + 1; i < n; i++) {
            for (int j = -n + 1; j < n; j++) {
                int cnt = 0;
                // 动态计算重叠区域：遍历 img1 的格子 (k, l)，对应 img2 位置 (k+i, l+j)
                // 要求 0 <= k+i <= n-1 且 0 <= l+j <= n-1，同时 k、l 本身在 [0, n-1]
                int kStart = max(0, -i);
                int kEnd   = min(n - 1, n - 1 - i);
                int lStart = max(0, -j);
                int lEnd   = min(n - 1, n - 1 - j);
                for (int k = kStart; k <= kEnd; k++) {
                    for (int l = lStart; l <= lEnd; l++) {
                        if (img1[k][l] == 1 && img2[k + i][l + j] == 1) {
                            cnt++;
                        }
                    }
                }
                result = max(result, cnt);
            }
        }
        return result;
    }
};
```

## 关键点

- 偏移范围 `[-n+1, n-1]` 是紧的：偏移量等于 `n` 时两图刚好完全不重叠，多枚举只是白算。
- 四个边界值是"两个合法区间取交集"的展开：`k` 要在 img1 里合法（`[0, n-1]`），映射后的 `k+i` 要在 img2 里合法（`[-i, n-1-i]`），`max` 取下界、`min` 取上界。一行 clamp 替代四个 if。
- 平移方向不要搞反：代码里 img1 的 `(k, l)` 对应 img2 的 `(k+i, l+j)`，相当于 img1 向"下、右"为正方向平移。方向约定反了不影响正确性（偏移本来就是正负全枚举），但自己调试时要想清楚对应关系。

## 从 if 判边界到 clamp 范围

最开始的写法更直接：内层循环不管偏移多少都跑满 `n²`，每个格子用 if 判一次边界。改成动态算 `k`、`l` 的范围之后，每个偏移只扫真实的重叠区。

算笔账：if 版每个偏移固定访问 `n²` 个格子，`(2n-1)²` 个偏移共约 `4n⁴` 次；clamp 版所有偏移的重叠区面积加起来恰好是 `(Σ(n-|d|))² = n⁴`，格子访问数只有前者的四分之一。不过省下的主要是越界判断的开销，单次调用 `n = 30` 时从 4ms 降到 0.6ms，看着快了近 7 倍，绝对量却都很小，在 LeetCode 上体感差别不大，复杂度也仍是 O(n⁴)。

## 复杂度

- 时间：O(n⁴)，偏移 O(n²) 种 × 每种的重叠区最多 O(n²)。`n <= 30` 时约 81 万次，绰绰有余
- 空间：O(1)

n 再大就得换思路了：只收集两图中 1 的坐标，枚举"img1 的 1 → img2 的 1"的偏移差，哈希计数出现次数最多的偏移差。复杂度和 1 的数量挂钩，稠密矩阵退化，稀疏矩阵快很多。
