# 最小缺失倍数（3718. Smallest Missing Multiple of K）

## 题意

给定数组 `nums` 和整数 `k`，返回**不在** `nums` 中的、最小的 `k` 的正整数倍。

```
输入: nums = [8,2,3,1], k = 2
输出: 4
解释: 2 的倍数依次为 2, 4, 6, ...，2 在数组中，4 不在。

输入: nums = [1,4,7,10,15], k = 5
输出: 5
解释: 5 本身就不在数组中。
```

约束：`1 <= nums.length <= 100`，`1 <= nums[i] <= 100`，`1 <= k <= 100`。

---

## 思路：装进集合，从 k 开始倍增扫描

把数组装进哈希集合，从 `t = k` 开始不断加 `k`，第一个不在集合里的 `t` 就是答案。

```cpp
class Solution {
public:
    int missingMultiple(vector<int>& nums, int k) {
        unordered_set<int> cnt(nums.begin(), nums.end());
        // 仅需找到 k 的最小倍数且不在集合中；直接倍增即可
        int t = k;
        while (cnt.count(t)) {
            t += k;
        }
        return t;
    }
};
```

**注意**：扫描起点是 `k` 不是 `0`——`0` 虽然是 `k` 的倍数，但题目要的是**正整数**倍，而且 `nums[i] >= 1` 保证 `0` 永远不在数组里，从 `0` 开始会直接错误返回 `0`。

---

## 核心理解

### 1. 为什么循环一定在 n+1 步内终止（鸽巢原理）

`k, 2k, ..., (n+1)k` 是 **n+1 个互不相同**的倍数，而 `nums` 最多 `n` 个元素（去重后不同值 ≤ n 个）。n+1 个倍数往 ≤ n 个"坑"里放，至少一个倍数缺席。所以：

- 循环必然终止，不存在死循环风险
- 答案上界 `k × (n+1) <= 100 × 101 = 10100`，int 毫无压力

### 2. 不需要排序，也不需要找 min/max

对比 3731（[ch44](./blog.html?post=leetcode/array/ch44.md)）：那题要先确定 `[min, max]` 范围再扫缺失；本题的范围天然从 `k` 开始单向延伸，扫描顺序就是答案顺序，连边界都不用算。

### 3. 值域小，数组也能替代哈希

`nums[i] <= 100` 但答案最大到 10100，用数组替代哈希要开 10101 个槽位（不能只开 101）。本题 `n <= 100`，线性扫描版（每个倍数 O(n) 查一次）总共也就 O(n²) = 10⁴ 次操作，完全是常数级别——小约束题，写法随手感选即可。

---

## 复杂度

| 指标 | 值 |
|------|----|
| 时间 | O(n + 答案/k) ≤ O(n)（鸽巢上界 n+1 步） |
| 空间 | O(n)（哈希集合） |

验证：500 组随机对拍（哈希集合版 vs 纯线性扫描版）+ 500 组鸽巢上界断言（答案必是 k 的倍数且 ≤ k×(n+1)）+ 边界用例（k 缺席、k=1 连续数组、全重复倍数）。1505 条断言全过。

---

## 踩坑点 / 注意点

- ❌ **从 `t = 0` 开始枚举**。`0` 不是正整数倍，且约束保证 `0` 不在数组中，会错误返回 `0`。
- ❌ **先排序或去重**。扫描顺序天然有序，任何预处理都是多余动作。
- ❌ **用数组替代哈希时槽位开小了**。要覆盖答案上界 `k×(n+1)`，不是 `nums[i]` 的值域 100。
