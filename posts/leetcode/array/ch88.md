# 构造统一奇偶数组 II（3876. Construct Uniform Parity Array II）

## 题意

与 [3875](./blog.html?post=leetcode/array/ch87.md) 同骨架，但翻转操作多了一条约束：`nums2[i] = nums1[i] - nums1[j]` 要求 `nums1[i] - nums1[j] >= 1`（**只能减去严格更小的元素**；互异保证没有相等）。问能否构造全奇或全偶的 `nums2`。各下标的选择相互独立（"in any order"）。

```
输入: nums1 = [1,4,7]
输出: true    （1 保持；4-1=3；7 保持 → [1,3,7] 全奇）

输入: nums1 = [2,3]
输出: false   （2 是全局最小且为偶 → 必须全偶；3 是奇数，
               要变偶需减去更小的奇数——不存在）

输入: nums1 = [4,6]
输出: true
```

约束：`n <= 10⁵`，值 `1..10⁹`，互异。

---

## 思路：最小元素的奇偶锁死整个目标

**全局最小值 `mn` 无法翻转**（没有更小的元素可减），它只能保持，所以 `nums2` 的目标奇偶 = `mn` 的奇偶。

- **`mn` 为奇 → 恒 true**：每个偶数 `x` 都满足 `x > mn`（互异），于是 `x - mn >= 1` 且为奇数，全体都能归奇，奇数保持即可。
- **`mn` 为偶 → 必须全偶**：每个奇数 `x` 要变偶，需减去一个**更小的奇数**；但全局最小是偶数，最小的那个奇数找不到比自己小的奇数，**只要有奇数存在就 false**。全是偶数则直接保持。

合并成判定：**`mn` 奇则 true；`mn` 偶则当且仅当没有奇数元素**。

## 解法一：最小值定奇偶 + 逐元素检查（第一版）

```cpp
class Solution {
public:
    bool uniformArray(vector<int>& nums1) {
        int min_val = *min_element(nums1.begin(), nums1.end());

        if (min_val % 2) {  // 目标：全奇数
            int min_odd = min_val;
            for (int num : nums1) {
                if (num % 2) {
                    min_odd = min(min_odd, num);
                } else {
                    // 偶数需借更小奇数翻转（奇-偶=奇... 此处是 偶-奇=奇）
                    if (num < min_odd) return false;
                    min_odd = min(min_odd, num - min_odd);
                }
            }
            return true;
        } else {  // min 为偶：存在奇数则不可行
            for (int num : nums1) {
                if (num % 2 == 1) return false;
            }
            return true;
        }
    }
};
```

## 解法二：化简后的两行判定

```cpp
class Solution {
public:
    bool uniformArray(vector<int>& nums1) {
        int mn = *min_element(nums1.begin(), nums1.end());
        if (mn % 2) return true;  // 最小为奇：恒可构造（全体归奇）
        // 最小为偶：有奇数即失败
        return none_of(nums1.begin(), nums1.end(),
                       [](int x) { return x % 2 == 1; });
    }
};
```

---

## 核心理解

### 1. 解法一的奇数分支其实是死代码

`min_odd` 初始化为全局最小 `min_val`，之后的 `min(...)` 只会让它**不变或变小**（实际不会变小，`min_val` 已是最小），所以 `num < min_odd` **永远不可能成立**，那个 `return false` 是到不了的分支。推导清楚"min 为奇 ⇒ 恒 true"之后，整个跟踪循环都可以删掉，这就是解法二。**写完后回头问一句"哪个分支真的活着"**，常常能把代码再砍一半。

### 2. 锁死效应：找"无法被操作触及"的元素

`>= 1` 约束的本质是操作只能朝**更小**的方向传递。这类"单向操作"题的第一步永远是找链路的**端点**，这里是最小值。端点的状态无法被改变，于是它反过来约束全局。3875 没有这个约束所以没有端点，恒 true；3876 有了端点，答案完全由端点和"是否存在某类元素"决定。

### 3. 翻转的奇偶算术

奇偶翻转的规则表：`偶−奇=奇`、`奇−偶=奇`、同奇偶相减得偶。目标"全奇"时偶数要找**更小的奇数**减；目标"全偶"时奇数要找**更小的奇数**减。两种情况都依赖"更小的奇数"，所以真正的稀缺资源是**奇数的最小值**与目标元素的相对大小。把算术表列出来，判定条件就自己浮出来了。

## 复杂度

| | 解法一 | 解法二 |
|--|--------|--------|
| 时间 | O(n) | O(n) |
| 空间 | O(1) | O(1) |

验证：两版都对拍**指数级暴力 oracle**（枚举每个下标"保持/减去任一更小元素"的全部选择组合，检查是否存在同奇偶方案）。官方 3 样例 + 值域 {1..7}、n ≤ 4 的**全部互异有序排列**（1,099 组）× 两版 + 300 组大数值随机 × 两版，**2,808 条断言全过**。

## 踩坑点 / 注意点

- ❌ **忽略 `>= 1` 约束**（作者亲踩）。第一反应沿用 3875 的"任意减"直觉，会得出恒 true 的错答案（`[2,3]` 就是反例）。两题题面几乎一样，差的就是这一条。
- ❌ **以为选择有顺序依赖**。题面 "in any order" 是说各下标独立选择，互不影响，每个元素单独判定可行性即可，不用考虑先后。
- ❌ **误认为 `nums2` 的新值能继续被别的下标当 `j` 用**。`j` 永远索引 `nums1` 的原值；解法一里 `min_odd = min(min_odd, num - min_odd)` 这行把 `nums2` 的产物混进了"可用减数"池，虽然由于它到不了 `return false` 而无害，但概念上是错的，化简版直接删掉。
- ⚠️ **互异条件别浪费**：它保证 `x != mn ⇒ x > mn`，"严格更小"的判断才好写。
