# 打扫教室的最少移动次数（3568. Minimum Moves to Clean the Classroom）

## 题意

`m × n` 网格，格子为五种之一：`S` 起点（恰好一个）、`L` 垃圾（至多 10 个）、`R` 能量重置区（踩上去能量回满，可重复用）、`X` 障碍、`.` 空地。每走一格耗 1 点能量，能量为 0 时只有站在 `R` 上才能继续。求收齐所有垃圾的**最少步数**，不可能则返回 `-1`。

```
输入: classroom = ["S.", "XL"], energy = 2
输出: 2        （绕开 X，两步吃到 L）

输入: classroom = ["LS", "RL"], energy = 4
输出: 3        （吃 L → 踩 R 回满 → 吃第二个 L）

输入: classroom = ["L.S", "RXL"], energy = 3
输出: -1
```

约束：`m, n <= 20`，`energy <= 50`，**`L` 至多 10 个**——这是状态压缩的信号。

---

## 思路：状态 = (位置, 垃圾掩码)，BFS + 能量支配剪枝

`L ≤ 10` 意味着收集状态可以用 10 位掩码表示（`1 << 10 = 1024` 种）。BFS 状态为 `(x, y, mask)`，每步四方向扩展，边权恒为 1，首次弹出 `mask == full` 的状态就是最优解。

能量不进状态 key，而是做**支配剪枝**：`bestEnergy[x][y][mask]` 记录到达同一位置、同一收集状态时的最大剩余能量。新状态能量**严格更大**才入队——同位同掩码下，能量低的状态能走的路，能量高的都能走，前者被完全支配，剪掉不影响最优性。

## 解法：BFS + bestEnergy 剪枝

```cpp
class Solution {
public:
    int minMoves(vector<string>& classroom, int energy) {
        int m = classroom.size(), n = classroom[0].size();

        // 给每个 L 分配唯一 bit 位，定位 S
        vector<vector<int>> id(m, vector<int>(n, 0));
        int sx = 0, sy = 0, cnt = 0;
        for (int i = 0; i < m; ++i) {
            for (int j = 0; j < n; ++j) {
                if (classroom[i][j] == 'S') { sx = i; sy = j; }
                else if (classroom[i][j] == 'L') { id[i][j] = 1 << cnt; ++cnt; }
            }
        }

        int full = 1 << cnt;
        vector<vector<vector<int>>> bestEnergy(
            m, vector<vector<int>>(n, vector<int>(full, -1)));
        bestEnergy[sx][sy][0] = energy;

        struct State { int x, y, mask, e, steps; };
        queue<State> q;
        q.push({sx, sy, 0, energy, 0});

        const int dx[4] = {0, 1, 0, -1};
        const int dy[4] = {1, 0, -1, 0};

        while (!q.empty()) {
            State t = q.front(); q.pop();

            if (t.mask == full - 1) return t.steps;  // 收齐
            if (t.e == 0) continue;                  // 没电且不在 R 上，走不动

            for (int k = 0; k < 4; ++k) {
                int nx = t.x + dx[k], ny = t.y + dy[k];
                if (nx < 0 || nx >= m || ny < 0 || ny >= n ||
                    classroom[nx][ny] == 'X') continue;

                // 踩 R 回满，否则耗 1；踩 L 把对应 bit 置 1
                int ne = (classroom[nx][ny] == 'R') ? energy : t.e - 1;
                int nmask = t.mask | id[nx][ny];

                // 支配剪枝：只保留能量更高的同位同掩码状态
                if (ne > bestEnergy[nx][ny][nmask]) {
                    bestEnergy[nx][ny][nmask] = ne;
                    q.push({nx, ny, nmask, ne, t.steps + 1});
                }
            }
        }
        return -1;
    }
};
```

## 核心理解

### 1. 为什么普通 BFS 就够，不需要 Dijkstra

所有移动代价都是 1 步——能量只是**可行性约束**（没电走不了），不是**代价**（踩 R 不花步数）。边权全 1，FIFO 队列弹出顺序即步数非降序，首次弹出目标态必然最优。只有"不同动作代价不同"时才需要堆。

### 2. 能量为什么不进 visited key

标准写法是 `visited[x][y][mask][e]` 精确去重。但同一 `(x, y, mask)` 下能量是**全序可比较**的：e=5 的状态能到的后续，e=3 的状态全是其子集。用 `bestEnergy` 只留最大值，状态数从 `m·n·2^cnt·(energy+1)` 压到 `m·n·2^cnt`——20×20 网格、10 个 L 时是 40 万对 2000 万+ 的差别。这是"支配关系替代精确去重"的典型：**当一个维度单调可比较时，只保留最优值**。

### 3. 三个判断的顺序不能乱

弹出时先判 `mask == full - 1`（收齐即返回，**哪怕能量是 0**——不需要再走了），再判 `e == 0`（走不动才跳过）。反过来会把"最后一步恰好耗尽能量收齐"的合法解漏掉。扩展时同理：先算出 `ne`（踩 R 回满发生在落地瞬间），再入队，所以队列里**永远不会出现 R 格上 e=0 的状态**。

### 4. `1 << cnt` 位掩码的老规矩

`cnt = 0`（没有 L）时 `full = 1`，初始 mask = 0 = full - 1，首次弹出直接返回 0——边界自然闭合。掩码题常见坑（`full` 写成 `1 << cnt - 1` 优先级错误、`int` 位移溢出）这里都不存在，但值得每次写的时候过一遍。

## 复杂度

| | 时间 | 空间 |
|--|------|------|
| BFS + 支配剪枝 | O(m·n·2^cnt·4) | O(m·n·2^cnt) |

最坏 20×20×1024 ≈ 41 万状态，每状态 4 方向，轻松可过。

验证：对拍一个 `visited[x][y][mask][e]` **精确去重、零剪枝**的朴素 BFS oracle。官方 3 个样例 + 手工边界（无 L、能量恰好 1、障碍堵死）+ 600 组随机小网格（≤4×4，L ≤ 4，energy ≤ 5，R/X 随机分布），**606 条断言全过**。

---

## 踩坑点 / 注意点

- ❌ **把能量当 visited 维度精确去重**。见核心理解 2——能 AC 但状态数多一个 `energy` 因子，且违背了"单调维度取最优"的剪枝直觉。
- ❌ **先判 `e == 0` 再判收齐**。最后一步踩着 0 能量收齐全部垃圾是合法的（样例 1 就是 e=0 时收齐），顺序反了会漏解。
- ❌ **踩 R 写成 `ne = min(energy, t.e - 1 + energy)` 之类的累加**。R 是**重置**不是回复，落地即满，与当前能量无关。
- ❌ **给 L 编号时 `id` 用 `cnt++` 当值存**而不是 `1 << cnt++`。`mask | id` 需要的是位不是序号。
- ⚠️ **剪枝条件必须是严格大于 `>`**。写 `>=` 会让同能量状态反复入队，最坏退化成指数级——同一个 `(x,y,mask,e)` 状态无需处理第二次。
