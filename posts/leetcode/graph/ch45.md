# 移除可疑方法（3310. Remove Methods From Project）

## 题意

项目有 `n` 个方法（编号 `0 ~ n-1`），`invocations[i] = [a, b]` 表示方法 `a` 调用方法 `b`。方法 `k` 有 bug，**`k` 以及被它直接或间接调用的所有方法都是可疑方法**，需要移除。

但有个限制：**只有当不存在"组外方法调用组内方法"时，可疑方法组才能被移除**；只要存在一条这样的调用边，就一个都不删。

```
输入: n = 4, k = 1, invocations = [[1,2],[0,1],[3,2]]
输出: [0,1,2,3]
解释: 可疑方法是 1 和 2，但 3→2、0→1 是组外调用组内，不能删。

输入: n = 5, k = 0, invocations = [[1,2],[0,2],[0,1],[3,4]]
输出: [3,4]
解释: 0、1、2 可疑，没有组外调用指向它们，可以删。

输入: n = 3, k = 2, invocations = [[1,2],[0,1],[2,0]]
输出: []
解释: 全部可疑，全部删除。
```

约束：`1 <= n <= 10⁵`，`0 <= invocations.length <= 2×10⁵`。

---

## 思路

拆解成两步：

1. **求可疑集合**：从 `k` 出发沿调用边 BFS，能到达的都是可疑方法。
2. **判定能否删除**：扫一遍 `invocations`，若存在边 `a → b` 满足 `b` 可疑而 `a` 不可疑，说明有组外方法调用组内——一个都不能删，返回全部方法；否则删除所有可疑方法。

第二步不需要额外的图遍历：可疑集合已经求出，逐条边检查两个端点的标记即可。

---

## 解法一：BFS + 出队时标记

```cpp
class Solution {
public:
    vector<int> remainingMethods(int n, int k,
                                 vector<vector<int>>& invocations) {
        vector<vector<int>> net(n);
        for (const auto invocation : invocations) {
            net[invocation[0]].push_back(invocation[1]);
        }

        vector<bool> visted(n, false);
        queue<int> q;
        q.push(k);
        while (!q.empty()) {
            int size = q.size();
            for (int i = 0; i < size; i++) {
                auto cur = q.front();
                q.pop();
                visted[cur] = true;
                for (const auto& next : net[cur]) {
                    if (!visted[next]) {
                        q.push(next);
                    }
                }
            }
        }

        for (const auto invocation : invocations) {
            if (visted[invocation[1]] && !visted[invocation[0]]) {
                vector<int> all(n);
                iota(all.begin(), all.end(), 0); // 填充 0, 1, 2, ..., n-1
                return all;
            }
        }

        vector<int> result;
        for (int i = 0; i < n; i++) {
            if (!visted[i]) {
                result.push_back(i);
            }
        }
        return result;
    }
};
```

## 解法二：入队时标记（优化版）

```cpp
class Solution {
public:
    vector<int> remainingMethods(int n, int k,
                                 vector<vector<int>>& invocations) {
        vector<vector<int>> net(n);
        for (const auto& invocation : invocations) {
            net[invocation[0]].push_back(invocation[1]);
        }

        vector<bool> visited(n, false);
        queue<int> q;
        q.push(k);
        visited[k] = true; // 标记起点，避免重复入队
        while (!q.empty()) {
            auto cur = q.front();
            q.pop();
            for (const auto& next : net[cur]) {
                if (!visited[next]) {
                    visited[next] = true; // 入队时立即标记，减少重复判断
                    q.push(next);
                }
            }
        }

        // 检查是否有外部方法调用了可疑方法
        for (const auto& invocation : invocations) {
            if (visited[invocation[1]] && !visited[invocation[0]]) {
                vector<int> all(n);
                iota(all.begin(), all.end(), 0);
                return all;
            }
        }

        vector<int> result;
        for (int i = 0; i < n; i++) {
            if (!visited[i]) {
                result.push_back(i);
            }
        }
        return result;
    }
};
```

## 关键细节

### 1. 入队标记 vs 出队标记

解法一在**出队时**才标记 `visited`，同一个节点在标记前可能被多条边重复入队（比如菱形图里两条路径汇到同一节点），队列里堆着重复节点，白白多弹出、多判几次。解法二在**入队时**立即标记（起点 `k` 也要先标上），每个节点恰好入队一次，这是 BFS 的标准写法。本题数据范围下两版都能过，但后者少了重复入队的开销。

### 2. 为什么扫一遍边就能判定

"能否删除"的充要条件是不存在组外→组内的调用边。可疑集合求出后，`visited[b] && !visited[a]` 精确对应这个条件，O(m) 扫一遍即可，不用再做一次反向 BFS。

### 3. `iota` 构造全量数组

不能删除时返回 `[0, 1, ..., n-1]`，`iota(all.begin(), all.end(), 0)` 一行填充，比循环 `push_back` 简洁（在 `<numeric>` 头文件里）。

### 4. range-for 里的拷贝

解法一的 `for (const auto invocation : invocations)` 按值拷贝，每条边复制一个 `vector<int>`。改成 `const auto&` 零成本，是范围循环的默认正确姿势。

| 空间 | O(n + m) | 邻接表 + visited |

## 踩坑点 / 注意点

- ❌ **读错题：以为是删"k 到不了的"**。删除对象是被 k **直接或间接调用**的方法（沿边向下游走），不是不可达点。
- ❌ **以为可以删一部分**。题目要求要么整组删、要么一个不删——存在组外调用时返回的是**全部** `n` 个方法，不是只保留被外部调用的那几个。
- ❌ **起点忘记标记**（入队标记写法里）。`visited[k] = true` 漏掉的话，`k` 可能被其他可疑节点重新入队。
- ❌ **分层 BFS 的 `size` 循环**。这题不需要层数信息，直接 `while (!q.empty())` 逐节点弹出即可，套一层 `size` 循环是无效模板（解法二已去掉）。
