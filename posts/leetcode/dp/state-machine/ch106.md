# K 条不重叠线段的方案数（1621. Number of Sets of K Non-Overlapping Line Segments）

## 题意

数轴上 `n` 个点 `0 ~ n-1`，要选出**恰好 k 条**线段，每条线段的端点都在这些点上，线段之间不重叠（**允许端点相触**，即一条的右端点可以是下一条的左端点）。求方案数，对 `1e9+7` 取模。

```
输入: n = 4, k = 2     输出: 5
输入: n = 3, k = 1     输出: 3
输入: n = 30, k = 7    输出: 796297179
```

- `2 <= n <= 1000`，`1 <= k <= n-1`

## 思路

先想清楚这题在数什么。一个方案就是 k 条线段 `(l₁,r₁), ..., (lₖ,rₖ)`，满足 `lᵢ < rᵢ` 且 `rᵢ <= lᵢ₊₁`（相触允许）。直接枚举线段组合是指数级的，`n, k <= 1000` 的规模摆明了要 DP，而且是**计数** DP，不是最优化。

难点只有一个：**"允许端点相触"**。不允许相触的话就是标准的"选 k 个不相交区间"计数；允许相触意味着一条的终点可以紧接下一条的起点，转移时这个边界处理不好，不是漏数就是重复数。下面三个解法的差别，本质上就是处理这件事的三种姿势。

## 解法一：状态机DP（开 / 关）

dp定义：dp[i][j][1/0]：已处理到点 i，已完成 j 条线段，当前状态开/关

从左往右扫点，通过记录状态信息来保存：现在有没有一条线段正开着。于是每个点上的状态是 `(已完成 j 条, 开/关)`，转移就四种：
- 关着继续关
- 开着继续开
- 开转关（这条线段到此结束，完成数 +1）
- 关转开（起一条新的）。相触的情形落在"同一点先关再开"上，所以同一轮里要先算完"关"再算"开"，顺序反了部分相交的方案就丢了。这个依赖顺序对于压缩dp的空间，改写成滚动数组至关重要。

```cpp
class Solution {
public:
    int numberOfSets(int n, int k) {
        const int MOD = 1e9 + 7;

        // dp[i][j][0]：处理到点 i，已完成 j 条线段，当前"关"
        // dp[i][j][1]：处理到点 i，已完成 j 条线段，当前"开"
        vector<vector<vector<long long>>> dp(n, vector<vector<long long>>(k + 1, vector<long long>(2, 0)));

        // 初始：第 0 个点，不开 或 开启第 1 条线段（完成 0 条）
        dp[0][0][0] = 1;
        dp[0][0][1] = 1;

        for (int i = 1; i < n; i++) {
            for (int j = 0; j <= k; j++) {
                // 先处理"关"状态，保证"先关"在"后开"之前完成

                // 0 -> 0：延续"关"
                dp[i][j][0] = (dp[i][j][0] + dp[i-1][j][0]) % MOD;

                // 1 -> 0：在点 i 关闭当前线段，完成一条
                if (j + 1 <= k) {
                    dp[i][j + 1][0] = (dp[i][j + 1][0] + dp[i-1][j][1]) % MOD;
                }

                // 再处理"开"状态，此时 dp[i][j][0] 已包含"同一点先关再开"的贡献

                // 0 -> 1：在点 i 开启一条新线段（j 不变）
                // 注意：这里的 dp[i][j][0] 已经是"关"完成之后的值，蕴含了端点重合的情况
                dp[i][j][1] = (dp[i][j][1] + dp[i][j][0]) % MOD;

                // 1 -> 1：延续"开"
                dp[i][j][1] = (dp[i][j][1] + dp[i-1][j][1]) % MOD;
            }
        }

        return dp[n - 1][k][0];
    }
};
```

**关键在轮内顺序**。先算完"关"（`0→0` 和 `1→0`），再算"开"（`0→1`），这样 `0→1` 读到的 `dp[i][j][0]` 已经包含"在点 `i` 刚关闭一条"的方案，于是"在点 `i` 先关一条、紧接着开一条"被自然计入，且只计一次。如果把 `0→1` 的源改成 `dp[i-1][j][0]`，端点相触的方案就全丢了。注释里那句"先关在后开之前完成"是这版代码的灵魂。

## 解法二：计数 DP + 前缀和

换个切法，不关心"开没开着"，只盯每条的右端点。

dp 定义：`dp[i][j]`：在 `[0, j]` 这 `j+1` 个点上恰好放下 `i` 条线段的方案数

按"第 i 条的右端点是不是 j"分类：
- 不是 j：方案数等于 `dp[i][j-1]`
- 是 j：左端点 `l` 取 `0..j-1`，前 `i-1` 条收在 `[0, l]` 内即可（`r = l` 的相触恰好被允许），对 `l` 求和得到 `sum_{p=0}^{j-1} dp[i-1][p]`

求和部分是个前缀和，随 j 右移滚动累加，不用每层重算。相触在这里靠"求和一直包含到 `l`"自然覆盖。

```cpp
class Solution {
public:
    int numberOfSets(int n, int k) {
        const int MOD = 1e9 + 7;
        // dp[i][j]：在 [0, j] 这 j+1 个点上构造恰好 i 条线段的方案数
        vector<vector<long long>> dp(k + 1, vector<long long>(n, 0));

        // 边界：0 条线段时，任意点集都只有"不选"这一种方案
        for (int j = 0; j < n; j++) {
            dp[0][j] = 1;
        }

        for (int i = 1; i <= k; i++) {
            // prefix：累加 dp[i-1][p]，p 从 0 到 j-1，即 sum_{p=0}^{j-1} dp[i-1][p]
            long long prefix = 0;
            for (int j = 1; j < n; j++) {
                // 边遍历边累加上一层的 dp[i-1][j-1]，得到当前 j 所需前缀和
                prefix = (prefix + dp[i - 1][j - 1]) % MOD;
                // 情况1：最后一条线段右端点不是 j → dp[i][j-1]
                // 情况2：最后一条线段右端点是 j → prefix（即 sum_{p=0}^{j-1} dp[i-1][p]）
                dp[i][j] = (dp[i][j - 1] + prefix) % MOD;
            }
        }

        return dp[k][n - 1];
    }
};
```

**前缀和是这版的命门**。"右端点是 j"这一类对左端点 `l` 的求和，如果每来一个 j 就重算一遍 `sum_{p=0}^{j-1}`，复杂度就退化到 O(n²k)。代码里 `prefix` 每轮只加一个 `dp[i-1][j-1]`，O(1) 摊还，这是"分类求和式 DP"的标准优化动作。

## 解法三：滚动数组

纯粹的空间优化：解法二的第 `i` 层只读第 `i-1` 层，压掉第一维。两个数组各管一摊：
- `dp[j]`：当前层，前 `j+1` 个点恰好 `i` 条的方案数（定义同解法二）
- `prefixSums[j]`：上一层的前缀和 `sum_{p=0}^{j-1} dp_prev[p]`

递推式原封不动，但要小心哪半是当前层、哪半是上一层。

```cpp
class Solution {
public:
    int numberOfSets(int n, int k) {
        const int MOD = 1e9 + 7;
        // dp[j]: 在当前处理的点集上构造恰好 (i+1) 条线段时的方案数（滚动数组）
        // prefixSums[t]: 表示 sum_{p=0}^{t-1} dp_prev[p]，用于 O(1) 计算前缀和
        vector<int> dp(n, 1);            // i=0 时：0 条线段只有"不选"一种方案，dp[j]=1
        vector<int> prefixSums(n + 1, 0);

        // 初始化第一层（i=0）的前缀和
        for (int j = 0; j < n; j++) {
            prefixSums[j + 1] = (prefixSums[j] + dp[j]) % MOD;
        }

        // 逐层增加线段数 i（从 1 到 k）
        for (int i = 1; i <= k; i++) {
            dp[0] = 0;  // 没有任何点（j=0）时无法构造 i>0 条线段
            for (int j = 0; j < n; j++) {
                // dp[j] = 右端点不是 j 的方案 + 右端点是 j 的方案
                // 右端点是 j：sum_{p=0}^{j-1} dp_prev[p] 即 prefixSums[j]
                dp[j] = (dp[j - 1] + prefixSums[j]) % MOD;
            }
            // 更新本层（线段数 i）的前缀和，供下一层使用
            for (int j = 0; j < n; j++) {
                prefixSums[j + 1] = (prefixSums[j] + dp[j]) % MOD;
            }
        }

        return dp[n - 1];
    }
};
```

**两个数组各管一层**：`dp[j-1]` 是**本层**刚算好的（对应"右端点不是 j"），`prefixSums[j]` 是**上一层**的（对应"右端点是 j"）。内层循环从左往右，读 `dp[j-1]` 写 `dp[j]`，层间不串；每层结束再整体重建 `prefixSums`。

两个这版特有的坑：

- ❌ **忘记每层重置 `dp[0] = 0`**。`dp` 初始化为全 1（0 条线段的边界），进入 `i = 1` 层后 `dp[0]` 还是 1，但"1 条线段、只有 1 个点"的方案数应该是 0。漏掉这行，错误会沿 `dp[j] = dp[j-1] + ...` 一路污染整层。
- ⚠️ **`int` 是踩着线过的**。`prefixSums[j] + dp[j]` 最大约 `2 × 1e9`，刚好小于 `INT_MAX`，单次加法不溢出，但没有任何余量，模数稍大或连加两项就越界。自己写模板时一律 `long long`，别学这版省。

## 一个数学事实：答案就是 C(n+k-1, 2k)

答案恒等于 **C(n+k-1, 2k)**。组合直觉：k 条线段共 2k 个端点，"允许相触"意味着相邻端点可以重合，相当于在端点序列里允许"空隙为 0"，把每个空隙加 1 摊平后，就变成从 `n+k-1` 个位置里选 `2k` 个的标准组合。DP 是对的，但知道这个数字，检查答案时心里就有底了。

## 复杂度

| | 解法一 | 解法二 | 解法三 |
|--|--------|--------|--------|
| 时间 | O(nk) | O(nk) | O(nk) |
| 空间 | O(nk) | O(nk) | O(n) |

实际做题时推荐的路径：先想出解法二的分类（或解法一的状态机），确认对了再谈压缩空间。
