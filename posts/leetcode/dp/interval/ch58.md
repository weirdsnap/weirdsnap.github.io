# 石子游戏 II（1140. Stone Game II）

## 题意

`n` 堆石子排成一行，Alice 先手。每轮行动的玩家可以拿走**最前面 X 堆**，其中 `1 <= X <= 2M`（初始 `M = 1`）；拿完后 `M` 更新为 `max(M, X)`。双方都采取最优策略，求 Alice 最多能拿到多少石子。

```
输入: piles = [2,7,9,4,4]
输出: 10
解释: Alice 先拿 1 堆(M 变 1)，Bob 只能拿 1~2 堆...
      最优对局下 Alice 拿到 2 + 4 + 4 = 10

输入: piles = [1,2,3,4,5,100]
输出: 104
```

约束：`1 <= n <= 100`。

---

## 思路：净胜分 DP，状态加一维 M

沿用 486 / 877 的**净胜分定义**（自己 − 对手，见 [ch41](./blog.html?post=leetcode/dp/interval/ch41.md)、[ch57](./blog.html?post=leetcode/dp/interval/ch57.md)），但拿取范围受 `M` 控制，状态必须多带一维：

**`dp[i][m]` = 从第 `i` 堆开始、当前 `M = m` 时，当前行动玩家能取得的最大净胜分。**

转移：枚举本次拿 `x ∈ [1, 2m]` 堆，拿到 `sum = piles[i..i+x-1]`，之后对手面对 `dp[i+x][max(m, x)]`——角色互换，取负：

```
dp[i][m] = max over x of ( sum - dp[i+x][max(m, x)] )
dp[n][m] = 0  （没有石子了）
```

```cpp
class Solution {
public:
    int stoneGameII(vector<int>& piles) {
        int n = piles.size();
        vector<vector<int>> dp(n + 1, vector<int>(n + 1, INT_MIN));
        for (int i = n; i >= 0; i--) {
            for (int m = 1; m <= n; m++) {
                if (i == n) {
                    dp[i][m] = 0;
                } else {
                    int sum = 0;
                    for (int x = 1; x <= 2 * m; x++) {
                        if (i + x > n) break;
                        sum += piles[i + x - 1];
                        dp[i][m] = max(dp[i][m],
                            sum - dp[i + x][min(n, max(m, x))]);
                    }
                }
            }
        }
        return (dp[0][1] + accumulate(piles.begin(), piles.end(), 0)) / 2;
    }
};
```

**特点**：`sum` 在内层循环里增量累加，不用单独的前缀和数组；`i` 从大到小保证 `dp[i+x][·]` 已算好，`m` 维没有顺序要求（转移只依赖更大的 `i`，`max(m, x) >= m` 不构成环）。

---

## 关键细节

### 1. 返回值是净胜分，不是 Alice 的石子数

`dp[0][1]` 是 Alice − Bob 的差值。设总数为 `total`：

```
alice + bob = total
alice - bob = dp[0][1]
→ alice = (total + dp[0][1]) / 2
```

忘记换算直接返回 `dp[0][1]` 是这题最常见的 WA。`total + diff` 必为偶数（每堆石子对两者的贡献同奇偶），整除安全。

### 2. M 的上限可以截断到 n

`x <= 2m` 但还有 `i + x <= n`，所以当 `m >= n` 时拿取范围已经不再扩张——`m > n` 和 `m = n` 完全等价。`min(n, max(m, x))` 这个截断让 `dp` 只需开 `(n+1) × (n+1)`，否则数组要开到 `2n`。

### 3. INT_MIN 哨兵不会残留

`i < n` 时 `x = 1` 必然合法（`i + 1 <= n`），内层循环至少执行一次，每个 `dp[i][m]` 都会被更新。所以用 `INT_MIN` 初始化不需要额外的"是否访问过"判断。

---

## 复杂度

| 指标 | 值 |
|------|----|
| 状态数 | O(n²)（`i × m`） |
| 单状态转移 | O(2m) ≤ O(n) |
| 总时间 | **O(n³)**，`n = 100` 约 10⁶，很宽裕 |
| 空间 | O(n²) |

验证：300 组随机（`n ∈ [1,10]`）与记忆化搜索版完全一致；另测 Alice 得分恒在 `[0, total]` 内。702 条断言全过。

---

## 踩坑点 / 注意点

- ❌ **忘记角色互换取负**。写成 `sum + dp[i+x][...]` 就变成"同一个人一直拿"，和 486/877 的坑一模一样——净胜分定义下子问题的"当前玩家"是对手。
- ❌ **返回 `dp[0][1]`**。这是净胜分，必须用 `(total + diff) / 2` 换算成 Alice 的实际石子数。
- ❌ **M 更新规则写错**。是 `M = max(M, X)`，不是 `M = X` 也不是累加。
- ❌ **数组越界**。`max(m, x)` 可以到 `2n`，不截断的话 `dp` 要开更大；`min(n, ...)` 一步解决。
- ❌ **`m` 从 0 开始枚举**。`M` 初值为 1 且只增不减，`m = 0` 是永远不会到达的死状态，枚举它纯属浪费（虽然不影响正确性）。
