# 石子游戏（877. Stone Game）

## 题意

`n` 堆石子排成一行（`n` 为偶数，总数为奇数），两名玩家轮流从**两端**拿一堆，拿到石子总数多者胜。问先手是否必胜。

```
输入: piles = [5,3,4,5]
输出: true
解释: 先手拿 5，后手只能拿 5 或 4... 先手 10 : 7 获胜
```

约束：`n` 偶数，`2 <= n <= 500`，石子总数为奇数（保证无平局）。

---

## 思路一：区间 DP（净胜分定义）

这题和 486 预测赢家（[ch41](./blog.html?post=leetcode/dp/interval/ch41.md)）是同一个模型，状态定义一字不差：

**`dp[i][j]` = 在子数组 `piles[i..j]` 上，当前行动玩家能比对手多拿的最大净胜分**（自己 − 对手）。

转移的关键在**角色互换**：当前玩家拿走 `piles[i]` 后，轮到对手在 `[i+1, j]` 上行动，而此时 `dp[i+1][j]` 表示的是**对手**作为"当前玩家"能赢的净胜分——那正是我们的亏损。所以：

```
dp[i][j] = max(piles[i] - dp[i+1][j],   // 拿左端
               piles[j] - dp[i][j-1])   // 拿右端
```

压缩到一维，遍历方向和 486 完全相同（`i` 从大到小，`j` 从小到大）：

```cpp
class Solution {
public:
    bool stoneGame(vector<int>& piles) {
        int n = piles.size();
        vector<int> dp = piles;  // dp[i][i] = piles[i] 压缩进一维

        if (n % 2 == 0) return true;  // 偶数堆先手必胜，见思路二

        for (int i = n - 2; i >= 0; --i) {
            for (int j = i + 1; j < n; ++j) {
                dp[j] = max(piles[i] - dp[j], piles[j] - dp[j - 1]);
                //               dp[i+1][j]       dp[i][j-1]
            }
        }
        return dp[n - 1] >= 0;
    }
};
```

**这个定义为什么有意思**：一般博弈 DP 会写成 `dp[i][j][turn]` 显式带玩家维度，或者存"双方各自的得分"两个数组。净胜分定义把双方压进**一个数**——因为零和博弈里"对手的最优"取负就是"我的局面"，`turn` 维度被 `-` 号吸收了。状态数和转移数直接减半。

**特点**：`dp[i][i] = piles[i]`（只剩一堆直接拿走），`dp[n-1] >= 0` 即先手不败。代码里对奇数 `n` 也能跑，等于把原题推广成了"任意堆数"版本。

## 思路二：数学结论，O(1)

原题 `n` 必为偶数，这题其实可以一句 `return true`：

把下标按奇偶分成两组：`A = piles[0], piles[2], ...`，`B = piles[1], piles[3], ...`。**先手可以强行拿走其中任意一整组**：

1. 先手拿 `piles[0]`（A 组），暴露的两个端点 `piles[1]`、`piles[n-1]` 都是 B 组
2. 后手无论拿哪头，暴露的新端点必然是 A 组
3. 先手继续拿 A 组……最终先手拿光 A，后手拿光 B

所以先手开局前算一下 `sum(A)` 和 `sum(B)`，选大的那组执行即可。又因为总数是奇数，两组和不可能相等，**先手必然严格获胜**。DP 都不用写。

### 博弈题的通用心法：先想先手有没有必胜的法子

这题是"一分钟数学杀掉整道题"的典型。遇到博弈题，值得先花极低成本试探：题目是否留了**结构缺口**让先手白赢——偶数堆（配对策略）、对称局面（模仿策略）、Nim 型（异或非零）。走不通再退回 DP/搜索。对照组就是 486（[ch41](./blog.html?post=leetcode/dp/interval/ch41.md)）：同一个两端取数模型，但 `n` 任意、无必胜保证，论证走不通，才轮到净胜分 DP 出场。

## 复杂度

| 指标 | 区间 DP | 数学结论 |
|------|---------|----------|
| 时间 | O(n²) | O(n)（算一次分组和）或 O(1) |
| 空间 | O(n) 滚动 / O(n²) 朴素 | O(1) |

验证：奇数堆 300 组与暴力递归（无记忆化求净胜分）符号完全一致；偶数堆 300 组验证性质"先手净胜分 >= 0 恒成立"（暴力、纯 DP、提交版三方吻合）。1502 条断言全过。

## 踩坑点 / 注意点

- ❌ **状态定义存"当前玩家得分"而不是净胜分**。存单方得分的话转移时搞不清对手拿了多少，绕一圈还是会回到差值上——零和博弈直接定义差值最省事。
- ❌ **转移忘记取负**。`dp[i][j] = piles[i] + dp[i+1][j]` 是错的：递归子问题的"当前玩家"已经换成对手了，他的最优收益是你的亏损，必须是 `piles[i] - dp[i+1][j]`。
- ❌ **一维滚动时遍历方向写反**。`j` 从小到大才能保证 `dp[j-1]`（即 `dp[i][j-1]`）是本轮新值、`dp[j]`（即 `dp[i+1][j]`）是上一轮旧值——和 486、0-1 背包倒序是同一个"读旧值/读新值各就各位"的道理（见 [ch41](./blog.html?post=leetcode/dp/interval/ch41.md)）。
- ❌ **死磕 DP 没注意题面约束**。`n` 偶数 + 总数奇数直接给出 `return true` 的数学解。竞赛/面试里 DP 是稳妥解，但看出奇偶分组论证才是这题的出题意图。
