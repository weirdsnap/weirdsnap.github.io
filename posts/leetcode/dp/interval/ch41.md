# 预测赢家（486. Predict the Winner）

## 题意

给你一个非负整数数组 `nums`。两名玩家轮流从数组的**某一端**拿走一个数字，拿走的数字计入自己的总分，数组空了游戏结束。玩家 1 先手，两人都采取最优策略，判断玩家 1 能否获胜（**平局也算玩家 1 赢**）。

```
输入: nums = [1,5,2]
输出: false
解释: 玩家 1 拿 2，玩家 2 拿 5，玩家 1 拿 1。比分 3 : 5，玩家 1 输。
     玩家 1 先拿 1 也一样输。

输入: nums = [1,5,233,7]
输出: true
解释: 玩家 1 先拿 1，之后无论玩家 2 怎么选，玩家 1 都能拿到 233。
```

约束：`1 <= nums.length <= 20`。

---

## 思路

### 差分视角：把"双方比分"压成一个数

最直观的模拟要同时跟踪两个分数，状态很臃肿。换个视角：只维护**玩家 1 分数 − 玩家 2 分数**这一个差值。

引入 `turn ∈ {+1, -1}` 表示当前轮到谁：`+1` 是玩家 1，`-1` 是玩家 2。定义 `func(i, j, turn)` 为子游戏 `nums[i..j]` 对最终差值的贡献：

- 当前玩家拿 `nums[i]`：贡献 `nums[i] * turn`（玩家 1 拿是 +，玩家 2 拿是 −），剩余子问题轮到对方：`func(i+1, j, -turn)`；
- 当前玩家要让自己的收益最大。玩家 1 回合取 `max`，玩家 2 回合取 `min`——但用符号技巧可以一行写完：

```cpp
max(r1 * turn, r2 * turn) * turn
```

`turn = +1` 时就是 `max(r1, r2)`；`turn = -1` 时先取 `max(-r1, -r2)` 再翻回来，等价于 `min(r1, r2)`。一行代码统一了双方视角。

最终 `func(0, n-1, +1) >= 0` 即玩家 1 不输。

---

## 解法一：差分视角 + 递归（deducing this）

```cpp
class Solution {
public:
    bool predictTheWinner(vector<int>& nums) {
        auto func = [&](this auto&& self, int i, int j, int turn) -> int {
            if (i == j) return nums[i] * turn;

            int r1 = nums[i] * turn + self(i + 1, j, -turn);  // 拿左端
            int r2 = nums[j] * turn + self(i, j - 1, -turn);  // 拿右端
            return max(r1 * turn, r2 * turn) * turn;  // 符号技巧统一 max/min
        };

        return func(0, nums.size() - 1, 1) >= 0;
    }
};
```

**注意**：`this auto&& self` 是 C++23 deducing this 写法，递归调用 `self(...)` 零开销。递归 lambda 必须显式写返回类型 `-> int`，否则编译报 "deduced return type cannot be used before it is defined"——原理见 [Lambda 递归：三种写法与类型擦除](./blog.html?post=cpp/practices/lambda_01.md)。

## 解法二：区间 DP 递推

把差分视角写成递推形式：`dp[i][j]` 表示子数组 `nums[i..j]` 上**当前先手玩家 − 对方**的最大净胜分。当前玩家拿 `nums[i]` 后，对方在 `[i+1, j]` 上变成先手，能拿到 `dp[i+1][j]` 的净胜分，所以自己的净胜分是 `nums[i] - dp[i+1][j]`——每个玩家在自己回合都是"先手"，`turn` 被自然消掉了：

```cpp
class Solution {
public:
    bool predictTheWinner(vector<int>& nums) {
        int n = nums.size();
        // dp[i][j]: 在子数组 [i, j] 上，当前玩家能获得的最大净胜分
        vector<vector<int>> dp(n, vector<int>(n, 0));

        for (int i = 0; i < n; ++i)
            dp[i][i] = nums[i];  // 只剩一个数，当前玩家直接拿走

        for (int len = 2; len <= n; ++len) {       // 区间长度从小到大
            for (int i = 0; i + len - 1 < n; ++i) {
                int j = i + len - 1;
                dp[i][j] = max(nums[i] - dp[i+1][j], nums[j] - dp[i][j-1]);
            }
        }

        return dp[0][n-1] >= 0;
    }
};
```

**注意**：区间 DP 的经典填表顺序——按**区间长度**从小到大枚举，保证 `dp[i+1][j]` 和 `dp[i][j-1]`（长度都是 `len-1`）在计算 `dp[i][j]` 时已就绪。

## 解法三：一维空间优化

`dp[i][j]` 只依赖下一行的 `dp[i+1][j]` 和同行左侧的 `dp[i][j-1]`，可以压成一维。关键在遍历方向：**`i` 从大到小、`j` 从小到大**——

- 内层循环计算 `dp[j]` 时，旧值 `dp[j]` 还是上一轮（`i+1` 行）留下的，正是 `dp[i+1][j]`；
- `dp[j-1]` 本轮刚被更新过，正是 `dp[i][j-1]`。

```cpp
class Solution {
public:
    bool predictTheWinner(vector<int>& nums) {
        int n = nums.size();
        vector<int> dp = nums; // 初始化为 dp[i][i] = nums[i]

        for (int i = n - 2; i >= 0; --i) {    // i 从大到小
            for (int j = i + 1; j < n; ++j) { // j 从小到大
                dp[j] = max(nums[i] - dp[j], nums[j] - dp[j - 1]);
                //               dp[i+1][j]       dp[i][j-1]
            }
        }

        return dp[n - 1] >= 0;
    }
};
```

**注意**：这和 0-1 背包倒序枚举是同一个道理——压缩维度后，必须用遍历方向保证"读到的旧值/新值"各就各位。这里 `j` 如果也从大到小，`dp[j-1]` 读到的就是上一轮的旧值 `dp[i+1][j-1]`，结果就错了。

## 关键细节

### 1. 为什么不需要记忆化也能过

纯递归的状态转移是二叉的，复杂度 O(2ⁿ)。但本题 `n ≤ 20`，2²⁰ ≈ 10⁶，完全在时限内。

### 2. 要记忆化的话，状态只有 (i, j)

`turn` 看似是第三维状态，其实由已拿走的步数决定：拿了 `n - (j - i + 1)` 步，奇偶性固定，`turn` 也就固定。所以解法一记忆化只需 `dp[i][j]` 一张二维表，复杂度降到 O(n²)——解法二的递推形式正是这么来的。

### 3. 为什么是 `>= 0` 而不是 `> 0`

题意明确平局算玩家 1 赢，差值为 0 也要返回 `true`。

## 复杂度

| | 解法一（递归） | 解法二（区间 DP） | 解法三（一维优化） |
|--|----------------|-------------------|---------------------|
| 时间 | O(2ⁿ)，n ≤ 20 可过 | O(n²) | O(n²) |
| 空间 | O(n) 递归栈 | O(n²) | **O(n)** |

## 踩坑点 / 注意点

- ❌ **子问题忘记翻转 `turn`**。写成 `self(i + 1, j, turn)` 就变成"同一个人一直拿"，结果完全错误。
- ❌ **玩家 2 回合也取 `max`**。双方立场相反，要么用符号技巧 `max(r1*turn, r2*turn)*turn`，要么老老实实写 `if` 分支，漏掉就是经典错法。
- ❌ **平局判成输**。返回值是 `>= 0`，不是 `> 0`。
