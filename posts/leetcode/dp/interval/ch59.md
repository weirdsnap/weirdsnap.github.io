# 石子游戏 III（1406. Stone Game III）

## 题意

`n` 堆石子排成一行，每堆分值**可以为负**。Alice 先手，轮流从最前面拿 **1、2 或 3 堆**，拿到手就累加对应分值。双方都最优，返回 `"Alice"` / `"Bob"` / `"Tie"`。

```
输入: stoneValue = [1,2,3,7]
输出: "Bob"

输入: stoneValue = [1,2,3,-9]
输出: "Alice"   ← 负分值让"多拿"不一定是好事

输入: stoneValue = [1,2,3,6]
输出: "Tie"
```

约束：`1 <= n <= 5 * 10⁴`，`stoneValue[i] ∈ [-1000, 1000]`。

---

## 思路：净胜分 + 记忆化搜索

石子游戏家族的第四篇（[ch41](./blog.html?post=leetcode/dp/interval/ch41.md) 486、[ch57](./blog.html?post=leetcode/dp/interval/ch57.md) 877、[ch58](./blog.html?post=leetcode/dp/interval/ch58.md) 1140），净胜分定义不变：

**`func(i)` = 从第 `i` 堆开始，当前行动玩家的最大净胜分（自己 − 对手）。**

拿 `k` 堆（`k ∈ {1,2,3}`），得 `sum = stoneValue[i..i+k-1]`，之后对手面对 `func(i+k)`，取负：

```
func(i) = max over k of ( sum - func(i+k) )
func(n) = 0
```

这题**一维状态就够**——没有 1140 的 `M` 维度，拿取上限恒为 3。

```cpp
class Solution {
public:
    string stoneGameIII(vector<int>& stoneValue) {
        const int n = stoneValue.size();
        vector<int> dp(n + 1, -1);  // -1 = 未计算

        auto func = [&](this auto&& self, int i) -> int {
            if (i >= n) return 0;
            if (dp[i] == -1) {
                int best = INT_MIN, sum = 0;
                for (int k = 1; k < 4 && i + k <= n; k++) {
                    sum += stoneValue[i + k - 1];   // 增量累加，不用内层 while
                    best = max(best, sum - self(i + k));
                }
                dp[i] = best;
            }
            return dp[i];
        };

        int total = func(0);
        return total > 0 ? "Alice" : (total == 0 ? "Tie" : "Bob");
    }
};
```

**特点**：相比提交初版做了两处顺手优化——内层 `while` 重算累加改成 `sum` 增量累加，`vector<int> result` + `ranges::max` 改成循环内直接 `max`。逻辑不变。

### 变体：哨兵修正 + 后缀和

针对关键细节 1 的哨兵撞车问题，修正版把哨兵换成 `INT_MIN / 2`（净胜分绝对值上限 `5×10⁴ × 1000 = 5×10⁷`，远撞不上），并预计算后缀和数组让"拿 k 堆的得分"变成 O(1) 的差值查询：

```cpp
const int n = stoneValue.size();
vector<int> dp(n + 1, INT_MIN / 2);   // 干净哨兵

vector<int> suffix(n + 1, 0);         // suffix[i] = stoneValue[i..n-1] 的和
for (int i = n - 1; i >= 0; --i) suffix[i] = suffix[i + 1] + stoneValue[i];

auto func = [&](this auto&& self, int i) -> int {
    if (i >= n) return 0;
    if (dp[i] == INT_MIN / 2) {
        for (int k = 1; k <= 3 && i + k <= n; ++k) {
            int gain = suffix[i] - suffix[i + k];   // O(1) 拿走 k 堆的得分
            dp[i] = max(dp[i], gain - self(i + k));
        }
    }
    return dp[i];
};
```

本题 `k <= 3`，增量累加和后缀和差别不大；但如果拿取上限变成参数（比如 1140 的 `2M`），后缀和就是标配了。

## 三步走的最后一步：自底向上递推

按 DP 通用路径（`_plan.md` 导读：DFS → 记忆化 → 递推），观察到 `func(i)` 只依赖 `i+1..i+3`，拓扑序就是 `i` 从大到小：

```cpp
class SolutionDp {
public:
    string stoneGameIII(vector<int>& stoneValue) {
        const int n = stoneValue.size();
        vector<int> dp(n + 1, 0);  // dp[n] = 0 天然边界
        for (int i = n - 1; i >= 0; i--) {
            int best = INT_MIN, sum = 0;
            for (int k = 1; k < 4 && i + k <= n; k++) {
                sum += stoneValue[i + k - 1];
                best = max(best, sum - dp[i + k]);
            }
            dp[i] = best;
        }
        return dp[0] > 0 ? "Alice" : (dp[0] == 0 ? "Tie" : "Bob");
    }
};
```

**特点**：无递归、无哨兵问题（`dp` 全部真实填出），`n = 5×10⁴` 时 O(3n) 轻松过。依赖只到 `i+3`，理论上还能压成 4 个变量的滚动窗口，但 O(n) 空间已经足够，没必要。

### 变体：多开 3 格，消除越界判断

递推版里 `i + k <= n` 的边界检查可以用**数组右侧多开 3 个 0** 消掉：`i + k > n` 时 `running` 不再累加（等价于拿了剩余全部），`dp[i + k]` 读到 `dp[n..n+2]` 的 0（等价于"对手面对空局面"），数学上和显式判断完全一致：

```cpp
vector<int> dp(n + 3, 0);   // dp[n..n+2] = 0 充当边界
for (int i = n - 1; i >= 0; --i) {
    int running = 0, best = INT_MIN;
    for (int k = 1; k <= 3; ++k) {
        if (i + k - 1 < n) running += stoneValue[i + k - 1];  // 只有这里还要判断
        best = max(best, running - dp[i + k]);                // 读 dp 不再判断
    }
    dp[i] = best;
}
```

**特点**：和 84 题（[ch24](./blog.html?post=leetcode/stack/ch24.md)）末尾加哨兵柱是同一个思路——**用填充位把边界情况吸进主循环**，代码主干不分叉。

## 关键细节

### 1. 哨兵 `-1` 和合法净胜分撞车

这题分值**可以为负**，净胜分 `-1` 是合法值（如 `[-5, 1]` 的子状态）。用 `-1` 当"未计算"标记不会算错（撞上只是重算一次，子状态已缓存所以代价可控），但哨兵不干净：**记忆化失效的判断和真实值混在一起**，换个约束（比如分值范围更大、重算链更长）就可能退化。稳妥写法是 `INT_MIN / 2`（解法一变体采用的修法）或 `std::optional<int>`。

### 2. Tie 是真实存在的结果

1140 里返回值要换算 Alice 得分，这题直接判净胜分符号即可，但**平局单独一支**不能漏：`> 0` Alice，`< 0` Bob，`== 0` Tie。三目嵌套 `total > 0 ? "Alice" : (total == 0 ? "Tie" : "Bob")` 顺序无所谓，分支必须齐。

### 3. 负分值改变了"贪心直觉"

分值全正时"能拿就拿最多"似乎划算；有负数后拿得多可能是在帮对手清掉负分（`[1,2,3,-9]` 里 Alice 赢正是因为 Bob 被迫接盘 `-9`）。直觉不可靠，老老实实 DP。

## 复杂度

| 指标 | 记忆化搜索 | 自底向上递推 | 暴力递归 |
|------|-----------|--------------|----------|
| 时间 | O(3n) = O(n) | O(n) | O(3ⁿ) |
| 空间 | O(n) + 递归栈 | O(n) | O(n) 递归栈 |

验证：记忆化初版 / 哨兵修正+后缀和变体 / 递推版 / 多开 3 格变体 / 无记忆化暴力，五方对拍 300 组（含负分值）完全一致；另测了净胜分恰为 `-1` 的哨兵撞车用例。g++-14 下 1211 条断言全过（Apple clang 无 deducing this，宏裁剪记忆化两版后 603 条全过）。

## 踩坑点 / 注意点

- ❌ **哨兵选 `-1`**。合法净胜分包含 `-1`，撞车后只是"不错但脆弱"，见关键细节 1。
- ❌ **漏掉 Tie 分支**。正负之外的 0 是独立结果。
- ❌ **内层 while 重复累加**。`k` 每加 1 就从头加一遍，O(3²) 常数；增量 `sum +=` 是 O(3)。本题规模下都能过，但后者显然更干净。
- ❌ **角色互换取负漏掉**。`sum + self(i + k)` 又变成"一个人一直拿"——家族传统坑，第四遍了。
