# 石子游戏 V（1563. Stone Game V）

## 题意

一行 `n` 堆正分值石子。每轮当前玩家把当前行**切成两个非空段**：

- 两段和不等：**和小的那段保留**（另一段丢弃），玩家得分 += 小段和
- 两段和相等：**切的人自己选**保留哪段，得分 += 段和

游戏在保留段上继续，直到只剩一堆。Alice 先手，求她最多能拿多少分。

```
输入: stoneValue = [6,2,3,4,5,5]
输出: 18

输入: stoneValue = [7,7,7,7,7,7,7]
输出: 28

输入: stoneValue = [4]
输出: 0
```

约束：`1 <= n <= 500`。

---

## 思路：区间 DP

**`dp[i][j]` = 区间 `stoneValue[i..j]` 上能获得的最大总分。** 长度 1 得 0（无法再切）。

转移：枚举切点 `k ∈ [i, j)`（`k` 归左段），用前缀和 O(1) 拿两段和：

```
leftSum = pre[k+1] - pre[i],  rightSum = pre[j+1] - pre[k+1]

leftSum >  rightSum → 得分 = rightSum + dp[k+1][j]   （保留右段）
leftSum <  rightSum → 得分 = leftSum  + dp[i][k]     （保留左段）
leftSum == rightSum → 得分 = leftSum + max(dp[i][k], dp[k+1][j])  （任选）
```

```cpp
class Solution {
public:
    int stoneGameV(vector<int>& stoneValue) {
        const int n = stoneValue.size();
        vector<vector<int>> dp(n + 1, vector<int>(n + 1, 0));

        vector<int> pre(n + 1, 0);
        for (int i = 0; i < n; i++) pre[i + 1] = pre[i] + stoneValue[i];

        for (int len = 2; len <= n; len++) {
            for (int i = 0; i + len <= n; i++) {
                int j = i + len - 1;
                for (int k = i; k < j; k++) {
                    int leftSum  = pre[k + 1] - pre[i];
                    int rightSum = pre[j + 1] - pre[k + 1];
                    int temp;
                    if (leftSum > rightSum) {
                        temp = rightSum + dp[k + 1][j];
                    } else if (leftSum < rightSum) {
                        temp = leftSum + dp[i][k];
                    } else {
                        temp = leftSum + max(dp[i][k], dp[k + 1][j]);
                    }
                    dp[i][j] = max(dp[i][j], temp);
                }
            }
        }
        return dp[0][n - 1];
    }
};
```

**特点**：`len` 从小到大枚举——子问题 `[i,k]`、`[k+1,j]` 都比 `[i,j]` 短，区间长度就是天然拓扑序，不用记忆化也不用管方向。

### 写法变体：半开区间 `[i, j)` + 双指针方向

`len` 枚举也可以换成 486 一维滚动（[ch41](./blog.html?post=leetcode/dp/interval/ch41.md)）同款的下标方向枚举：

```cpp
for (int i = n - 2; i >= 0; i--) {
    for (int j = i + 2; j <= n; j++) {    // 区间 [i, j)，长度 >= 2
        for (int k = i + 1; k < j; k++) { // 切点：左 [i,k)，右 [k,j)
            int leftSum  = pre[k] - pre[i];
            int rightSum = pre[j] - pre[k];
            int temp;
            if (leftSum > rightSum)      temp = rightSum + dp[k][j];
            else if (leftSum < rightSum) temp = leftSum + dp[i][k];
            else temp = leftSum + max(dp[i][k], dp[k][j]);
            dp[i][j] = max(dp[i][j], temp);
        }
    }
}
return dp[0][n];
```

方向为什么对：转移读 `dp[i][k]`（同 `i`、更小的 `k < j`——`j` 升序保证已算）和 `dp[k][j]`（更大的 `k > i`——`i` 降序保证已算）。两个方向各自服务一个读操作，和 ch41 里"`i` 从大到小、`j` 从小到大"是同一套逻辑。

半开区间和前缀和是绝配：`[i, j)` 的和就是 `pre[j] - pre[i]`，没有 `+1/-1` 的噪音，切点 `k` 直接当边界用（左 `[i,k)`、右 `[k,j)`），代码里几乎看不到下标修正。

## 核心理解：为什么这题没有"角色互换取负"

家族前几篇的净胜分定义（自己 − 对手）在这里**不需要**，因为对抗性被规则吸收了：

- 486/1140/1406：对手在自己的回合有**自由选择**，他的最优是你的亏损，所以转移要取负
- 本题：保留哪段由**分段和的大小决定**（确定性规则），对手没有任何自由；唯一的选择权在切的人手里（选切点 `k`，平局时选边）

于是双方追的是**同一个得分口径**，`dp[i][j]` 就是"这段区间轮到谁谁就能拿到的最大分"，状态定义与玩家身份无关。这是博弈题的第三种形态：877 数学可杀 → 486/1140/1406 净胜分对抗 → 1510 布尔输赢 → **本题：规则确定性，只剩单方最优**。

## 关键细节

### 1. 切点约定：k 归左段

`k ∈ [i, j)`，左段 `[i, k]`、右段 `[k+1, j]`。`k` 取不到 `j`，保证右段非空；两段不重不漏。写成 `k <= j` 会出现空右段，`pre[j+1] - pre[j+1] = 0` 的"和 0 段"会污染比较。

### 2. 前缀和下标

`pre[i]` 是前 `i` 个元素的和，`[i, k]` 的和是 `pre[k+1] - pre[i]`。边界想错一位，等和判断就全错。

### 3. 平局分支的 max

等和时切的人选边，`max(dp[i][k], dp[k+1][j])` 不能漏——漏了等于白白扔掉一半选择权。验证里专门构造了 `{3,3,3,3}`（等和分裂 `[3,3]|[3,3]`，答案 `6 + 3 = 9`）盯住这个分支。

## 解法二：O(n²) 优化——分界点的单调性复用

O(n³) 的三重循环里有浪费：**分值全正**，切点 `k` 右移时 `leftSum` 递增、`rightSum` 递减，所以"左段和 ≤ 总和一半"的切点构成一个**前缀** `[i, p]`，右保留集合是后缀 `[q, j-1]`。更关键的是，区间 `[i, j]` 向右扩张一格时，`leftSum(k)` 不变、`total` 变大，于是 `p` 只会**继续右移**——之前比较过的大小关系全部有效，不用重新扫。

两个方向的候选分别用滚动最大值维护：

- 左保留候选 `leftSum + dp[i][k]` = `(pre[k+1] + dp[i][k]) - pre[i]`：行固定 `i`、`j` 递增时，`p` 单调右移，每纳入一个新 `k` 就把 `pre[k+1] + dp[i][k]` 并入 `best1`
- 右保留候选 `rightSum + dp[k+1][j]` = `pre[j+1] + (dp[k+1][j] - pre[k+1])`：列固定 `j`、`i` 递减时，所有切点的 `2·leftSum - total` 同步增加 `stoneValue[i]`（整体同步偏移，不改变相互大小），`q` 单调左移，新纳入的 `k` 并入 `best2`

```cpp
// len 从小到大；每个 len 内先行扫描（i 升序）再列扫描（i 降序）
for (int len = 2; len <= n; len++) {
    // 行扫描：推进每行的分界指针 p[i]，更新左保留最优
    for (int i = 0; i + len <= n; i++) {
        int j = i + len - 1;
        long long total = pre[j + 1] - pre[i];
        while (p[i] + 1 <= j - 1 && 2 * (pre[p[i] + 2] - pre[i]) <= total) {
            p[i]++;
            best1[i] = max(best1[i], pre[p[i] + 1] + dp[i][p[i]]);
        }
        if (p[i] >= i) c1[i] = best1[i] - pre[i];
    }
    // 列扫描：推进每列的分界指针 q[j]，更新右保留最优
    for (int i = n - len; i >= 0; i--) {
        int j = i + len - 1;
        long long total = pre[j + 1] - pre[i];
        while (q[j] - 1 >= i && 2 * (pre[q[j]] - pre[i]) >= total) {
            q[j]--;
            best2[j] = max(best2[j], dp[q[j] + 1][j] - pre[q[j] + 1]);
        }
        if (q[j] <= j - 1) c2[i] = pre[j + 1] + best2[j];
    }
    for (int i = 0; i + len <= n; i++)
        dp[i][i + len - 1] = max(c1[i], c2[i]);
}
```

每个行指针 `p[i]` 总共右移不超过 `n` 次，每个列指针 `q[j]` 总共左移不超过 `n` 次——`len` 循环里每个区间只做 O(1) 均摊工作，总复杂度 O(n²)。等和切点同时落在两个集合里（左集 `≤ total/2`、右集 `≥ total/2`），平局分支被天然覆盖。

**注意**：单调性依赖分值**全正**（约束保证 `stoneValue[i] ≥ 1`）。有负值时 `p`/`q` 不再单调，这个优化直接失效，退回 O(n³)。

## 复杂度

| 指标 | 解法一（枚举切点） | 解法二（单调分界点） |
|------|-------------------|----------------------|
| 时间 | O(n³)：`n = 500` 约 2×10⁷，可过 | **O(n²)**：指针均摊 O(n) |
| 空间 | O(n²) | O(n²) |

验证：枚举版 / 半开区间版 / O(n²) 版 / 无记忆化暴力四方对拍——`n ≤ 12` 对暴力 300 组、`n ≤ 120` 对枚举版 100 组，另测等和分裂专项。1006 条断言全过。

## 踩坑点 / 注意点

- ❌ **惯性写角色互换取负**。本题规则是确定性的，对手无选择，取负就错了——先想清楚"对手在这个规则下有没有自由"再定状态。
- ❌ **切点循环写成 `k <= j`**。右段必须非空。
- ❌ **区间和现场用循环算**。内层已经 O(n) 个切点了，再叠一个 O(n) 求和就是 O(n⁴)；前缀和是标配（1406 变体里也说过同样的话）。
- ❌ **平局分支随手写 `dp[i][k]`**。等和时选哪边是 Alice 的权利，必须 `max` 两边。
- ❌ **O(n²) 优化忘了前提**。分界点单调性依赖分值全正（`≥ 1`）；如果有负分值，`p`/`q` 可能回退，均摊分析失效。
