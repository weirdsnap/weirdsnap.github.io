# 博弈题决策清单：四步分流与石子游戏地图

这不是代码骨架。博弈题（石子游戏系列、预测赢家、求和游戏）**没有统一的代码模板**——状态形状、分数语义、甚至"是不是 DP"都因题而异。统一的是**决策路径**：拿到题按四步分流，每一步对应一小撮定式。这份清单就是那四步。

---

## 什么时候进这份清单

两名玩家轮流行动、都采取最优策略、问胜负或净胜分。出现"先手/轮流/最优策略"字样就进来。

## 第一步：先想数学秒杀

动手 DP 之前先问：**先手是否有与策略无关的必胜法？** 博弈题经常藏着数学结论：

- 877：堆数为偶数时先手恒胜（奇偶堆分组论证），一行 `return true`
- 1927：平衡条件 `diff == 待填数差 × 4.5` 直接判负，其余必胜

**找不到秒杀再往下走**，但每题都值得先花两分钟找。

## 第二步：零和 → 净胜分转化

两人总分固定（零和）时，定义 `dp = 我方得分 − 对方得分`，当前玩家取最大化 `dp` 即可——**双层 minimax 压成单层 max**：

```
dp(状态) = max over 行动a ( a的直接收益 - dp(对方先手的新状态) )
```

486、1140、1406、1690 全靠这个转化。不适用的情况：得分不是零和（1563 双方各自累计、目标只是最大化 Alice 一人得分），那就只管单方收益的 DP，别硬套。

## 第三步：取子位置定状态形状

操作的位置决定 DP 状态的维度：

| 操作形态 | 状态 | 代表题 |
|----------|------|--------|
| 两端取 | 区间 `dp[i][j]`，i 从大到小、j 从小到大 | 486、877、1690 |
| 只从一端取（可连取 k 个） | 后缀 `dp[i]`（或带参数 `dp[i][m]`） | 1406、1140 |
| 从全局任取（数量缩减） | 一维 `dp[n]`，胜负布尔 | 1510 |
| 任选位置分割 | 区间 + 分割点枚举，`dp[i][j] = max over k` | 1563 |

区间 DP 的循环顺序口诀：**按长度递增**或**i 降序 j 升序**，保证转移源先算好。

## 第四步：演化路径 DFS → 记忆化 → 递推

递归定义天然对应 minimax，先写 DFS 暴力（小规模能跑），加 memo 变记忆化搜索（1140 的 `dp[i][m]`、1406 的 `dp[i]` 都从这来），再改自底向上递推。三步各留一版代码互相印证，是博弈题最稳的开发路径。优化（滚动数组、后缀和 O(1) 求收益、单调分界点降维）都在递推版上做。

## 踩坑速查

- ❌ 跳过第一步直接 DP：877 写了区间 DP 才发现 `return true` 就行（[ch57](./blog.html?post=leetcode/dp/interval/ch57.md)）
- ❌ 净胜分写成"我方总分"：忘记 `- dp(对方先手)` 那一下，minimax 退化（[ch41](./blog.html?post=leetcode/dp/interval/ch41.md)）
- ❌ 区间 DP 循环顺序写反：i 必须**从大到小**、j 从小到大，否则转移源还没算（多篇的共同坑）
- ❌ 非零和题硬套净胜分：1563 双方得分独立累计，套了就算错（[ch61](./blog.html?post=leetcode/dp/interval/ch61.md)）
- ❌ 记忆化哨兵与合法值撞车：净胜分可以是负数，memo 的"未计算"标记要用 `INT_MIN/2` 这类值域外哨兵（[ch59](./blog.html?post=leetcode/dp/interval/ch59.md)）

## 延伸

- 决策清单 vs 代码骨架：滑窗（[template](./blog.html?post=leetcode/sliding-window/template.md)）、线段树（[template](./blog.html?post=leetcode/segment-tree/template.md)）有统一骨架可抄；博弈没有，因为状态形状跟着题面操作走。两类"模板"都要会用。
