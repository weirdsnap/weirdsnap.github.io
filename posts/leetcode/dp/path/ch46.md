# 网格中的最大路径得分（3742. Maximum Path Score in a Grid）

## 题意

`m × n` 网格，格子值为 0、1 或 2。从左上角走到右下角，每步只能向右或向下。每个格子同时贡献**得分**和**花费**：

| 格子值 | 得分 | 花费 |
|--------|------|------|
| 0 | 0 | 0 |
| 1 | 1 | 1 |
| 2 | 2 | 1 |

总花费不能超过 `k`，求最大得分；不存在合法路径返回 -1。

```
输入: grid = [[0,1],[2,0]], k = 1
输出: 2
解释: 走 下→右：(0,0)→(1,0)→(1,1)，得分 0+2+0 = 2，花费 0+1+0 = 1 ≤ k。

输入: grid = [[0,1],[1,2]], k = 1
输出: -1
解释: 两条路花费都是 2，超过 k。
```

约束：`1 <= m, n <= 200`，`0 <= k <= 10³`，题目保证 `grid[0][0] == 0`。

---

## 思路

在 [62/63/64 题](./blog.html?post=leetcode/dp/path/ch43.md) 的"只能向右向下"路径 DP 上加了一维限制：**花费是有限资源**。状态从 `dp[i][j]` 扩成 `dp[i][j][c]`——到达 `(i, j)` 且总花费恰好为 `c` 的最大得分：

```
dp[i][j][c] = max(dp[i-1][j][c-cost], dp[i][j-1][c-cost]) + score
```

其中 `cost = grid[i][j] == 0 ? 0 : 1`，`score = grid[i][j]`。`-1` 表示该状态不可达。最终答案是 `max(dp[m-1][n-1][c])`（`c ≤ k` 都合法）。

一个小优化：路径固定走 `m + n - 1` 个格子，最大花费不超过 `m + n - 2`（起点是 0），所以 `c` 的上限取 `min(k, m + n - 2)`，不用开满 `k`。

---

## 解法一：记忆化搜索（deducing this）

```cpp
class Solution {
public:
    int maxPathScore(vector<vector<int>>& grid, int k) {
        const int rows = grid.size();
        const int cols = grid[0].size();
        int maxCost = min(k, rows + cols - 2);
        vector<vector<vector<int>>> dp(rows,
            vector<vector<int>>(cols, vector<int>(maxCost + 1, -1)));

        dp[0][0][0] = 0;  // 起点 grid[0][0] == 0

        auto func = [&](this auto&& self, int i, int j, int c) -> int {
            if (c < 0 || c > maxCost) return -1;
            if (dp[i][j][c] != -1) return dp[i][j][c];

            int curCost = (grid[i][j] == 0 ? 0 : 1);
            int curScore = grid[i][j];

            int best = -1;
            if (i > 0) {
                int prev = self(i - 1, j, c - curCost);
                if (prev != -1) best = max(best, prev + curScore);
            }
            if (j > 0) {
                int prev = self(i, j - 1, c - curCost);
                if (prev != -1) best = max(best, prev + curScore);
            }
            dp[i][j][c] = best;
            return best;
        };

        int ans = -1;
        for (int c = 0; c <= maxCost; c++) {
            int score = func(rows - 1, cols - 1, c);
            if (score != -1) ans = max(ans, score);
        }
        return ans;
    }
};
```

**两个注意点**：

- 递归 lambda 用 `this auto&& self`——这里写成 `this auto self`（按值）也能过，但**每层递归都拷贝一次闭包**（闭包捕获了整张 dp 表的引用，拷贝本身便宜，但语义上是多余动作），惯例写 `auto&&`，见 [Lambda 递归](./blog.html?post=cpp/practices/lambda_01.md)。
- `-1` 同时承担"未计算"和"不可达"两个角色：算过的不可达状态会被重复计算。因为重算结果幂等，正确性不受影响，只是浪费；要严格记忆化可以用 `-2` 当"未计算"哨兵。

## 解法二：滚动数组递推

`dp[i][j][c]` 只依赖上一行同列和本行左侧，行维度可以滚动（和 [64 题](./blog.html?post=leetcode/dp/path/ch14.md) 同款技巧）：

```cpp
class Solution {
public:
    int maxPathScore(vector<vector<int>>& grid, int k) {
        const int rows = grid.size();
        const int cols = grid[0].size();
        int maxCost = min(k, rows + cols - 2);
        vector<vector<int>> prev(cols, vector<int>(maxCost + 1, -1));
        vector<vector<int>> cur(cols, vector<int>(maxCost + 1, -1));

        for (int i = 0; i < rows; i++) {
            for (int j = 0; j < cols; j++) {
                int cost = (grid[i][j] == 0 ? 0 : 1);
                int score = grid[i][j];

                fill(cur[j].begin(), cur[j].end(), -1);  // 重置当前格子

                if (i == 0 && j == 0) {
                    cur[j][0] = 0;  // 起点：得分 0 花费 0
                    continue;
                }

                for (int c = cost; c <= maxCost; c++) {
                    int best = -1;
                    if (i > 0 && prev[j][c - cost] != -1)      // 从上方
                        best = max(best, prev[j][c - cost] + score);
                    if (j > 0 && cur[j - 1][c - cost] != -1)   // 从左方
                        best = max(best, cur[j - 1][c - cost] + score);
                    cur[j][c] = best;
                }
            }
            if (i < rows - 1) swap(prev, cur);
        }

        // 最后一行算完没有 swap，答案永远在 cur 里
        int ans = -1;
        for (int c = 0; c <= maxCost; c++)
            ans = max(ans, cur[cols - 1][c]);
        return ans;
    }
};
```

---

## 关键细节

### 1. 滚动数组的答案在哪个缓冲里？——一个真实的坑

双缓冲滚动最常见的写法是"每行算完就 `swap(prev, cur)`"，然后答案读 `prev`。本题 `if (i < rows - 1)` 让**最后一行不 swap**，于是答案永远在 `cur` 里，与行数无关。

如果试图用奇偶性判断——`(rows - 1) % 2 == 0 ? cur : prev`——就掉坑了：它错以为缓冲区归属随 swap 次数交替，却忘了**最后一次没有 swap**。实测：偶数行时会读到上一行的数据，样例 1 直接给出错误答案，500 组随机对拍错 131 组。教训：滚动数组的答案位置由**最后一次 swap 是否发生**决定，与其记奇偶，不如让 swap 逻辑和读取逻辑在代码上紧挨着、一眼能对上。

### 2. `fill` 重置为什么不可少

`cur[j]` 被 swap 交换后装的是两行前的旧数据，每处理一个格子必须先把它的 `c` 维度清成 -1，否则旧值会被当成"本行左侧"或下轮的"上方"误用——和 [63 题障碍物清零](./blog.html?post=leetcode/dp/path/ch42.md) 是同构的坑。

### 3. 状态上界的裁剪

`maxCost = min(k, m + n - 2)`：路径只有 `m + n - 1` 个格子，起点是 0，所以花费天然不超过 `m + n - 2`。`k` 给得再大也不用开那么多状态。

## 复杂度

| | 解法一（记忆化） | 解法二（滚动） |
|--|------------------|----------------|
| 时间 | O(m·n·k) | O(m·n·k) |
| 空间 | O(m·n·k) + 递归栈 | **O(n·k)** |

`m, n ≤ 200, k ≤ 10³`：滚动版约 200×1000×4B ≈ 800KB，记忆化版约 160MB——这题数据范围下滚动数组的空间优势是决定性的。

---

## 踩坑点 / 注意点

- ❌ **滚动数组答案位置搞错**。本题 `if (i < rows - 1)` 意味着最后一行没有 swap，答案**永远**在 `cur` 里；写成 `(rows - 1) % 2 == 0 ? cur : prev` 的奇偶判断会在偶数行读错缓冲（实测 500 组错 131 组）。详见关键细节 1。
- ❌ **忘记 `-1` 不可达状态不能参与转移**。`prev[j][c-cost] != -1` 的守卫漏掉，会把"不可达"当成"得分 -1"的路径继续加。
- ❌ **`c` 从 0 开始枚举**。`c < cost` 时 `c - cost` 越界，要么从 `cost` 开始，要么显式判负。
- ❌ **起点没特殊处理**。起点没有"上方/左方"，直接初始化 `dp[0][0][0] = 0`（本题保证起点值为 0）。
