# 不同路径 II（63. Unique Paths II）

## 题意

`m × n` 网格，从左上角走到右下角，每步只能向右或向下。网格中 `1` 表示障碍物（不可通行），`0` 表示空地。返回到达右下角的不同路径总数。

```
输入: obstacleGrid = [[0,0,0],
                      [0,1,0],
                      [0,0,0]]
输出: 2
解释: 正中间有障碍物，只剩两条路：
     右→右→下→下  和  下→下→右→右 。

输入: obstacleGrid = [[0,1],[0,0]]
输出: 1
```

约束：`1 <= m, n <= 100`，答案保证不超过 `2×10⁹`（`int` 够用）。

---

## 思路

经典路径 DP：`dp[i][j] = dp[i-1][j] + dp[i][j-1]`（从上方来 + 从左方来）。和无障碍物的 62 题相比只多一条规则：**障碍物格子的路径数恒为 0**——相当于把它从转移图里挖掉，后续格子自然加不到它。

用一维滚动数组压缩空间时，这条规则变成一个关键动作：**遇到障碍物必须显式把 `dp[j]` 清零**。二维写法里新行默认是 0 不用管，但滚动数组的 `dp[j]` 还带着上一行的旧值，不清零就会把旧路径数错误地传递下去。

---

## 代码

```cpp
class Solution {
public:
    int uniquePathsWithObstacles(vector<vector<int>>& obstacleGrid) {
        const int n = obstacleGrid.size();
        const int m = obstacleGrid[0].size();
        // 改用一维滚动数组，空间从 O(n*m) 降至 O(m)
        vector<int> dp(m, 0);

        // 起点或终点有障碍物，直接返回 0
        if (obstacleGrid[0][0] == 1 || obstacleGrid[n - 1][m - 1] == 1)
            return 0;

        // 初始化第一行第一个位置
        dp[0] = 1;

        for (int i = 0; i < n; i++) {
            for (int j = 0; j < m; j++) {
                if (obstacleGrid[i][j] == 1) {
                    dp[j] = 0; // 障碍物位置路径数为 0，替代原来的 -1 标记
                } else if (j > 0) {
                    // dp[j] 保留上一行的值（即 dp[i-1][j]），dp[j-1] 是本行刚计算的值
                    dp[j] += dp[j - 1];
                }
                // j == 0 且无障碍物：dp[0] 继承上一行的值，无需改动
            }
        }

        return dp[m - 1];
    }
};
```

**注意**：滚动数组的正确性全靠"读到的值各就各位"——`dp[j]` 在更新前是上一行的值（相当于 `dp[i-1][j]`），`dp[j-1]` 是本行刚算出的值（相当于 `dp[i][j-1]`），所以原地 `+=` 就完成了 `dp[i][j] = dp[i-1][j] + dp[i][j-1]`。

---

## 关键细节

### 1. 为什么障碍物要清零而不是跳过

如果障碍物格子什么都不做，`dp[j]` 会保留上一行的路径数，下一行再读到它时就当成"从上方来的路径数"加进去——相当于让路径"穿过"了障碍物。清零后它上方来的贡献恒为 0，语义正确。

### 2. 第一列为什么不用特判赋值

`j == 0` 时只能从上方的 `dp[0]` 来，滚动数组里 `dp[0]` 不动就是继承上一行，天然正确。唯一的例外是 `dp[0]` 本身遇到障碍物时被清零，之后每一行的 `dp[0]` 都是 0——第一列被障碍物"截断"，语义也对。

### 3. 起点/终点的提前返回其实是可省略的

主循环本身已经能处理这两种情况：起点是障碍物时 `dp[0]` 在第一轮就被清零，终点是障碍物时最后 `dp[m-1]` 也是 0。开头的 `if` 只是少跑一轮循环的小优化，留着可读性也更好。

## 踩坑点 / 注意点

- ❌ **滚动数组遇到障碍物不清零**。旧值残留会让路径"穿墙"，是最经典的错法。
- ❌ **用 `-1` 之类标记障碍物再特判**。多此一举——路径数 0 本身就是最好的标记，加法里 0 不产生贡献。
- ❌ **初始化整行 `dp` 为 1**。那是无障碍物版本的做法；有障碍物时第一行的 1 必须靠主循环从 `dp[0] = 1` 逐步传播（遇障碍即断），一步到位初始化会绕过障碍物的截断效果。
