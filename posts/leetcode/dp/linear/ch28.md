# 好二进制字符串（2533. Good Binary Strings）

## 题意

给定三个整数 `minLength`、`maxLength`、`oneGroup`、`zeroGroup`。求有多少个**好二进制字符串**，其长度在 `[minLength, maxLength]` 范围内。

**好二进制字符串**的定义：
- 每个连续的 `1` 块长度恰好为 `oneGroup`
- 每个连续的 `0` 块长度恰好为 `zeroGroup`

```
输入: minLength = 2, maxLength = 3, oneGroup = 1, zeroGroup = 2
输出: 5

解释: 长度为 2: "00", "11"（2个）
      长度为 3: "001", "011", "110"（3个）
      共 5 个
```

---

## 思路

### 关键观察

字符串由若干个 `oneGroup` 长度的 `1` 块和 `zeroGroup` 长度的 `0` 块拼接而成。每个块是**固定长度**的，问题转化为：用两种"砖块"（长度 `oneGroup` 和 `zeroGroup`）拼出长度在 `[minLength, maxLength]` 之间的字符串，有多少种方案？

### DP 定义

`dp[i]` = 拼出长度恰好为 `i` 的好二进制字符串的方案数。

### 状态转移

对于长度 `i`，最后一块要么是 `oneGroup` 个 `1`，要么是 `zeroGroup` 个 `0`：

```
dp[i] = dp[i - oneGroup] + dp[i - zeroGroup]
```

- `dp[i - oneGroup]`：最后一块是 `1`，前面是长度为 `i - oneGroup` 的合法串
- `dp[i - zeroGroup]`：最后一块是 `0`，前面是长度为 `i - zeroGroup` 的合法串

### 边界条件

`dp[0] = 1`：空字符串是一种方案（作为递推基础）。

**注意**：不要直接给 `dp[oneGroup]` 或 `dp[zeroGroup]` 赋值，让它们通过 `dp[0]` 在循环中自然递推得到。

## 代码

```cpp
class Solution {
public:
    int goodBinaryStrings(int minLength, int maxLength, int oneGroup, int zeroGroup) {
        const int mod = 1e9 + 7;
        vector<int> dp(maxLength + 1, 0);
        dp[0] = 1;  // 空字符串是一种方案
        
        int result = 0;
        for (int i = 1; i <= maxLength; i++) {
            long long temp = 0;
            
            // 最后一块是 1
            if (i - oneGroup >= 0) {
                temp += dp[i - oneGroup];
                temp %= mod;
            }
            
            // 最后一块是 0
            if (i - zeroGroup >= 0) {
                temp += dp[i - zeroGroup];
                temp %= mod;
            }
            
            dp[i] = temp % mod;
            
            // 累加 [minLength, maxLength] 范围内的方案
            if (i >= minLength) {
                result = (result + dp[i]) % mod;
            }
        }
        
        return result;
    }
};
```

## 关键细节

### 1. 为什么 `dp[0] = 1`？

空字符串是**一种**合法方案（什么都不放）。它是递推的基础：

```
dp[oneGroup] = dp[0] = 1   // 全是 1
 dp[zeroGroup] = dp[0] = 1  // 全是 0
```

如果 `dp[0] = 0`，所有 `dp[i]` 都会是 0。

### 2. 取模时机

每次加法后立即取模，防止 `int` 溢出：

```cpp
long long temp = 0;  // 用 long long 保险
temp += dp[i - oneGroup];
temp %= mod;         // 立即取模
temp += dp[i - zeroGroup];
temp %= mod;         // 立即取模
```

### 3. 和 322 零钱兑换的区别

| | 322. 零钱兑换 | 2533. 好二进制字符串 |
|--|-------------|-------------------|
| 目标 | 凑成金额的最少硬币数 | 拼出字符串的方案数 |
| `dp` 含义 | `dp[i]` = 凑成 `i` 的最少硬币数 | `dp[i]` = 拼出 `i` 的方案数 |
| 转移 | `min(dp[i], dp[i - coin] + 1)` | `dp[i - one] + dp[i - zero]` |
| 初始化 | `dp[0] = 0`，其余 INF | `dp[0] = 1`，其余 0 |

本质都是**完全背包**，但一个求最值，一个求方案数。

## 踩坑点 / 注意点

- ❌ **直接给 `dp[oneGroup]` 和 `dp[zeroGroup]` 赋值**。应该通过 `dp[0] = 1` 让它们在循环中自然递推。
- ❌ **忘记 `dp[0] = 1`**。空字符串是一种方案，是递推基础。
- ❌ **取模不及时导致溢出**。`dp[i]` 可能很大，每次加法后都要取模。
- ❌ **结果范围搞错**。题目要求长度在 `[minLength, maxLength]` 之间，不是恰好等于某个值。
- ❌ **误以为本题必须用 `long long`**。每次取模后每个 dp 值 ≤ 1e9+6，`dp[i - oneGroup] + dp[i - zeroGroup]` 最多约 2×10⁹ < INT_MAX，本题用 `int` 其实也不会溢出——`long long` 只是无害的保险习惯；真正要防溢出的是不取模的累加场景。
