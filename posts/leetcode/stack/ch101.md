> **标签**：栈、单调栈、循环数组
# 下一个更大元素 II（503. Next Greater Element II）

## 题意

496 的循环数组版：数组首尾相接，最后一个元素的"下一个"从头继续找。对 `nums` 中每个元素，求它循环意义上的下一个更大元素，不存在为 `-1`。

```
输入: nums = [1,2,1]
输出: [2,-1,2]
解释: 第一个 1 的下一个更大是 2；2 是最大值，-1；第二个 1 循环绕一圈找到开头的 2

输入: nums = [1,2,3,4,3]
输出: [2,3,4,-1,4]
```

- `1 <= nums.length <= 10⁴`
- `-10⁹ <= nums[i] <= 10⁹`（注意：和 496 不同，元素**可以有重复**）

## 思路

循环数组的单调栈有两个套路：

1. **双倍展开**：扫 `2n` 步，下标取模 `i % n`，相当于把数组首尾拼一遍；
2. **从最大值出发转一整圈**（本解法）：全局最大值的答案必然是 `-1`，先找到它的位置 `maxIdx`，从它开始沿环形反向遍历一整圈（`n` 步），其余套路和 496 的反向扫完全一样。

为什么转一圈就够：最大值是所有元素的"终点屏障"。任何元素顺时针找下一个更大，最坏情况就是撞到最大值——它比谁都大，轮到它当答案候选时别人已经不需要再往前看了。所以从最大值出发绕一整圈，每个位置右边的有效信息都在栈里。

## 解法：从最大值出发 + 单调递减栈

```cpp
class Solution {
public:
    vector<int> nextGreaterElements(vector<int>& nums) {
        int n = nums.size();

        // 找到数组中的最大值下标（该元素的下一个更大元素必为 -1）
        int maxIdx = 0;
        int maxVal = nums[0];
        for (int i = 1; i < n; ++i) {
            if (nums[i] > maxVal) {
                maxIdx = i;
                maxVal = nums[i];
            }
        }

        // 从最大值左侧开始，向数组前部反向遍历，用单调递减栈求下一个更大元素
        vector<int> result(n);
        stack<int> decreaseStack; // 栈内元素从栈底到栈顶单调递减
        for (int i = 0; i < n; ++i) {
            int idx = (maxIdx - i + n) % n; // 从 maxIdx 起向左循环遍历

            while (!decreaseStack.empty() && decreaseStack.top() <= nums[idx]) {
                decreaseStack.pop(); // 弹出所有不大于当前值的元素
            }
            result[idx] = decreaseStack.empty() ? -1 : decreaseStack.top();
            decreaseStack.push(nums[idx]);
        }

        return result;
    }
};
```

## 核心理解

### 1. 和 496 反向扫的关系

主体就是 [496](./blog.html?post=leetcode/stack/ch100.md) 的反向单调栈：弹出比自己小的、栈顶即答案、入栈即定案。变的只是**遍历顺序**——`(maxIdx - i + n) % n` 把线性数组的"从右往左"换成了环形的"从 `maxIdx` 起逆时针绕一圈"。栈里存值（`result` 按下标写，`idx` 已知），也和 496 反向版一致。

### 2. 为什么最大值是合法的起点

两个原因。第一，全局最大值右边不可能有更大的，答案必为 `-1`，它入栈时栈恰好是空的，自洽。第二，它是屏障：对任何元素 `x`，顺时针方向第一个比 `x` 大的元素如果出现，一定出现在到达最大值之前或正好就是最大值本身——绕到最大值再往前，栈里的信息对任何人都没有增量了。所以一圈刚好，双倍展开的第二圈在这里是浪费。

### 3. 重复元素为什么不用特殊处理

496 里值唯一，本题允许重复，但弹出条件用的是 `<=`：等值元素一样被弹掉。想想 `[5,1,5]` 这种重复最大值的情况——`maxIdx` 取到第一个 5，遍历到第二个 5 时栈顶的 5 被 `<=` 弹掉，它同样得到 `-1`，正确。这就是 496 那篇说的"记模板就记 `<=`"的回报。

### 4. `(maxIdx - i + n) % n` 里的 `+ n`

当 `i > maxIdx` 时 `maxIdx - i` 是负数，而 C++ 的 `%` 对负数结果向零取整（`-1 % n` 得 `-1` 而不是 `n-1`），直接取下标就越界了。`+ n` 把被除数抬回非负再取模，是环形下标的标准写法。

## 复杂度

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| 时间 | O(n) | 找最大值一圈 + 环形遍历一圈，每个元素最多入栈出栈各一次 |
| 空间 | O(n) | 栈 + 结果数组 |

## 踩坑点

### ❌ 环形下标忘记 `+ n`

`idx = (maxIdx - i) % n` 在 `i > maxIdx` 时得到负下标，行为是越界读。凡是"起点减去步数再取模"的环形写法，都必须先 `+ n`。

### ⚠️ 双倍展开法不是不行，但别混用

`2n` 取模的写法也 AC，概念上更直白（不需要先找最大值），代价是多扫一圈、且要写"只在前 `n` 步记录答案"的限制。两种都行，但一个解法里只选一种遍历骨架，混着写最容易出下标错误。
