> **标签**：栈、单调栈、哈希表
# 下一个更大元素 I（496. Next Greater Element I）

## 题意

给定两个无重复元素的数组 `nums1` 和 `nums2`，`nums1` 是 `nums2` 的子集。对 `nums1` 里每个元素，找出它在 `nums2` 中右边第一个比它大的元素，不存在则为 `-1`。

```
输入: nums1 = [4,1,2], nums2 = [1,3,4,2]
输出: [-1,3,-1]
解释: 4 在 nums2 右边没有更大的；1 右边第一个更大的是 3；2 右边没有更大的

输入: nums1 = [2,4], nums2 = [1,2,3,4]
输出: [3,-1]
```

- `1 <= nums1.length <= nums2.length <= 1000`
- `nums1`、`nums2` 内元素各自不重复，`nums1` 是 `nums2` 的子集

## 思路

核心是一个单调栈，从右往左扫 `nums2`：

- 栈里存的是"当前元素右边、还有可能成为别人答案"的候选；
- 新进一个元素时，把栈顶所有比它小的弹掉——它们被挡住了，对左边任何位置来说，当前元素又大又近，被弹的永远不可能是答案；
- 弹完后栈顶（如果还有）就是当前元素的下一个更大元素，存进哈希表。

扫完 `nums2` 就有了全表答案，`nums1` 直接查表。预处理 + 查询分离，是这个子集题型的标准两步。

## 解法：单调栈 + 哈希表查表

```cpp
class Solution {
public:
    vector<int> nextGreaterElement(vector<int>& nums1, vector<int>& nums2) {
        // 预处理nums2
        // 下一个更大->递减，弹出小的，更新小的的下一个更大为当前新入栈的
        stack<int> increase;
        unordered_map<int, int> next_big;
        for (int i = nums2.size() - 1; i >= 0; --i) {
            while (!increase.empty() && increase.top() <= nums2[i]) {
                increase.pop();
            }
            if (increase.empty()) {
                next_big[nums2[i]] = -1;
            } else {
                next_big[nums2[i]] = increase.top();
            }
            increase.push(nums2[i]);
        }
        // 提取nums1的数和对应的答案
        vector<int> result(nums1.size());
        for (int i = 0; i < nums1.size(); ++i) {
            result[i] = next_big[nums1[i]];
        }
        return result;
    }
};
```

## 核心理解

### 1. 正向扫和反向扫，都能做，但语义完全不同

"下一个更大"其实两种方向都能写，区别在于**谁在什么时候拿到答案**。

**反向扫（本文解法，从右往左）**：扫到 `i` 时它右边已经全部处理完，栈里就是右边的候选。当前元素**主动**问栈要答案——弹掉比自己小的，栈顶即所求，入栈时答案已经定好。

**正向扫（从左往右）**：栈里存的是"还没找到答案的元素"，它们在看右边。每来一个新元素 `x`，它比谁大，谁的答案就结算成 `x`——答案是**被动**的，元素入栈时不知道自己答案，被后来的更大元素"顶出去"那一刻才结算：

```cpp
vector<int> nextGreaterElement(vector<int>& nums1, vector<int>& nums2) {
    // 正序遍历 nums2，维护一个单调递减栈（栈底→栈顶递减）
    // 遇到更大的元素时，弹出比它小的元素并记录其下一个更大元素
    stack<int> mono; // 存下标，便于用 nums2[下标] 反查值
    unordered_map<int, int> nextGreater; // 值 -> 其下一个更大元素（无则为 -1）

    for (int i = 0; i < nums2.size(); i++) {
        int cur = nums2[i];
        // 弹出所有比当前元素小的，此时当前元素就是它们的下一个更大元素
        while (!mono.empty() && nums2[mono.top()] < cur) {
            int top = mono.top();
            mono.pop();
            nextGreater[nums2[top]] = cur;
        }
        mono.push(i);
    }

    // 栈中剩余元素右边无更大值，统一置为 -1
    while (!mono.empty()) {
        int cur = mono.top();
        mono.pop();
        nextGreater[nums2[cur]] = -1;
    }

    // 用哈希表直接查询 nums1 每个元素的结果
    vector<int> result(nums1.size());
    for (int i = 0; i < nums1.size(); ++i) {
        result[i] = nextGreater[nums1[i]];
    }
    return result;
}
```

注意这版的两个工程细节：

- **栈存下标不存值**。这是更通用的写法——值如果有重复，拿值当 key 会互相覆盖；而且 739 每日温度那种"答案是距离不是值"的题，必须存下标才能算 `i - st.top()`。本题值唯一，两种都行。
- **末尾清栈统一记 `-1`**。留在栈里的就是右边没有更大值的，遍历结束后补一个循环把它们全部结算掉，哈希表就是满的，查询回到方括号直查。另一个收尾选择是不清栈、查询时用 `find` 兜底（没进过表的就是 `-1`），少一个循环但查询变慢——前者更好。

两种写法都是 O(n)，栈的单调性也一样（栈底到栈顶递减），真正的差别在这几点：

| | 反向扫 | 正向扫 |
|---|---|---|
| 栈里存的是 | 候选答案（右边元素） | 待解决的提问者（左边元素） |
| 答案结算时机 | 入栈时主动查 | 出栈时被动结算 |
| `-1` 的处理 | 栈空时显式记 `-1` | 遍历完清栈，统一记 `-1` |
| 栈里适合存 | 值（扫到谁结算谁） | 下标（方便反查值、算距离） |

怎么选：问"下一个/右边"，反向扫更直接，边扫边出答案；正向扫更适合"答案要按原数组位置写回"或"答案是下标距离"的题，739 每日温度常见的就是这种写法。

### 2. 栈里到底是什么

这个栈从栈底到栈顶是递减的（新元素入栈前会把比它小的都弹掉，所以它一定比下面的都小）。栈顶是右边最近的、比当前元素大的候选；栈里越往下越大、越远，但都可能在未来某个位置成为答案。

### 3. 为什么弹掉的元素是安全的

这是单调栈正确性的关键。假设 `nums2[i]` 弹掉了 `x`（`x <= nums2[i]` 且 `x` 在 `i` 右边）。对 `i` 左边的任何位置 `p`：`nums2[i]` 比 `x` 大，且比 `x` 离 `p` 更近，所以 `p` 的"下一个更大"轮不到 `x`。弹掉不影响任何答案，每个元素最多入栈一次、出栈一次，总复杂度 O(n)。

### 4. 哈希表这里为什么必然查得到

`nums1` 是 `nums2` 的子集，预处理时 `nums2` 每个元素都进过 `next_big`，所以 `next_big[nums1[i]]` 一定存在，方括号直接查不会插入脏数据。如果题目改成"不是子集"，就得换 `find` 并处理缺省值。

## 复杂度

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| 时间 | O(m + n) | 每个元素最多入栈、出栈各一次；查表 O(m) |
| 空间 | O(n) | 栈 + 哈希表 |

两个官方样例通过，反向、正向两种写法都和"逐个向右线性找"的暴力对拍了几百组随机数组，结果一致。

## 踩坑点

### ⚠️ 变量名和栈的实际单调性反了

代码里栈叫 `increase`，但从栈底到栈顶它实际是递减的（注释里写的"递减"才是对的）。逻辑没错，就是名字会误导读代码的人。单调栈起名建议带上方向和目标，比如 `dec_stack` 或 `next_greater_st`。

### ❌ 弹出条件写成 `<` 而不是 `<=`

本题元素互不相同，`<` 和 `<=` 结果一样。但搬到允许重复的题（比如 503 的变体数据）时，`<=` 才能保证弹掉等值元素、栈顶才是真正的"严格更大"。记模板就记 `<=` 这版。
