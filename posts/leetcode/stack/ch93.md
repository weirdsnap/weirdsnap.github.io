# 机器人组合并计数（4045. Count Robot Groups）

## 题意

数轴上有 `n` 个机器人，`position` 严格递增，`speed[i]` 是第 `i` 个机器人向右的恒定速度。任意时刻两个机器人（或组）的距离不超过 `distance` 就合并成一个组；同一时刻满足条件的合并**同时发生**（位置相邻差都不超过 `distance` 的一整段连通机器人合成一组）。合并后的组取**组内最右机器人**的当前位置和速度，且合并后不再分开。问所有合并结束后剩几个组。

```
输入: position = [1,5,6,20], speed = [4,3,2,3], distance = 1
输出: 2
解释: t=0 时 R2(5) 与 R3(6) 相邻合并（取 R3 的速度 2）；
      t=2 时 R1(速度4) 追上该组再合并；最终 {R1,R2,R3} 与 {R4} 共 2 组

输入: position = [1,5,9], speed = [3,2,2], distance = 2
输出: 2
```

约束：`1 <= n <= 10⁵`，`position[i], speed[i], distance <= 10⁹`，`position` 严格递增。

---

## 思路：两个阶段的合并分开处理

合并有两种成因，分开处理就清晰了：

**第一阶段：t = 0 就相邻的**。初始时间隙已经 ≤ `distance` 的机器人立即合并，按题目规则是一整段连通块合成一组，组速 = 段内最右机器人的速度。一趟扫描，把被吞掉的机器人标记掉即可。

**第二阶段：之后追上的**。剩下的组都在向右跑，左边的组速度**严格更大**时，迟早追上右边的组（间隙单调缩小到 0）。合并后又取最右者的速度，也就是追上别人的组把自己的身份交给被追上的组。这正是"车队"模型（853. Car Fleet）：从右往左看，只有"后面没有更快者"的组能幸存。用单调栈从左到右模拟：当前组速度能吃掉栈顶（栈顶更快）就弹栈，最后栈里剩几组就是答案。

为什么弹栈条件是 `st.back() > speed[i]` 而不是 `>=`：等速时两组的间隙恒定不变，而第一阶段已经排除了初始间隙 ≤ `distance` 的情况，所以等速永远追不上。

## 解法：一趟标记 + 单调栈

```cpp
class Solution {
public:
    int countGroups(vector<int>& position, vector<int>& speed, int distance) {
        // ========== 第一阶段：处理 t = 0 时相邻就满足距离条件的合并 ==========
        // 相邻位置相差 <= distance 的机器人会立即合并（题目规定同时发生）
        int merge = 0;                     // 记录被合并掉（消失）的机器人数量
        int last_pos = position[0];        // 上一个（最右侧）机器人的位置

        for (int i = 1; i < position.size(); i++) {
            if (position[i] - last_pos <= distance) {
                // 当前机器人紧挨着上一个，合并成一个组
                merge++;
                speed[i - 1] = 0;          // 被合并的左侧机器人速度置 0，标记为"已合并"
            }
            last_pos = position[i];        // 更新最右侧位置
        }

        // ========== 第二阶段：处理后续追上的合并 ==========
        // 用单调栈模拟：更快的机器人在后面追上前面较慢的组
        vector<int> st;                    // 栈中保存"不会被追上"的组的速度，单调不降

        for (int i = 0; i < speed.size(); i++) {
            if (speed[i] == 0) {           // 已被第一阶段合并的机器人，跳过
                continue;
            }
            // 栈顶组比当前机器人快，迟早追上并并入当前组（组速取最右者）
            while (!st.empty() && st.back() > speed[i]) {
                st.pop_back();
            }
            st.push_back(speed[i]);        // 新组入栈
        }

        return st.size();                  // 栈中剩余的组数即答案
    }
};
```

## 核心理解

### 1. "取最右者速度"是把问题化简成车队的关键

合并规则取最右机器人的速度，意味着：**左边的组追上右边的组之后，新组的行为和被追上的组完全一样**（同位置、同速度）。所以"追上"可以建模为栈顶组消失、当前组继续，不用维护合并时刻、合并位置这些细节。这是 853. Car Fleet 的同款化简，只是那题追上到同一位置（fleet），这题追近到 `distance` 以内，本质一样：速度差严格为正就迟早满足。

### 2. 栈里存的是"还活着的组"

不变量：栈中速度单调不降（每来一个速度，先把比它大的栈顶弹光再入栈）。栈顶永远是最右的幸存组；一个组被弹出，当且仅当它右边出现了一个严格更慢的组（它必然追上对方并消失）。最后没被淘汰的都留在栈里，直接 `st.size()` 出答案。

### 3. 第一阶段的标记技巧

被合并的机器人用 `speed[i-1] = 0` 标记（题目保证 `speed[i] >= 1`，0 是安全的哨兵），第二阶段扫到 0 直接跳过。这个技巧成立的前提是"组速 = 最右者速度"：一段连通块里只有最右机器人的速度会被留下，恰好对应没被置 0 的那个。另外注意 `last_pos` 每轮都更新（不是只在合并时更新），因为合并条件比的是**相邻机器人**的原始位置差。

### 4. 为什么不用真的模拟时间

连续时间 + 追及问题，第一反应是按"下次合并时刻"做事件模拟，那要维护优先队列、处理同时事件，复杂度 O(n log n) 还容易错。看出"严格更快必追上、等速永不追上"之后，时间维度可以直接扔掉，只剩相对速度的大小关系，一趟栈解决。

## 踩坑点 / 注意点

- ❌ **弹栈条件写成 `>=`**。等速的两组初始间隙 > `distance` 时间隙永远不变，不会合并；多弹会少算组数。
- ❌ **第一阶段 `last_pos` 只在合并时更新**。题目要的是"连通段"合并，比较基准是相邻机器人的位置差，断更会把不相邻的也连起来。
- ❌ **调试输出忘删**。这版代码里的 `cout << "pop"` / `cout << "push"` 是调式残留，虽然 LC 一般不影响判题，但 10⁵ 规模下输出本身就会拖慢甚至 TLE，提交前务必清掉。
- ⚠️ **speed 可能为 0 的假设依赖题面**。`speed[i] >= 1` 是题目约束，拿 0 当"已合并"哨兵才安全；约束变了这个标记法就失效。
